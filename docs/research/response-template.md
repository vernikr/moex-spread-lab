# Research response contract

Use this outline for each completed Rxx investigation. English, concise but sufficient to audit. Do not fill unknown fields with guesses. This file is a template, not research results.

## Header
- Research ID / title:
- Completed at (date and timezone); current-facts cutoff:
- Context/policy version used:
- Inputs actually read; inaccessible/missing inputs:
- Status: complete / conditional / blocked / not applicable.

## Decision summary
- What decision this supports; short answer; explicit go / conditional / no-go.
- Verified facts vs assumptions vs hypotheses vs unknowns.
- What changes in the project if the finding is true; what does not follow from it.

## Evidence table
| Claim ID | Precise claim | Instrument / broker / account / period scope | Source URL or supplied filename | Issuer, title, section/page | Publication / version / effective interval | Accessed at | Short supporting excerpt | Status and caveat |
|---|---|---|---|---|---|---|---|---|

Use stable claim IDs (e.g. R01-C01). Distinguish publication, observation, availability and effective dates. A webpage's crawl date is not a historical availability date. Every decision-changing current or historical factual claim must be traceable. Use primary sources for legal/operational claims; methods from books/papers need bibliographic locations. If edition/page is unknown, identify the topic and state that limitation.

## Task-specific deliverables
Include the matrices, formulas, worked examples, source inventories or experiment protocols required by the prompt. Monetary values need currency, unit, taxable basis where relevant, and period. Quoted percentages need their denominator. Compare base/stress cases and any requested scale scenarios. Never label a proposed experiment as completed.

## Conflicts and gaps
| Issue | Conflicting evidence / missing item | Safe interpretation pending resolution | Who can resolve it | Exact question / next read-only check |
|---|---|---|---|---|

Account-specific unknowns must be resolved with redacted documents or written broker confirmation, not assumptions from a marketing page. Include a short ready-to-send broker question list where needed.

## Falsification and acceptance
- What would invalidate the proposed conclusion?
- What can be established from the available data, and what cannot?
- Feasible next validation; data, approximate resource/cost needs; no fabricated results.
- Material uncertainty and residual risk, not an unsupported confidence percentage.

## Handoff
- Links to reusable sources; license/retention/redistribution restrictions where relevant.
- Dependencies still missing from other Rxx reports.
- Proposed updates to A-xx questions/policy; blocking facts vs optional enhancements.
- Refresh triggers (changed tariff, expired promotion, API release, broker status, etc.).
