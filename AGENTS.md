# Working rules
- Chat: Russian, outcome first, brief business language. Authored project files: English by default. User-requested exception: R01–R06/R12 research prompts and the user-facing sections of the research README are Russian; reports may follow their prompt language. Preserve user-supplied source documents in their original language; explicitly label redactions.
- `docs/inputs/brief.md` defines scope and stage gates. Each stage occupies at least one separate user/assistant turn and produces a committed artifact. Never combine later stages into the current one.
- Current stage: Stage 9 development. See `README.md` for status, `docs/decisions.md` for confirmed boundaries, and `docs/stages/08-planning.md` for S4 and later work.
- Workspace map and ownership (Phase 6): `packages/core` owns contracts/settings/hashing; `packages/data` owns ISS/lake/retention/benchmark; `packages/accounting` owns costs/risk/sizing/ledger/artifacts; `packages/strategies` owns isolated strategy plugins and pair/calendar datasets; `packages/proof` owns replay/search/audit; `packages/web` owns the loopback server/routes/static UI. Import dependencies flow `core -> data|accounting -> strategies -> proof -> web`; `data` and `accounting` remain siblings. Root `src/moex_spread_lab/cli.py` and `__init__.py` are public entry points; other root modules are documented backward-compatibility shims whose module docstrings name the canonical replacement.
- Default agent scope is one `packages/<name>/` subtree, including its tests/docs/fixtures/manifest. Use canonical `moex_spread_lab.<domain>` imports in all workspace package code and tests; root compatibility shims are reserved for external consumers. Cross-package contract changes start with an additive contract and conformance test, then fan out to consumers. Keep root governance files (`pyproject.toml`, `uv.lock`, workflows, `README.md`, `AGENTS.md`) minimal and coordinate cross-cutting edits.
- Package tests are collected only from `packages/{core,data,accounting,strategies,proof,web}/tests`; root `tests/` contains shared synthetic fixtures only. Run a focused suite with `uv run pytest packages/<name>/tests -q`, the dependency-light global check with `uv run python scripts/architecture_gate.py`, and the full suite with `uv run pytest -q -n auto --dist loadfile`. CI schedules dynamic xdist `loadfile` work per package; do not add a central test-duration JSON.
- Code-health gate: before committing code changes, run `./scripts/check_health.sh`; never raise ceilings in `config/code-health-baseline.json` or `.basedpyright/baseline.json`, never add `# noqa` / `# type: ignore` / broad `except Exception` without an inline justification, and always run `packages/proof/tests/test_perf_equivalence.py` (plus `scripts/run_sanitized_pytest.py` when clang/ASan is available) when touching `_fastcore.c` or its pure-Python mirrors.
- Session velocity & context budget (`docs/development/agent-performance-plan.md`): scope each turn to one cohesive slice (`<= 1` package or `<= 5` files per commit/push; target `<= 60` tool calls) rather than multi-phase rewrites that hit per-turn tool limits. Follow the 4-stage verification pyramid (1: `<2s` single-file `ruff`/`basedpyright`/JS check during inner edits -> 2: focused test module -> 3: `./scripts/check_health.sh` + package `pytest` once per completed slice -> 4: full `pytest` / affected browser smokes once pre-push). Always set `MOEX_OFFLINE_ONLY=1` in standalone/browser harnesses so `CalendarData` never probes MOEX ISS over HTTP; never wait with `nohup <cmd> & sleep <N>` loops (use synchronous `timeout <sec> <cmd>` or native background tools); prefer structured Read/Edit/Grep tools over `Bash` `sed`/`cat <<EOF` dumps; and never commit temporary GitHub Actions workflows to exfiltrate org/repo secrets. If bridge credentials are absent, finish the push and ask the user for them; treat any credential-bearing Actions artifact as burned, delete it and rotate the affected token.
- Stage 2 produces research prompts; the user performs the research. Treat supplied reports as intake material and validate them before accepting findings or changing later-stage artifacts.
- Read `docs/decisions.md`, `docs/risk/pilot-policy.md` and the current stage artifact before continuing. The user clarified 10–15k means LQDT shortfall and delegated risk-default selection; numeric defaults are versioned judgment, not verified safety or authorization to fund/trade. Track unresolved groups in `docs/blockers/bNN-slug.md`; use bNN.N subitems and archive resolved groups.
- Keep documentation compact, agent-readable and nonduplicative. Update affected docs after functional changes. Clearly separate provided facts, dated evidence, hypotheses, proposals and approved decisions.
- Keep the repository private. Commit coherent successful changes with Conventional Commits and push to origin. Verify remote success; never claim a push that failed. Apply SemVer when software releases begin.
- Preserve the proof search and accounting contracts in `docs/development/execution-proof.md`; never infer shared capital or expanded trading authority from the offline UI.
- Workstation handoff (user request, 2026-11-18): after each completed change, push to `main`, then fast-forward the checkout at `~/Downloads/projects/moex-spread-lab` and verify its HEAD against the remote. Preserve untracked/local work; never reset it to force a sync. Sync locked dependencies when they change.
- Never commit tokens, credentials, account identifiers, production host addresses, trading statements, market datasets or generated dependency/cache folders. Obtain credentials from secure runtime configuration. Never echo credential values.
- Treat uploaded `AGENTS.source.md` as sanitized workstation guidance, not proof that tools or bridges exist here. Detect availability; unavailable local macOS tools are not a cloud blocker. Use available native tools when appropriate. When a workstation bridge is provided at runtime, prefer loopback HTTP APIs and CLI execution over browser automation except for UI smoke tests; never spawn orphan servers on random ports or mutate `data/analytics/research-settings.json` during benchmarks (see `docs/development/remote-agent-testing.md`).
- GitHub connector was unsupported in this environment; direct authenticated API/git access worked. Use supported connectors where available; otherwise secure runtime credentials, never credential-bearing remote URLs.
- Stages 1–2 use no broker connection, trading, Telegram messaging, VPS access or deployment. Later connectivity belongs to stage 3 and trading remains separately gated.
- Follow `docs/inputs/server-spec.redacted.md` before any server work. Protect the VPN, management/SSH ports, network settings and existing applications. The resource ceiling is shared capacity, not a fresh allowance for each process.
- Broker terms, KPUR effects, collateral eligibility, margin offsets, market sessions and API/data access are unverified until evidenced by dated applicable documents. Missing safety-critical data must never become zero cost or unlimited capacity.
- All performance comparisons must address LQDT; do not assume a return guarantee, risk-free arbitrage, fixed carrying yield or that an internal allocation ring-fences the account.
- Research localization must preserve complete context, evidence requirements, dependencies and risk authority. Every prompt states search languages, maximum-breadth priority and conditional public-page retrieval priority; no claim of tested bot protection. Broader discovery does not mean harder retrieval.
- Research reports use each external agent’s own format: no common template, fixed section layout or file-type requirement. Keep evidence/substantive requirements. The research README owns search priorities and input/dependency guidance; do not recreate redundant guide/template files.
- Every externally executed prompt must define referenced Rxx tasks and explicit attachment/unknown-data needs; predecessor plans are not measured baseline results. Embed task-relevant policy details rather than depending on unseen repo files.
- Research prompts must be usable outside this private repository: embed necessary context, specify any attachments, require effective-dated sources, distinguish proposed tests from executed evidence, and state dependencies. Repeated context in standalone copy/paste prompts is intentional. R10–R15 are standalone: they must not take other research reports as inputs; keep all working assumptions embedded in the prompt text.
- Keep benchmark-relative peaks, losses and lifetime gross top-up usage continuous across funding/reviews; no hidden resets, automatic rescue capital or unapproved access to core collateral.
- Review each turn for reusable lessons; update this file only when useful. Never copy secrets from source instructions.

- For native GitHub sub-issues, ensure `.github/workflows/issue-parent-sync.yml` exists with `issues: [opened, edited]`, `permissions: issues: write`, and a job calling `vernikr/mother/.github/workflows/issue-parent-sync.yml@v1` (create the caller workflow if missing); then put `<!-- issue-parent: #N -->` on its own line in the child Issue body, or use `<!-- issue-parent: none -->` to detach.
