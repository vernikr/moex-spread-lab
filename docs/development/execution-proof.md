# Unified execution proof (`/`, `/proof`)

Status: **slices 1–3 delivered** (payload + adapters + tests 2026-11-16; LWC UI rewrite 2026-11-16; screener deep links + docs 2026-11-16). Design: `execution-proof-screen-design.md` (workspace artifact, not committed).

## Homepage, automatic parameters and stability lamps (2026-11-18)

`/` and `/proof` serve the same screen and accept the same deep links. The old S2 homepage and its back-link have been removed. Its compatibility API (`/api/optimize`) still implements the original hand-coded neighborhood grid; it is **not** used by the proof UI.

### Scope and compatibility

Click a name to inspect its chart; check its box to include it in **Подобрать параметры**. Checks survive switching assets. Asset/family boxes cascade and show a mixed state for a partial subtree. Upper **Все** controls the entire catalog; lower **Все** controls just the open asset. No checks means exactly the open window. An unchecked focus is never silently added. The first check initializes a shared parameter editor from the current controls. Its vector and strategy stay pinned when browsing another row or universe. Compatible checked charts can preview the common settings; an unchecked focus keeps its own settings and never enters the mean. Clearing all checks restores the ordinary per-leaf editor.

One active strategy and one common vector, never a separate optimum per instrument. Pair `mean_reversion.lookback` maps to calendar `zscore_mean_reversion.window`; thresholds share their intersecting stepped domains. Pair and calendar MR share next-open (default), next-close and explicitly diagnostic same-bar close fills. Carry and RUONIA do not cross universes; RUONIA is restricted to its configured assets. Size is automatic for each entry; slippage is a global preference. Neither is a search/probe axis; fill, calendar conventions and chart transforms are not tuned.

`POST /api/proof/optimize` accepts the normal focused request plus optional `targets` (unique `{universe, pair}` / `{universe, asset, pair}`). An omitted or empty array uses the focus. **Before** removing any explicit check, `selection_requires_confirmation` returns all exclusions, reasons and remaining count, with zero trials. Cancel/Escape leaves the selection unchanged. Acceptance resubmits only the confirmed remainder. If none remain, stop; only a subsequent click will use the empty-selection fallback. A trial-level failure does **not** authorize removing that window.

**Research screens (settings dialog).** `allow_failed_volume` and `allow_failed_capital` default to `true`, independently. Checked = allow the respective failed check; unchecked = enforce it. A window failing both needs both permissions. The switches govern proof search (checked or focused), its live stability probes and the matching proof/evaluation. They do not check additional windows, change the raw V/C verdicts, alter ordinary S2/CLI gates, or enable trading. Whole-window failures remain in proof/evaluation metadata and the period table’s V/C/rate tooltips; the right-column result strip and group rows no longer print the volume/capital or risk/cash explanations. A relaxed capital stress test is not extra funding: a position that cannot pay actual margin cannot contribute a trading return.

### Selection, accounting and evidence

- [BR-10](../stages/04-requirements.md): **Настройки → Доля истории для проверки** is one persistent 0–50% preference, default 0 (`GET/POST /api/settings`; ignored `data/analytics/research-settings.json`). Old split-only settings files retain their exact share and use both default permissions, one tick of slippage and RUB 30,000 starting capital, without being rewritten on read. Partial saves preserve omitted fields; booleans are not coerced from numbers or strings. Pre-preference search logs used both strict screens, irrespective of today’s defaults. Snapshot all preferences once per request; split **each window's own eligible sessions**, not their intersection. At 0%, report on full training. Otherwise reserve the last `max(1, floor(n × percent / 100))` sessions. Journal-only rows do not consume the share. No confirmation interval and no training substitution for unavailable validation.
- For each window start with an independent account using the global `initial_capital_rub` (default RUB 30,000). Reinvest free cash in LQDT; posted margin earns nothing until released (the existing end-of-row margin convention). Incorporate the proof ledger's net daily P&L (costs and applicable funding). The matched benchmark is fully invested in LQDT. For `d` actual elapsed calendar days, score `100 × [(V_end/V_start)^(365/d) − (LQDT_end/LQDT_start)^(365/d)]` in percentage points per year. Counts weight neither by session count nor invested margin. Positive sub-year spans, even a single validation session measured from the previous mark, are annualized **projections**, not realized yearly returns. Nonpositive spans, balances, invalid prices or unfundable margin cannot supply a valid score.
- The objective is the **arithmetic mean** of these annualized excesses on the fixed cohort. A legitimately idle LQDT-only book contributes zero with its full weight. Missing/unmeasurable/risk-blocked training is not zero: prune the entire proposal. Require defensible funding coverage under the policy below and all other required inputs, any non-waived training liquidity or stress gate, warm-up with room for a signal, and the existing 10k excess-drawdown / 15k shortfall limits. Each training replay ends at its own cutoff, including carry's fee reference and the usual terminal marking convention.
- Optuna **TPESampler** (seed 41, 8 startup trials, 40 proposals). Integer windows, 0.1 threshold steps, `exit_z < entry_z`. Include the current vector when on the common feasible grid. Apply the maximum admissible **tested proposal**, including nonpositive maxima; prefer the current vector on an exact tie, otherwise the first tied proposal. No admissible score → leave settings unchanged. This is not a claim of an exhaustive global optimum.
- **Only after selection**, measure the chosen rule on each continuous full ledger. Validation begins economically at the last training mark; do not reset cash, positions, costs, funding or warm-up. The expandable group result shows members, their rates, the equal-weight training mean and the separately labelled result-period mean. A missing validation rate leaves the mean unavailable, never divided by fewer members. The focused period strip also retains net RUB and the booked LQDT hurdle on entry margin; those RUB measures are not the search objective.
- **Lamps are diagnostics, not vetoes.** Probe ±1/±2 feasible input steps, everything else fixed, training only. `100 × clamp(worst neighbor / center, 0, 1)`: green ≥70, amber ≥40. A nonpositive measured center scores zero; absent exposure, insufficient history (<24 training sessions) or unavailable evidence can leave a lamp unscored. The workbench has no size/slippage sensitivity fields; legacy fixed-size API callers retain them. With checks, both the form lamps and the search summary profile the common vector: first average all members’ annualized excesses at the center and each neighboring point, then score the worst neighboring **mean** against the center **mean**. Do not average individual lamp scores or colors. With no checks, the form profiles the open window. An incomplete cohort shows no group estimate and keeps every check. Neighbor probes are not Optuna proposals or a second ranking step.
- `POST /api/proof/plateau` probes the explicit strategy/vector on `targets` without starting Optuna, applying parameters, writing a trial log or using a focus instrument. Refresh on changes to checks, parameters, execution assumptions, either screening preference or the BR-10 split. Navigation replays only the inspected chart; it cannot clear, replace or restart group lamps. Request keys, cancellation and separate response guards prevent stale results. A completed search can supply the same profile directly.
- `proof-search.v3` records every proposal, rank score, member scores in canonical member order (or reason for pruning), selection, dated evaluation metadata (including screen preferences, global slippage/capital and full-window failed checks) and member run IDs in ignored `data/analytics/proof-searches.jsonl`. Single-window searches retain the focused result ID. The UI requests a fresh `/api/proof/run` after an actual search, with accepted or unchanged settings. The proof/evaluation IDs distinguish full replay from period evaluation. The full chart, journal and CSV mark the validation boundary without changing the ledger.
- Calendar data and member input snapshots are reused per request. Optimize/checked-plateau requests permit 192 KiB and ≤1024 targets; the read-only window table permits 192 KiB and ≤128 distinct single-window requests. Serialize group profiles separately from searches, with cancellation checks. No shared capital, broker connection or prospective performance claim. Historical W7 and the separate S2 compatibility grid are not changed.

Optional Chromium regressions (synthetic data): install Chromium with `uv run --with playwright python -m playwright install chromium`, then run `uv run --with playwright python tests/browser/checkbox_tuning_smoke.py`, `uv run --with playwright python tests/browser/period_settings_smoke.py`, `uv run --with playwright python tests/browser/group_lamps_smoke.py` and `uv run --with playwright python tests/browser/screen_settings_smoke.py`.

## Window table, signal lines and reference fills (2026-11-18)

- The lower selector displays ticker-free **Период / V / C / Сд. / п.п./г** rows. V/C preserve the original one-spread volume/capital verdicts, with keyboard-focusable icons and detailed tooltips; a blue download arrow identifies missing local data, not a failed screen. Screen permissions do not recolor these verdicts. The former instruction block below the tuning button is removed.
- **Сд.** counts accepted entries across the entire current simulation, including positions still open at the end, not skipped intents or only validation trades. **п.п./г** is the exact proof evaluation's annualized excess over LQDT: validation when enabled, otherwise training. A genuine zero remains zero; pending, missing or unmeasurable results are dashes with reasons. This is an independent account per row, never the cohort mean or a previous search winner substituted for the current parameters.
- `POST /api/proof/windows` reuses `StudyWindow.report(seed)` without optimization, parameter mutation, logs or preference writes. It snapshots settings/benchmark once; returns each row's counts, evaluation, selection and run ID, not its full ledger. Invalid data/parameters fail that row rather than hide it. Identity/list/duplicate errors reject the request. A separate cancellable lock keeps table work independent of tuning/profiles. The browser keys readings by target, strategy, parameters, fill, sizing and every setting; chart results seed the same cache. Abort/version/branch/settings guards prevent stale repaint. Checked compatible rows use the common editor; unchecked/incompatible rows keep their own saved/default settings.
- The raw spread pane starts **expanded**, independent of the normalization selector. Thin buy/sell curves are the actual strategy's **entry thresholds at the signal bar's close**, not visual-normalization bands, exit rules or later fill prices. `buy_level` / `sell_level` use raw price units; `_rel` fields divide by that signal date's far-leg value ×100 for this chart. Warm-up, zero-volume and zero-deviation rows have no price bands; positions, expiry, account/volume gates and entry delay can still prevent a trade. Funding carry has no fabricated price bands.
- Pair MR uses the engine's previous-window population deviation. Native MR uses sample deviation in RUB, excluding the current bar for delayed fills but including it in the existing same-bar reference mode; convert thresholds by that date's RUB point value, including FX. RUONIA boundaries invert `dev_pp` at ±`threshold_pp`, using `near_price × 91 / 365 / 100` raw price points per rate percentage point. Tooltip/legend and CSV expose thresholds; transforms never feed them or the strategy.
- `next_open` = one eligible-bar delay/open, `next_close` = one eligible-bar delay/close, `reference_same_bar` = zero-delay/close. The ordinary-pair adapter and common cohort now forward all three, including CNYRUBF and GLDRUBF. The prior exclusion was an adapter/UI inconsistency with native calendars, **not an economic ban on reference analysis**. Zero-delay analytics remain restricted to `diagnostic_only` close fills; primary/legacy defaults remain delayed. Funding carry accepts only its own `same_day_settlement` convention. Signal dates identify the triggering bar, not the later fill bar.
- Same-bar signals already use the closing price: it cannot then be treated as an achievable post-signal fill. `execution_reference` marks proof/selection/evaluation, group summaries and live profile metadata. The result strip, row rate tooltips, group summary, lamp tooltips, price-role notes and CSV warn that these are **reference results, not executable-return evidence**, even when the open chart is an unchecked next-open window. Existing funded sizing, costs, risk, funding and holdout rules still apply.
- Regressions: `tests/test_proof_windows.py` covers engine bands/timing/causality/units, close-fill cross-universe search, exact compact/chart identity, missing versus zero, snapshots, cancellation and HTTP guards. `tests/browser/window_table_smoke.py` exercises actual table values, raw lines/default expansion, normalization independence, CNY/cohort reference behavior, unchecked focus, stale responses, validation and 400px overflow. Run alongside the six existing browser smokes; fixtures are synthetic, not fill/profitability evidence.

## Automatic per-entry size and global slippage (2026-11-18)

- The workbench sends `sizing=max_affordable`, never manual contracts. `position_sizing.py` replays unit **signal intents** through one funded account per window, not a multiplied/unfunded portfolio. Before each entry choose the largest whole number of spreads within `max(0, min(initial_capital_rub, last observable account wealth + an earlier same-row exit P&L − exit costs))`. Fix that quantity until exit; losses can shrink the next trade. Profits cannot expand the original authority; no top-ups, core collateral or former 50-contract input ceiling. An unaffordable intent is an explained skip with zero exposure/cost/funding; retry only at the next declared strategy entry.
- Affordability covers actual margin and rounded entry costs **plus one exit side reserved at entry prices**, never eventual exit prices, future P&L or the full-window maximum margin. Pair margin uses the validated two-leg snapshot; native-calendar margin uses the fill leg prices and the documented reference margin rate. Next-open FX-dependent terms and exit conversion use the previous daily point value (reference fallback on the first row). Missing/nonpositive/nonfinite required terms are errors, not unlimited financing.
- Requiring the capital stress screen preserves the engine conventions: pair `3×M×q + 5000×q + 5000`, native calendar `(3×M + 5000 + 5000)×q`, plus both cost sides. Allowing a failed stress screen removes those stress reserves, **not ordinary affordability**. Raw V/C flags still describe the original one-spread window screen, not a claim that the maximum size is safe or executable at the observed volume.
- Actual trade fees/funding, daily posted margin, free LQDT cash and wealth drive both replay and scoring. Journal-only zero-volume rows cannot revalue a position or its margin. Funding belongs only to accepted held exposure; an ordinary pre-clearing exit gets none. Existing terminal proxy-mark/cost conventions remain labelled, including no fictitious exit fee for an open funding-carry position. Pause new entries on an observed 10k excess drawdown/shortfall or negative free cash, including before same-row re-entry; historical funding shortfalls invalidate scoring, never inject money. There is no guaranteed loss bound, order-book-capacity model or broker liquidation simulation.
- **Настройки → Проскальзывание** is the only slippage control: numeric 0–10 ticks, default 1, persisted as `slippage_ticks` beside the split/screens. It applies to every strategy/window, once per side for a native spread and per leg/side for an ordinary pair. Partial saves preserve it, old files migrate without a read-time rewrite, invalid saves are rejected. Changes invalidate proofs, searches and lamps and notify other tabs; all members/probes in one request share the immutable snapshot. Automatic sizing and global slippage are neither optimized nor sensitivity-varied.
- `selection.quantity=null` and `selection.sizing=max_affordable` identify the new policy; native editable strategy parameters are separate from fixed `strategy_conventions`. Per-trade quantity, ledger held quantity, skips, funded-account values and sizing policy are explicit; journal badges/cards, chart tooltips, summary ranges and CSV (`contracts_held`, `entry_contracts`, `exit_contracts`) show actual sizes. IDs include sizing/account/settings evidence. Calls omitting `sizing` retain the fixed-size quantity policy; interactive research uses the saved capital for their engines/evaluations too. Direct non-research API/CLI defaults and archived study assumptions remain unchanged.
- Regression coverage: `tests/test_position_sizing.py` and `tests/browser/automatic_size_smoke.py`, plus the existing split/cohort/funding/screens browser smokes. These use synthetic offline fixtures; workstation real-data checks are distinct dated evidence, not an order/fill validation.

## Global capital and quieter results (2026-11-18)

- **Настройки → Капитал · ₽** is one project-wide research assumption, `initial_capital_rub`, default **30,000**, stored with the existing split/screens/slippage. The UI/API accept numeric RUB **0.01–1,000,000,000**, at most two decimals; the upper bound is an implementation guard, not a risk/funding approval. Reject strings, booleans, null and nonfinite/out-of-range/sub-cent values without replacing the file. Old files receive the default without rewriting; partial saves preserve all other preferences.

Direct legacy study/CLI defaults remain RUB 30,000; no archived result is restated. The same setting per independent window is **not** a shared basket allocation.

- This changes a **research hypothesis**, not the pilot’s approved funding, emergency-money rules, fixed RUB 5k buffers / 10k risk trigger / 15k shortfall boundary, or broker authority. Profits never expand the configured original entry envelope; no automatic top-up or percentage-based relaxation of loss limits.
- Regressions: `tests/test_global_capital.py` (migration, validation, budgets/quantity in all four strategies, exact nonzero training/continuous-validation annualization, no-trade zero, unchanged risk limits, screens, compact identities and immutable search/table snapshots); `tests/browser/global_capital_smoke.py` (cancel/validation, two tabs, cohort execution, stale-budget responses, CSV, reference warning, mobile/reload). ## Signed funding in mean reversion (2026-11-17)

- For `perpetual_quarterly_same_asset`, `mean_reversion` joins local MOEX ISS FORTS EOD history on trade date and requires a published, verified or explicitly estimated rate for each analysis clearing. The cash effect per clearing is `−position × SWAPRATE × near_lot × quantity` (`position=+1` long near, `−1` short near); it feeds per-day ledger P&L, cumulative equity/LQDT comparison, trade gross/net and summary reconciliation. On next-open proxies, funding is counted only when the modeled position remains open through that day's proxy clearing; an exit at that day's open does not receive/pay that day's funding.
- The pair screener requires a local near-perpetual funding-history cache for mean-reversion availability. An unresolved funding gap prevents the proof; missing values are never silently treated as zero. Non-perpetual dated calendars do not receive funding.
- MOEX's EOD `SWAPRATE` is used as the exchange-published clearing result; it already reflects its operative funding calculation/caps. The application does not attempt to reconstruct minute-average deviation `D` or point-in-time `K1/K2` regimes from EOD candles. The lot currently comes from the contracts intake snapshot, not a point-in-time specification. These are exchange-data proxies, not broker statements or account reconciliation. Current MOEX description for `GLDRUBF` states `K1=0.05%`, `K2=0.15%` and its minute observation interval; see [MOEX perpetual gold one-pager](https://fs.moex.com/f/19628/onepager-vechnye-fjuchersy-na-zoloto.pdf) and [perpetual-futures hub](https://www.moex.com/ru/derivatives/perpetual-futures).
- The table labels each row `начислено` / `списано` / `нет платежа` and shows `−position × SWAPRATE × lot × contracts`; exported CSV carries the rate, lot, quantity and source. The funding chart's signed values and net total now apply to both pair strategies whenever coverage is complete.

### Exchange check and short gaps (2026-11-18)

- One offline resolver serves the pair catalogue, `mean_reversion`, `funding_only`, their training replays and the S2 pair screener. Existing recorded W7 studies and native calendars are not restated. A finite published rate, **including zero**, wins. A supplemental MOEX re-download can supply a missing number. A documented extra session without clearing has **no payment and no rate**: keep genuine candles in price replay, never add a weekend settlement to carry, and never move or duplicate the next regular rate. If such a candle has no same-day LQDT quote, use only its last observed close and identify its date; futures prices are never filled by this policy.
- For **1–3 consecutive missing clearing sessions** only, book the **same** signed `(previous + next) / 2` per underlying unit on every missing date. Resolve the run on the perpetual's complete local EOD/candle history **before** selecting a quarterly or its positive-volume dates; other observed FORTS settlements can confirm a clearing and reveal absent EOD rows. Do not bridge 4+ sessions, an unbounded edge, an unverified clearing, the 2022 FX regime change, the sample end, or the training/validation boundary. No midpoint can restore either leg's missing `SETTLEPRICE`. Input pages remain unchanged.
- Cash is attributed retrospectively to its session under the existing position/sign/lot rules. A carry decision uses a complete prior window: a midpoint is available **after** its right-hand clearing, never for the same settlement decision. While it is unknown there is no funding-triggered entry or exit; independent expiry/assignment exits still work. A prefix or training account that would need a later rate is unavailable, not computed with validation data.
- Ledger/CSV distinguish a published zero, a flat position, `rechecked`, `midpoint` (both source dates/rates) and `no_clearing` (notice). Policy/exception dates and recheck page hashes appear in provenance. The checked group and both V/C permissions are not altered if a rate cannot be resolved.
- See [historical intake](historical-pair-intake.md#funding-reconciliation-2026-11-18) for live-source evidence, coverage counts and the explicit read-only-by-default recheck command.

## Spread display & causal normalization (2026-11-16)

## Reconciliation contract (asserted in tests)

- `Σ ledger.costs == Σ trade entry+exit costs` (±0.02 ₽ rounding).
- `Σ ledger.mark_pnl == Σ trade gross` (telescoping; prices for the pair book are RUB-normalized `near*mv − far*mv`, constant multipliers — no FX drift on this universe).
- `last(ledger.cumulative_net) == Σ trade net` (±0.02 ₽); `ledger_reconciliation_rub == 0.0`.
- `cost_totals` equals the sum of per-side component dictionaries; broker component always 0.0 (VTB zero fee to 2026-12-31).
- Same inputs → identical `run_id`.
