## 2. Decision Architecture: What This Plan Must Falsify

This project fails safely only if it can **reject** bad ideas cheaply. The decision hierarchy is:

1. **Is there an economic mechanism?** — carry, convenience yield, dividend/forecast, funding-rate, deliverable supply. If story is “correlation = 0.8 so it reverts” → reject without trade (see §7).
2. **Can EOD bars define the signal?** — If hypothesis requires minute-level queue or live spread-book → parked until EOD version is rejected and cost of upgrade is justified.
3. **Does net X survive cost?** — Base → Conservative → Stress. Failure at Base = hard reject. Survival only at Base with failure at Conservative = “fragile, manual-latency-sensitive” tag.
4. **Does one portfolio beat LQDT with finite capital & queue?** — Single virtual portfolio, no oracle, respecting IM, VM calls, rejected fills, and 3–90 min latency. If only cherry-picked individual spreads beat LQDT → reject architecture.
5. **Does simplicity beat complexity?** — Fixed-minimum sizing + ranked queue must be beaten by adaptive/size/scale-in variants in ablation, on same splits/delays, before any complexity is adopted.

**Deliverable is a ranked test plan, not a chosen strategy.** No backtest claimed below. Where numbers appear they are **verified contract/fee/margin facts** or **deterministic cost arithmetic**, never PnL.

### 4.1 What free EOD history actually contains

ISS History endpoint for any FORTS contract (verified live):

```
GET https://iss.moex.com/iss/history/engines/futures/markets/forts/securities/<SECID>.json
  ?from=YYYY-MM-DD&till=YYYY-MM-DD
```

Returns per-calendar-day (no weekend gap issue): `BOARDID, TRADEDATE, SECID, OPEN, LOW, HIGH, CLOSE, OPENPOSITIONVALUE, VALUE, VOLUME, OPENPOSITION, SETTLEPRICE, SWAPRATE, WAPRICE, CHANGE, QTY, NUMTRADES, SHORTNAME, ASSETCODE, SWAPRATE_CURR` — verified columns on CRZ6 2026-10-21 and expired CRU6 2026-09-17. `SETTLEPRICE` and `OPENPOSITION` are daily settlement and OI; `SWAPRATE` in RUB per contract per day carries funding for perpetuals.

**Coverage checked 2026-10-22:**

* Active contracts return full OHLCV + OI (e.g., CRZ6: 2026-10-21 CLOSE 12.404, SETTLE 12.419, OI 33.9 m contracts, VOLUME 6.59 m).
* Expired contracts remain queryable after last trade (CRU6 last day 2026-09-17: SETTLE 12.5876, OPENPOSITION 0, volume 2.29 m) — delisted history **is** available, but **contract specification history is not** via this endpoint; point-in-time lot/step/IM must come from daily securities snapshots.
* Perpetuals are perpetual in name and infinite-dated in practice (`LASTTRADEDATE = 2100-01-01` for CNYRUBF/GLDRUBF/etc.), but their **funding series** is the extra `SWAPRATE` column — already in EOD.

**Limitations that must be modeled:** No intraday OHLCV in this source; no spread-book history; no per-contract historical IM/step series in one call — must be scraped/archived daily. No corporate-action-adjusted stock-future series flag.

Unknown fees = unknown, not zero. Every hypothesis is evaluated under **all three**:

| Scenario | Label | Broker (RUB/contract/leg) | Exchange (per contract/side) | Spread (observed) | Slippage ticks/leg/side | LQDT drag applied | Interpretation |
|----------|-------|---------------------------|------------------------------|-------------------|-------------------------|-------------------|----------------|

| **S** | **Stress** — adverse manual | **3.00** (voice/urgent/2nd attempt + BCS Investor short-leg 0.1% trap if triggered) | 100% taker | **2.0×** | **2.0** | Same | “30–90 min delay into volatile book” |

Round-trip cost (RTC) for a spread with `n1` contracts leg1, `n2` leg2:

```
RTC = 2*(n1*fee_ex1 + n2*fee_ex2) + (n1+n2)*2*fee_broker
      + spread_entry + spread_exit          [= 1.0 * (n1*sp1*tv1 + n2*sp2*tv2) * mult]
      + slippage_entry + slippage_exit      [= 2 * (n1*tv1 + n2*tv2) * ticks * mult]
```

Spread is `0.5 bid-ask each side` (crossing half-spread in, half out = one full spread total). Slippage is extra ticks beyond BBO mid.

**Reading the table:** A 15-calendar-day hold of H1a on RUB 30k must clear **~RUB 13–27 RTC** plus **RUB 6–17 LQDT drag** (depending on collateral accounting, §6) before it prints positive X. That implies required mean-reversion amplitude **> RUB 20–44** just to break even — which for CNY (tick = RUB 1) is **20–44 ticks** of spread move, i.e., ~0.16–0.36% of notional, or roughly **2–5 days of typical carry** at current funding (see H1a card). This alone filters hypotheses.

**Why three scenarios:** Base survival proves *possibility* under favorable execution; Conservative survival proves *routine viability*; Stress survival proves *manual-latency robustness*. **No hypothesis is “approved” on Base alone** — ranking (§1) is by Conservative RTC / hurdle ratio.

> **Calibration vs “zero”:** VTB promo 0.00 RUB/contract (until 31-12-2026) would cut Base by RUB 1.2–6.6; calendar-spread order 20% discount (K=0.2) would cut exchange fee by ~20% *if* accessible via Spectra/QUIK — both are disclosed as **upside memo, not base case**, because future execution at BCS (0.08–1.20 RUB/contract tiered) and post-promo VTB (1.00 RUB/contract) will not be zero.

## 6. LQDT Counterfactual & Excess Metric X(t) — No Double-Count

### 6.1 Principle

Every ruble diverted from LQDT (test cash), every ruble of VM paid/received, and every ruble of IM locked must have a **matched LQDT counterfactual** with identical external flows. The test P&L is **excess**:

```
X(t) = NAV_test(t) − NAV_counterfactual(t)
NAV_test = test_cash + VM_cum − fees − slippage + value_of_open_positions(MTM)
NAV_cf   = same external flows compounded in LQDT (+ collateral yield counted once)
```

**Two collateral modes reported for every backtest:**

* **C1 — Segregated:** Test book is fenced. LQDT core (RUB 40m+) stays fully invested; test cash RUB 30k is the *only* capital whose LQDT return is foregone. Excess = test P&L − (30k × LQDT_return) − costs. This is the **primary pilot metric** (isolates strategy skill).
* **C0 — Full-account (with EDP):** Single settlement account where LQDT *can* be posted as collateral and continues earning. Here **never deduct LQDT return twice**: the yield on collateral still posted is *retained* in both test and counterfactual (so it cancels). Only the *incremental* cash diverted to IM/VM buffer loses LQDT accrual. Research must publish both C1 and C0; if broker’s Single Cash Position (EDP / единый денежный пул) allows LQDT-as-collateral with haircut, C0 excess will be **higher** than C1 by the retained yield — must not be misread as strategy alpha.

### 6.2 LQDT daily hurdle at current rates

RUSFAR 13.97% pa ⇒ LQDT net ~13.5–13.7% pa after TER ⇒ daily log hurdle **~0.035%/day**, i.e. **RUB 10.5/day on RUB 30k** (≈ RUB 73/week, ~RUB 157/fortnight). Any spread held 15 days drags ~ RUB 17 (C0) of foregone compounding; a 60-day hold drags ~RUB 69 (C0). Shorter holds are therefore structurally favored — long “hope” trades must earn carry, not just wait.

### 6.3 Tax/fee exclusions per prompt

Exclude only **long-term holding (LTH) benefit** of LQDT (0% on 3y+ for Russian retail). All other taxes (13% on VM/futures PnL, fund distributions) are **identical in test and counterfactual** and cancel in excess — model as zero at pilot scale. Residence/account wrapper unknown → mark as conditional.

## 7. Why z-Scores / Correlation / ADF Are Not a Trade

This section is the research team’s shared rejection checklist. Every candidate that relies solely on:

* Pearson correlation > 0.8
* “Cointegration p < 0.05” (ADF on residuals)
* z = (spread − μ)/σ crossing ±2
* “Hurst < 0.5” or “stationary by KPSS”
* “Half-life = 5 days so we hold 5 days”

…is **flagged as non-economic** and must pass five extra gates before costing logic runs:

| Gate | Why alone it fails | What economics must add |
|------|--------------------|-------------------------|
| **1. Mechanism** | Correlation ≠ deliverable linkage; two tech stocks can correlate in risk-on then diverge on earnings. | Carry, convenience yield, dividend forecast, funding arbitrage, index arbitrage — state the cash-flow that enforces mean-reversion or its band. |
| **2. Stationarity fragility** | ADF/KPSS are low-power on short, heteroskedastic samples; regime shifts (2022 sanctions, 2024 rate regime, 2025 FX controls) break parameters. Book counter-examples: Lopez de Prado (2018) shows ADF false-positive rate rises with volatility clustering. | Require walk-forward parameter stability; break test (Chow/Bai-Perron) on train; Chow p < 0.05 ⇒ invalidate, not re-fit. |
| **3. Tradability gap** | z at close ignores spread of spread, integer lot, IM, expiry. A 2σ = RUB 8 move that costs RUB 27 to enter/exit is noise. | Map to integer lots with IM check; simulate settlement-price fill + slippage; reject if amplitude < 1.5× Conservative RTC. |
| **4. Horizon mismatch** | Half-life from AR(1) on daily closes assumes AR(1) DGP — rarely true for calendar strips with roll jumps. | Estimate half-life **after** removing deterministic roll/carry; report confidence interval; require holding period < 1/3 time-to-expiry. |
| **5. Selection bias** | Testing 200 pairs × 5 z thresholds × 3 windows = 3,000 chances; one p=0.01 is expected. | Pre-register candidate ranges; log every trial; apply Benjamini-Hochberg or Deflated Sharpe; hold-out set untouched. |

> **Literature anchors:**
> * Chan, E. *Algorithmic Trading* (2013), Ch. 2–6 — ADF/Hurst/VR/Johansen taxonomy, but Ch. 6.6–6.8 explicitly warn “cointegration does not imply mean-reversion at tradeable horizon” and demonstrate **calendar spreads often drift due to term-structure shift**, not revert.
> * Vidyamurthy, G. *Pairs Trading* (2004), Ch. 3, 7–9 — distinguishes *distance* (non-parametric) vs *cointegration* (common-trends) vs *stochastic spread* (OU); Ch. 7 “Testing for Tradability” requires **spread variance bounded and trade-trigger feasible** beyond unit-root test; Ch. 8 shows **band optimization needs explicit transaction-cost function**.
> * Carver, R. *Systematic Trading* (2015), Ch. 1–4, 10–12 — “forecast must have economic rationale” and “cost-aware sizing” (cost per trade vs forecast strength) — raw signal strength ≠ position.

## 9. Common Machinery: Normalization, Hedge, Integer Mapping, Expiry, Breaks

> **Rule: Every threshold below is a *pre-registered candidate range* until walk-forward selects; training data only. No “best ex-post” threshold in final report.**

### 9.1 Normalization

Per hypothesis, one canonical spread price in **RUB per spread unit**, tick-aligned:

* **Dollar-valued legs** (BR, NGM): Convert each leg to RUB via `RUBprice = FX * USD_price * lot` where FX = MOEX USD/RUB settlement (used by clearing for step-price). Use same FX for both legs at same timestamp to avoid FX noise.
* **Calendar (same lot):** `S_cal = P_far − P_near − carry_fair` (H2/H3). `carry_fair` is model carry (see cards); if none, S is raw difference but validated against forward curve.
* **Perp-quarter:** `S_perp = P_perp − P_quarter − cum_funding_fair` or directly `z_fund = swaprate − fair_funding`.
* **Cross (gold/silver etc.):** `S_x = P_a − β·P_b` with β in price units; alternatively `S_log = log P_a − β_log·log P_b` (Carver/Chan log-spread); choose per family and keep consistent.

Standardize to **risk units**: `s = S / σ_S` where σ is rolling SD of *residual* (not raw S) over lookback L. But `s` never triggers alone — trigger needs `|S|` in RUB > cost floor.

### 9.2 Hedge / β estimation

Three estimators, **chosen per family and frozen**:

1. **Carry-implied** — β=1 (or lot-ratio) from spec. Used for all calendars (H2/H3) and perp-quarter (H1). No regression.
2. **Rolling OLS** — `β = Cov(P_a, P_b)/Var(P_b)` over formation window, with Newey-West, winsorized, outlier-capped. For H5 only; requires 60–120 day formation.
3. **Kalman β(t)** — state-space `P_a(t) = α(t) + β(t) P_b(t) + ε`, random-walk β. Chan Ch. 6 endorses Kalman for time-varying hedge but warns of overfit if noise ratio tuned in-sample. Pre-register `Q/R` ratio range; validate stability.

**No hedge is updated on test data.** Walk-forward refits only at train→test boundary with gap.

### 9.3 Integer lot mapping

A theoretical ratio `r = n1_continuous / n2_continuous` is mapped to feasible integer `n1,n2` by:

```
min  | r − n1/n2 |   s.t.  n1*IM1 + n2*IM2 ≤ C_avail / buffer
                   and  max(n1,n2) ≥1
                   and  cost(RTC) < trigger_gap
```

Buffer = 1.5× gross IM (pilot prudence; backtests also show 1.2× and 2.0× sensitivity). For RUB 30k, most hypotheses bind at 1×; BR full or TT×TP bind at 0 (rejected for size).

### 9.4 Entry / exit / invalidate / expiry logic

All hypotheses share this state machine; parameters differ:

```
FLAT ──[z_entry breached AND |S|>cost_floor AND days_to_expiry>min AND OI/volume filters pass]──► OPEN
OPEN ──[TP hit OR mean-revert to exit band OR time stop OR structural-break OR margin call]──► FLAT
ANY  ──[break test fires OR expiry-2d OR IM spike >1.5× OR OI collapse <20th pct]──► FORCED FLAT (at market + stress slippage)
```

* **Filters pre-entry:** `VOLTODAY > 5k contracts & OI > 10k` per leg (or perp equiv) on both legs; spread BBO spread-ticks < 10; no entry on expiry day itself.
* **Structural-break invalidate:** 5-day rolling Chow on formation-window β; or sequential CUSUM on spread residual; or ADF-on-rolling-window stability. Any break ⇒ **no new entry** for cool-down N days; existing position **tightens TP** or forced-flats depending on severity.
* **Expiry handling:** Hard flat **T-2 trading days** before `LASTTRADEDATE`. Calendar roll is **not** automatic; roll = close old spread + open new spread as two independent decisions, each paying RTC again. Perpetual leg never expires.

### 9.4a “Dark” reality adaptation

Prompt says execution can be manual at VTB with “dark-only future screener + Telegram alerts.” Research must model:

* Signal computed on **settlement price** (SETTLEPRICE) at evening clearing (~23:50 MSK) or daily close — not intraday snapshot.
* Alert latency 3–90 min → fill simulated at **next day’s WAPRICE or OPEN+slippage**, not same-bar close. Sensitivity column “+60 min” mandatory.

### 9.5 Point-in-time inputs

Required daily snapshot (archived, not live-regenerated):

* Contract table: SECID, ASSETCODE, LOTVOLUME, MINSTEP, STEPPRICE, LASTTRADEDATE, SETTLEPRICE, INITIALMARGIN (per KPUR/KSUR/KNUR tier), BUYSELLFEE.
* Marketdata: BID/OFFER/BIDDEPTH/OFFERDEPTHT/SETTLEPRICE/OPENPOSITION/VOLTODAY (to estimate spread cost and filters).
* Corporate actions / splits for stock-futures underlying (MOEX corporate-action feed).
* RUSFAR ON + LQDT TQBR CLOSE for hurdle.
* Perp swaprate history (already in FORTS history `SWAPRATE`).

All “as of T” inputs must be timestamped ≤ T close; no using T+1 IM.

## 10. Candidate Hypothesis Cards H1–H6

Each card follows: **Story → Instruments → Data → Formula/Units → Param-selection → Entry/Continue/Exit/Invalidate → Failure mode → Validation → Reject decision.** Thresholds are **ranges**, not points.

### H1a — CNY Perpetual Funding vs Quarterly Carry (Family A)

**Economic story:** CNYRUBF is a 1-day auto-rollover future whose price is anchored to CNY/RUB spot via daily **funding (swaprate)**. The quarterly CRZ6 price embeds **implied RUB carry** (interest-rate differential + FX basis) to Dec expiry. When `P_perp − P_quarter` deviates from fair carry by more than funding + carry uncertainty, a spread mean-reverts as funding accrues or roll-down realizes. This is **cash-flow enforced**, not stat arb.

**Instruments:** Long 1× CNYRUBF + Short 1× CRZ6 (or inverse). Hedge 1:1 notional (both 1,000 CNY). Margin benefit MKS Gr.3 (FX family). Tick 1 RUB both legs.

**Data:** Daily FORTS history (both contracts), perpetual `SWAPRATE` (RUB/1,000 CNY/day), RUSFAR ON, FX settlement, IM snapshots. Formation: 60–90 days.

**Formula:**
```
Implied daily carry (quarter) c_imp(t) = (F_quarter(t) − S_perp_proxy(t)) / tau
  S_perp_proxy ≈ P_perp(t) (perp ≈ spot within funding band)
Fair funding f_fair(t) = RUSFAR_RUB − RUSFAR_CNY_proxy
  proxy: on-shore CNY rate or, pragmatically, 0–2% pa (param)
Spread signal S(t) = P_perp(t) − P_quarter(t) − E_carry_fair(tau)
  E_carry_fair = f_fair * tau_remaining  (linear carry accrual)
z(t) = S(t) / sigma_S   where sigma_S = stdev of S residual over L
Alternative direct: z_fund = (swaprate_observed − f_fair)/sigma_fund
Units: RUB per 1,000 CNY; thresholds in ticks.
```

**Param-selection (pre-registered):**
* L ∈ {30, 60, 90} days for sigma; tau in days; f_fair ∈ {1.0%, 2.0%, spread of RUSFAR−2%} pa; entry |z| ∈ {1.5, 2.0, 2.5}; TP at z ∈ {0, ±0.5}; SL/time-stop variants; min |S| floor = Conservative RTC + LQDT_5d.

**Entry / Continue / Exit:**
* Entry: |z| ≥ z_entry AND |S| > RTC_Cons + 0.5*IM variation AND tau ≥ 10 days AND OI both legs > 20k.
* Continue (next day while OPEN): hold while |z| on favorable side and not mean-reverted; **conditional value test** (§12) each day; no averaging down.
* Exit: z crosses 0 (or ±0.5) OR tau ≤ 5 (expiry flatten) OR time-stop N ∈ {10,15,20} days OR spread adverse by 2× entry gap.
* Invalidate: RUSFAR jump > 200 bp/day or SWAPRATE formula change announced by MOEX/NCC → cool-down 5 days.

**Failure mode:** Central bank FX intervention, capital-control step, or NCC funding-parameter change (K1/K2 bands, L1/L2) → carry fair jumps; spread walks away without reversion, VM drains test book. Also: perp funding can stay pinned at floor/cap for weeks, creating slow bleed.

**Validation:** Walk-forward quarterly refit; gap = N_lookback/3 between train and test; stress branch with MOEX funding-spec change dates as known event dummies.

**Reject if:** Net X median ≤ 0 on C1 after Conservative cost and LQDT drag, or half-life > tau/2, or funding-persistence test shows swaprate is regime-shifted (ADF on swaprate residual p > 0.10 across 2 regimes).

**Verified pilot edge check (not PnL):** Current funding 0.00571 RUB/1k/day = RUB 5.71/day per contract, i.e. **~47 bp per fortnight** on RUB 12,230 notional. Spread move to close entry-level deviation must exceed Base RTC 7.5 RUB within ~1.3 days of funding accrual alone — plausible only if dislocation > 1.5–2σ **and** held >10 days. Hence **frequency will be low** — matches prompt’s “zero-trade days acceptable.”

### H2a — CNY Calendar Carry (CRZ6 vs CRH7) (Family A–B)

**Story:** Pure FX carry strip. `F(March) − F(Dec)` = carry between Dec and Mar maturities. In absence of deliverable commodity squeeze, forward FX follows covered-interest logic; calendar spread is **direct carry quote**. Mean-reversion occurs when front-vs-back misprice relative to interpolated RUSFAR curve corrects, not because two random series correlate. Time decay is deterministic (theta = −carry accrual/day), giving structural edge if entered rich/cheap correctly.

**Instruments:** CRZ6 (2026-12-17) vs CRH7 (2027-03-18), 1:1. MMS-eligible (CNY second quarterly). IM ~RUB 1,281 on spread vs RUB 2,467 gross.

**Data:** Same as H1a but without perp; need RUSFAR curve (O/N out to 3M) to compute fair calendar carry; alternatively use `c_fair = (F_far − F_near)/tau`.

**Formula:**
```
S_cal(t) = P_far(t) − P_near(t)
fair_cal(t) = c_fair * tau_spread   where c_fair from RUSFAR 3M or rolling median of S_cal/tau
signal s(t) = (S_cal − fair_cal) / sigma_cal
Units RUB/1,000 CNY. Entry on s deviation AND fair_cal stability (no rusfar jump).
```

**Params:** L ∈ {45, 60, 90}; entry |s| ∈ {1.8, 2.2, 2.8}; exit s=0±0.3; max hold = min(20 days, tau_near − 2d); entry floor = RTC_Cons + 2× daily carry.

**Continue vs exit:** Each day, remaining theta (carry bleed/earn) is recomputed; position closed early if adverse theta flips sign (carry curve inversion) — see §12.

**Failure:** Rushing into March when Dec spot is stressed (year-end FX liquidity), curve inverts and stays inverted; spread trends, not reverts. Observed CRZ6/CRH7 spread on 2026-10-22 implies ~ RUB 0.205 over 91 days = **2.25 RUB/1k per day carry** — modest; a 20-day hold earns ~45 RUB carry but Base RTC is 9.5 RUB, leaving narrow net. So **model predicts few trades**.

**Validation:** Train on 2020–2024 CNY calendars (CRH3→CRZ6 rolls, handling tick history), test on 2025–2026. Must survive 2022-03 FX restriction regime split (structural break test).

### H3a — Brent Mini Calendar (BMX6 vs BMZ6) (Family B)

**Story:** Commodity calendar reflects **storage cost + convenience yield + expected scarcity**. In contango (far > near) seller of calendar earns roll-down; in backwardation the opposite. Near-term physical tightness (e.g., refinery turnarounds) can push `F_near − F_far` rich, then mean-revert as tightness eases. This is seasonal/operational, not pure stat.

**Instruments:** BMX6 (Nov-26, last 2026-11-02) vs BMZ6 (Dec-26, last 2026-12-01), 1:1 × 1 bbl mini. Full BR (10 bbl) as scale-up analog. MMS-eligible to 2nd monthly only (so Nov–Dec **is** eligible, but Dec–Jan would still be eligible until Dec expires — verify monthly rolling).

**Data:** BR forward curve (MOEX BR/BM settlements), Dated Brent vs front spread if available, OI/volume per expiry, seasonal dummies (month).

**Formula:**
```
S_oil(t) = P_far − P_near − seasonal_fair(month_pair)
seasonal_fair estimated as median S over same month-pair last N years (N=3–5) or rolling 60-day median.
s = S / sigma (heteroscedastic — scale by near price or use % spread)
Units: USD/bbl → RUB via FX; threshold in USD ticks (0.01 USD = 0.82 RUB).
```

**Expiry:** Must flat Nov leg by T-2 (~2026-10-29!). Pilot starting 2026-10-07 would face **only ~3 weeks** on nearest expiry — forcing rapid test; plan rolls to Dec→Jan pair (BMZ6 vs BMM? actually BMF7 = Jan-27 listed). Real hypothesis is **recurring monthly pair**, not one fixed pair.

**Params:** L ∈ {30,45,60}; entry |s| 2.0–2.8; exit 0±0.5; seasonal_fair lookback 3y; max hold 15 days; OI filter 10k min.

**Failure:** Geopolitical shock (pipeline, sanctions) → curve structure breaks, convenience yield spikes, calendar stays inverted for months despite “reversion” signal → forced loss at expiry. Oil calendars famously **trend** in supply shocks (Chan Ch.6 “Do Calendar Spreads Mean-Revert? — generally no, except seasonal/month-specific”).

**Validation:** Yearly walk-forward by month-pair; gap = 10 trading days; report per-month-pair hit rate separately — aggregation must not hide that only 2 of 12 month-pairs ever work.

## 12. Entry vs Continuation: Conditional Value, Not Sunk Cost

> Prompt core: *Conditional expected incremental value from now, remaining costs, LQDT counterfactual, distribution of time-to-exit, loss/expiry risk and freed funds for competing opportunities. Do not make “holding long” automatically bad or sunk losses a reason to continue.*

### 12.1 Formal rule

At any day `t` while position in spread `i` is OPEN, compute **incremental expected value (IEV)** from *now* (mark-to-market), not from entry:

```
IEV_i(t) = E[ PnL_to_exit | signal_t, tau_remaining ] − RTC_remaining(= exit RTC + time LQDT drag)
           − opportunity_cost_of_locked_IM(t)
where:
  E[PnL_to_exit] from walk-forward conditional mean: historical PnL of same hypothesis
                   when signal at t equals s(t) and tau similar
  RTC_remaining = one-way exit cost (exchange+broker+0.5 spread+slippage at Stress if adverse)
                  + LQDT_drag_daily * E[time_to_exit | s(t)]
  opportunity_cost = bestAlternativeQueueExpectedExcessPerDay * E[time_to_exit]
                     (if queue non-empty and alternative can be funded by freeing IM)
```

**Action:**

* If `IEV_i(t) < 0` **and** alternative queue has positive-expected trade that fits freed IM → **flatten i now** (even at loss), free IM, enter alternative. This is *opportunity-aware exit*, not stop-loss.
* If `IEV_i(t) < 0` but queue empty → flatten if `E[PnL_to_exit] < exit_cost` (i.e., expected loss from holding exceeds exit cost) — essentially time-stop.
* If margin call risk (VM buffer < 1 day of 99th-pct adverse move) → flatten immediately (risk rule overrides IEV).
* **Never** count sunk entry RTC or sunk PnL in IEV — they cancel on both “hold vs close now” branches.

**Practical estimator:** For each s bucket (|s| ∈ [1.5,2.0), [2.0,2.5), [2.5,∞)), compute empirical distribution of *future* spread PnL to exit (at TP or time-stop) from **train data only**. Then IEV at t is median (or mean minus 1 SD conservative) of that bucket. This avoids “we lost 200 RUB so we must hold to win it back.”

### 12.2 Expiry & loss risk

* Calendar spreads lose deterministic theta (cost of carry) each day regardless of signal → IEV must subtract daily theta (for FX, RUSFAR-day; for oil, seasonal drift). If theta turns adverse (curve inverts), IEV negative even before any price move.
* For quarterly FX/index, forced flatten at T-2 ensures loss is bounded but still can be large if spread moved adversely 5–10% of notional (e.g., RUB 600 on ~12k notional for CNY = 5% move). Distribution of tail must be reported (99th pct loss), not hidden by average.
* Physical/perp funding jump risk: overnight gap (observed CNY close 12.404 vs settle 12.419 = 15 RUB gap on 1k notional = 0.12% overnight). Stress RTC already embeds 2× spread for gap day.

### 12.3 Freed funds for competing opportunities

Opportunity cost is real only if alternative **(a) exists now**, **(b) fits RUB 30k IM**, and **(c) was not cherry-picked ex-post**. Hence queue (§14) must be evaluated on *available-at-t* set, not full sample optimum. Prompt explicitly forbids “oracle that always reallocates to ex-post best trade.”

## 13. Sizing Compared on Same Splits, Fixed vs Capped Adaptive vs Scale-Ins

All three variants share **same data splits, same execution delays, same cost scenarios, same total authority (RUB 30k + max RUB 15k emergency only-to-flat)**, so difference is architecture, not data.

### 13.1 Definitions

| Variant | Rule | Cap | Emergency behavior |
|---------|------|-----|--------------------|
| **F1 — Fixed minimum** | `n = 1× spread (or 5× micro minimum) if IM*1.5 ≤ C` else 0. Forecast only gates entry (yes/no); size never varies with |z| or volatility. | 1× | No add; emergency funds only to meet VM and flatten. |
| **A1 — Capped adaptive (vol-targeted)** | `n = clamp( floor( (C * vol_target / sigma_spread) * forecast_strength ), 1, n_max)` where `n_max = 2` for pilot (3 on RUB 10m scale). `forecast_strength = |s|/z_entry` capped at 2.0. | 2× (pilot) / ~4× (scaled book) | Same — no increase on loss; adaptive size is *a priori* function of signal strength, not PnL. |
| **S1 — Preplanned scale-in** | Plan at entry: up to 2 tranches, 2nd triggers at `|s| ≥ z_entry + 0.7` *only if* first still open and IEV_2 > 0 incremental (i.e., adding improves IEV, not sunk). Second tranche = 1× same size as first (no pyramid). Total still ≤ cap. | 2× | **Any second tranche funded from uncommitted C only** — never from emergency reserve, never after drawdown breaches 10k shortfall. Reserve cannot “fund averaging down” (prompt prohibition). Emergency still only-to-flat. |

### 13.2 Why S1 is not averaging down

Averaging down = “I’m losing, so I add to improve breakeven.” S1 = “My *ex-ante plan* said: if spread widens another 0.7σ, the conditional edge *per unit* is higher (farther from fair), so a second unit has positive IEV *on its own*.” Formal test: compute IEV_2 **ignoring first position** — if IEV_2 < 0, second leg never fires, even though average price would look better. This distinction is what Leung & Li (2015) and Chan (2013 Ch.5) require: optimal double-stopping has *disconnected* entry region — too-close-to-stop-loss is *not* entry even if underwater.

### 13.3 Hypothesis for ablation

*Null (must be disproven):* `A1` and `S1` do **not** improve net X vs `F1` after costs, given RUB 30k cap and manual latency. If walk-forward shows X_A1 − X_F1 median < Conservative RTC margin or Sharpe difference p > 0.10 (Harvey-Liu), complexity is rejected. This directly addresses prompt §5: “missing evidence must prevent complexity being treated as necessary.”

## 14. Opportunity-Arrival Model: Ranked Queue vs Oracle (Anti-Oracle Test)

### 14.1 Ranked queue (honest)

Each day `t`, score every eligible spread `i` with:

```
score_i(t) = ( |S_i(t) − fair_i(t)| − RTC_Cons_i ) / IM_i(t)    # excess per unit IM
           = effective edge per ruble locked
```

* Eligibility: filters (§9.4) pass, tau ≥ min, |s| ≥ z_entry, |S| > floor.
* Rank descending; top-ranked that fits `C_avail` is entered (1 at a time for pilot; parallel later).
* Ties: lower IM first (fills book), then higher OI.
* If top cannot fit due to IM, skip to next — queue never fragments book (no 0.3× positions).
* **Stale/rejected log:** Every day an eligible signal existed but portfolio was full or IM insufficient → counted as *foregone opportunity*; its *realized* future PnL (if it had been taken) is tracked for queue-efficiency audit — but never used to re-rank ex-post.

This is Carver’s “forecast → position” mapped to spread book: single score, deterministic, no discretion.

### 14.2 Oracle (dishonest, for ablation only)

Oracle at `t` knows *realized* future PnL of each eligible spread to its optimal exit, picks max, and pretends it chose correctly. Its X is **unachievable upper bound**. Purpose is to measure **regret gap**: `regret = X_oracle − X_queue` after same costs. If queue captures > 60–70% of oracle’s achievable edge net of costs, queue is “sufficient” (prompt test criterion) and no ML allocator is justified now.

### 14.3 Stale/rejected inclusion

Past available opportunities = all eligible signals on **train** period, including days queue was full. Do **not** train queue parameters on test period. Queue’s z thresholds are the same as individual hypotheses’ thresholds — no extra tuning.

## 15. Validation Discipline: Walk-Forward, Gaps, Logs, Hold-Out

Chronological walk-forward, no information leakage:

1. **Preregister** candidate ranges (§9–10) in CSV before any test fetch. Commit hash logged.
2. **Expanding or rolling?** Rolling 3-year train / 1-year test for FX/oil (regime-sensitive); expanding for stock pairs (sparse). Gap between train-end and test-start = **L_max/2** (or 15 trading days min) to prevent look-ahead from overlapping rolling σ windows; signal/holding overlap size explicitly sets gap.
3. **Fit only on train:** β, σ lookback, fair estimates, z thresholds, TP/SL chosen by **maximizing net X per trade after Base cost**, not gross. Optimize via grid; penalize turnover > 1/trade per month.
4. **Log every trial:** date, hypothesis, params, RTC scenario, X_C1/C0, drawdown, trades, foregone queue. No cherry-picked “best” without full log.
5. **Statistical guards:**
   * Deflated Sharpe Ratio (Bailey-López de Prado) for multiple trials (n≈168); required DSR p < 0.05 to claim edge (not raw Sharpe).
   * Benjamini-Hochberg on per-hypothesis significance.
   * Bootstrap (stationary, block len = half-life) for X CI.
6. **Hold-out untouched:** 2026-07-10 → 2026-10-07 (90 cal days, ~64 trading days) — only portfolio-level E07 runs here once, reporting distribution of time-to-exit, LQDT shortfall path, and 10k-trigger events. No param tweak on hold-out; violation = invalidate study.

**Primary metric (per prompt):** **Net RUB excess X(t) after all modeled costs, vs matched LQDT counterfactual with identical external flows.** Secondary: max drawdown of X, time under water, trades/year, tail loss (99th pct).

## 16. Risk, Governance & Emergency-Funding Protocol

### 16.1 Drawdown & shortfall action ladder (prompt defaults, unvalidated)

| Condition (excess-curve basis) | Action | Funding allowed? |
|---------------------------------|--------|------------------|
| 5k excess drawdown from high-water or 5k cumulative LQDT shortfall | **Warning** — pause new entries; review open spread IEV daily | No |
| 10k drawdown from X HWM *or* 10k cumulative shortfall | **Act** — flatten existing at market (stress slippage); **any funding is solely to reach flat** (prompt mandate) | Only to meet VM to *reach flat*, counts to RUB 15k gross cap, needs explicit approval, incident-logged |
| 15k cumulative shortfall (outer boundary) | **Hard stop** — immediate flat, 90-day review gate; no new risk until review passes | Same as above, up to cap |
| 90 calendar days elapsed | **Review gate** even if no breach — loss not reset | No auto-reset |

**Broker use of core collateral (R > RUB 40m LQDT) without approval = incident**, counts to 15k gross allowance. Sale proceeds of LQDT collateral are *not* automatically economic loss in X — only realized loss net of collateral retained yield counts (prompt distinction).

### 16.2 Margin discipline

* Pre-trade: `required_IM_spread * 1.5 + 2× daily 99th move < C_avail` else skip trade (even if queue ranks it top).
* Intraday: If evening VM close breaches 50% of VM buffer, preemptive flatten next AM (no waiting for exchange margin call) — models manual 5–15 min latency as *next-settlement* exit with extra tick.

### 16.3 Human quota

Manual capacity = **1 new spread entry + 1 exit per trading day max** (conservative for 3–90 min window and Telegram-dark workflow). Queue test must respect this throttling; unconstrained portfolio is oracle-like.

### Vidyamurthy, G. — *Pairs Trading: Quantitative Methods and Analysis* (Wiley, 2004)

**Inspect first:** TOC: Ch.1 CAPM/MS-neutral, Ch.2 Time-series models, Ch.3 Factor models/APT, Ch.4 Kalman, **Ch.5 Overview — history/motivation/cointegration**, **Ch.6 Pairs selection (distance vs cointegration)**, **Ch.7 Testing for tradability**, **Ch.8 Trading design (band design, dynamics, non-parametric, regularization)**, Ch.9–12 Risk arb.

**Extract for this plan:**

* **Ch.5–6 (pp.71–101):** Common-trends model: “two prices share I(1) common trend ⇒ spread is I(0)” is *selection story*, not trade proof; distance SSD vs cointegration — Gatev et al. ### Chan, E.P. — *Algorithmic Trading: Winning Strategies and Their Rationale* (Wiley, 2013)

**Inspect first:** TOC: Ch.1 Backtesting traps, **Ch.2 Mean-reversion basics (ADF, Hurst, VR, half-life, CADF, Johansen)**, **Ch.3 Implementing mean-reversion (Bollinger, Kalman, costs)**, Ch.4 Stocks/ETF, **Ch.5 Currencies & futures (calendar, roll yield)**, Ch.7 Momentum/roll, Ch.8 Risk/Kelly.

**Extract:**

* **Ch.2 (pp.39–62):** ADF vs KPSS vs VR — ADF null is *unit root* (non-stationarity), so “fail to reject” ≠ stationary; need both directions. Hurst <0.5 ≠ tradeable if variance is microstructure noise. **Half-life formula** `t½ = ln(2)/λ` from OU fit, but λ biased if series has jumps (expiry roll).
* **Ch.3 (pp.63–85):** **Bollinger vs Kalman**: Bollinger bands are moving-average reversion; **Kalman filter is dynamic hedge regression** (pp.75–82) — useful for H5a β(t) but warns Kalman *lags* at regime shift → same reason we prefer static carry-implied β for H1–H3. **Cost section (pp.84–85):** Chan quantifies “roll-adjustment before test” — calendar P&L must remove contract-roll jump, otherwise fake mean-reversion.

**Inspect first:** TOC: Part One Behavioural, **Part Two Toolbox (Fitting Ch.13, Portfolio Ch.14)**, **Part Three Framework (Instruments Ch.6, Forecasts Ch.7–8, Vol-targeting Ch.9, Position Sizing Ch.10–11, Costs Ch.12)**, Appendices (EWMAC, Carry rule).

## 20. Falsification Criteria & Project Gates

### 20.1 Per-hypothesis reject triggers (any one ⇒ hypothesis rejected, not retuned forever)

1. **Cost fail:** Base-scenario median net X ≤ 0 on C1, or Conservative X 10th pct < −5k (warning level) on rolling window.
2. **Frequency fail:** < 2 eligible trades/year on median param (after filters) → opportunity set too sparse for manual workflow to justify monitoring.
3. **Stability fail:** Chow/Bai-Perron break p < 0.01 on train, or half-life CI spans > 3× (e.g., 5–60 days) → parameter unstable.
4. **Expiry trap:** > 40% of trades forced-flatten at T-2 at loss (i.e., edge not realized within expiry window).
5. **Tail fail:** 99th-pct loss per trade > 2.5× median win (left-tail dominated — the “non-convergence” pathology Do & Faff 2012 documented for equity pairs).

### 20.2 Portfolio-level gates

* **After E01–E06:** If *zero* hypotheses survive Conservative → **stop new hypothesis hunt** (prompt: broad hunting without validation discipline increases selection bias). Report “no pilot-viable mean-reversion spread at RUB 30k manual” as honest outcome.
* **After E07:** If queue X net ≤ 0 after C0 accounting on hold-out, or if queue captures < 40% of oracle regret → **do not automate at BCS**; either reduce to single-calendar carry hobby or abandon futures-spread pilot and keep LQDT.
* **After ablation:** If S1/A1 do not beat A0, ship F1 + queue only — no scale-in, no adaptive sizing at pilot scale.

### 20.3 Scale gates

* RUB 30k pilot surviving Conservative ⇒ paper-trade on VTB 1× with 1.5× buffer for 90 days (gate 2027-01-07).
* Surviving Stress as well ⇒ justify VPS sizing increase (1 vCPU → 2) and minute-snapshot upgrade cost.
* Scale to RUB 10–20m only after **KPU​R-tier IM confirmed in writing by broker** and EDP haircut quantified — internal budgets do not prove collateral eligibility.
