# S4c — Workstation handoff and real-data startup: implementation note (2026-11-23)

**Status (2026-11-23):** Implemented and unit-tested. Workstation checkout
fast-forwarded from `aba5d33` to `4a747e2`; the first update reconciled the venv
for `pyproject.toml`, restarted the launch agent, and a separate loopback probe
confirmed that the service reported the new HEAD. A subsequent helper/test-only
fast-forward skipped the restart as intended. The first sync used the older
workstation helper and did not return health in the same payload, so the
current-code single-call readiness path is still unverified on the Mac. The
acceptance timings (docs-only sync <1.5 s, cold catalog <0.8 s with identical
payload hash, bench setup <4 s on APFS) remain **unmeasured** and must be recorded
in a dated baseline. Companion to [plan.md](plan.md) §4 (S4c) and
[remote-agent-testing.md](../remote-agent-testing.md).

## What landed

### 1. Conditional sync — `core/workstation_remote.py` (`sync()`, `await_readiness()`, `_is_runtime_path()`, `_is_dependency_input()`)

- HEAD unchanged after fetch → no-op: no merge, no `uv sync`, no restart, no
  readiness poll; outcomes report `up-to-date` / `skipped-up-to-date` /
  `not-required` (idempotence for a repeated SHA is covered by a test).
- `uv sync --frozen` runs only when the diff contains the lockfile, any
  `pyproject.toml`, `.python-version`, or `uv.toml`, `setup.py`/`setup.cfg`, or the
  candidate `.venv` is missing. The old "always reconcile" behavior is gone.
- The fastcore freshness assertion runs only when dependencies were reconciled or
  `_fastcore.c` changed in the diff.
- Restart only when a runtime path changed (`src/**`, `packages/*/src/**`,
  dependency inputs, `_fastcore.c`). `docs/**`, `tests/**`, package test trees,
  `reports/`, `scripts/`, `config/`, `.github/`, fixtures and root-level files
  (including `AGENTS.md`) fast-forward without touching the service. Unknown
  paths fail safe towards a restart.
- When a restart is needed, `sync()` polls `127.0.0.1:8765/api/dev/health` with
  **bounded** retries (monotonic deadline, 60 s default, 0.25 s interval, 2 s
  per-request timeout) until HTTP 200 **and** `git_head` equals the new head —
  no fixed sleeps. The verified health payload is returned in the same call.
- Runtime-classification table is unit-tested, including the fail-safe default.

### 2. Copy-on-write candidate worktrees — `core/candidate_data.py`, `core/workstation_bench.py`

- Provisioning modes (`MOEX_BENCH_DATA=auto|clone|copy|symlink`, default `auto`):
  - `clone` — APFS copy-on-write via `cp -cR` per top-level entry (macOS auto
    default). Data shares extents with the live trees and decouples on write.
  - `copy` — private byte copy (`shutil.copytree`), the default elsewhere;
    preserves the isolation invariant on every filesystem.
  - `symlink` — read-only-by-convention symlink farm for very large non-APFS
    datasets. **Opt-in only**: the candidate can write through the links into the
    live trees, so it is never the automatic fallback. `data/analytics` stays a
    private directory with a private `research-settings.json` copy in all modes;
    the H1 seal files are always private copies (never cloned/linked into a
    rebind path), and a live seal refuses rebinding.
  - `clone` failure wipes the partial tree and falls back to `copy`.
- Root `.venv` reuse: when the patch does not touch dependency or native-build
  inputs (`uv.lock`, any `pyproject.toml`, `.python-version`, `uv.toml`,
  `setup.py/setup.cfg`, `*.c/*.h/*.pyx/*.pxd`), the bench skips `uv sync` and
  runs the candidate with the root `.venv` and a `PYTHONPATH` that shadows the
  workspace sources with the candidate sources. `_assert_candidate_python`
  verifies in a subprocess that `moex_spread_lab.core.w0` loads from inside the
  candidate and refuses to benchmark otherwise (fail-closed).
- Results report `candidate_setup_ms`, `candidate_data_mode` and
  `candidate_isolated_venv` so the APFS acceptance target can be measured.
- `remote_cli._candidate_options` rejects any patch whose diff touches `data/`
  or `data-lake/` (defense in depth for "no market-data movement"; data/ is
  gitignored, so this can only trigger on a forced or quoted path).

### 3. Fingerprint-keyed derived catalog cache — `core/derived_cache.py`, `proof_runtime/catalog_payload.py`

- `ProofService.catalog()` delegates to `catalog_payload`, which keys a derived
  cache entry over: schema version, timeframe, `initial_capital_rub`, and a
  fingerprint of **every file** under `data/` (excluding `data/analytics`),
  `data-lake/`, `src/` and `packages/*/src/`.
- Key entries are `(relpath, mtime_ns, ctime_ns, size)` plus a SHA-256 content
  digest for files up to 2 MiB. This is deliberately stronger than the plan's
  literal `(name, mtime_ns, size)`: that key cannot detect a same-size in-place
  edit inside a coarse filesystem timestamp tick, which the plan's own acceptance
  demands be covered by a test. `ctime` cannot be restored with `utime(2)`;
  APFS records nanosecond timestamps for larger files.
- Cached payloads are byte-for-byte identical to a fresh build (payload
  normalized once through canonical JSON — `STRATEGIES`/`FILL_LABELS` tuples
  become lists — so the in-memory object, the served bytes and the stored bytes
  are the same object). Equivalence, same-size same-mtime-tick invalidation,
  corrupt-entry fallback, analytics exclusion and the opt-out env
  (`MOEX_DERIVED_CACHE=0`) are covered by tests.
- Entries live in `data/analytics/derived-cache/` (gitignored, mutable, never
  committed), are written atomically, and are scoped per root.
- Synthetic-fixture measurement: full cache-hit catalog ≈3 ms and fingerprint
  ≈1.6 ms (fixture is small; real-data timings must be measured on the
  workstation).

### 4. Explicit outcomes — `remote sync` payload

`outcomes`: `published` (`fast-forwarded` | `up-to-date`), `synced`
(`uv-sync` | `skipped-no-dependency-changes` | `skipped-up-to-date`),
`health-confirmed` (`confirmed` | `not-required`). The verified loopback health
payload and `changed_files`, `restarted`, `candidate_*` telemetry are returned
in one command. The S0 recorder vocabulary already separates `synced` from
`health-confirmed` promotions; the sync result uses the same terms.

## Deliberate deviations from the plan text

1. **Symlink fallback is opt-in**, not automatic. The plan's §1.2 resolution
   ("`cp -cR` with `shutil.copytree` fallback is the implementation; a
   mount/symlink read-only variant is the preferred fallback on non-APFS
   filesystems") is ambiguous, and "never share a writable cache across trust
   boundaries" + the existing isolation tests rule out implicit live-tree
   sharing. `auto` is therefore `clone`→`copy`; the symlink farm is available
   via `MOEX_BENCH_DATA=symlink`.
2. **Fingerprint strengthens the plan's key** (adds `ctime_ns` and a content
   digest for files ≤ 2 MiB) to make the plan's own same-size same-mtime-tick
   acceptance test pass on coarse filesystems.
3. **`scripts/`, `config/`, `.github/`, `reports/` and root-level files never
   restart the service** even though they are not on the plan's literal
   non-restart list; they cannot affect the running daemon.
