## 1. Executive answer

### 1.1 Direct answer

**Could a compact neural model, in principle, add value on this data class? Yes. Is there any evidence that it does here? No. Can the project currently test the question? No — the prerequisites are missing.**

On the stipulated input — a free end-of-day MOEX futures panel of tens to a few hundred contracts with delisting-affected histories, few independent economic episodes, manual execution with a 3–90 minute response, integer contracts and RUB 30,000 all-in — the binding constraints are lawful point-in-time data, effective sample size, execution realism and selection risk. Model capacity and CPU speed are not the binding constraints.

The nine contributing reports differ in confidence, not in action:

| Framing | Reports | Position |
|---|---|---|
| Unknown, but testable behind gates | `ex`, `ar`, `cg`, `ds` | The question is open; no evidence of value; defer and bound the experiment. |
| Probably not | `gs` | No public evidence of net reproducible value; keep it an optional side experiment off the critical path. |
| Negative under current constraints | `ge` | Linear/deterministic models exhaust the information in daily EOD data; neural complexity is negative-value now. |
| Neutral-to-sceptical prior | `mm` | Optional late-stage experiment with strict early-stop criteria. |

**Consensus recommendation.** Keep neural modelling as an optional, late, falsifiable challenger. Do not place it on the critical path. Proceed only after (i) lawful, reproducible point-in-time data, (ii) a cost-aware label and a RUB 30,000 integer-contract portfolio simulator, (iii) a completed non-neural ladder under identical splits and costs, and (iv) an episode/power audit showing that a meaningful uplift could be detected. Then test **at most one small CPU-trainable candidate** on a locked holdout. If it does not beat the best non-neural model **and** the matched-LQDT counterfactual net of costs, delay and finite capital, discard it and keep the simpler system.

### 1.2 The five binding findings

**1. Data rights may block the project before any model choice matters.** MOEX's ISS page states that information obtained from ISS is "available only for familiarization" and cannot be used "to extract profit" without a contract with the exchange [E1]. A MOEX presentation classifies automated processing and use in automatic trading systems as "non-display" use requiring an information agreement, while separately listing "individual use: viewing, storage, accumulation, processing (for personal purposes)" [E2]. Whether private signal generation on delayed or archive data is permitted is unresolved, and a new edition of the governing rules took effect on 2026-10-15 [E4]. This constrains every model, not only neural ones, and it is the first gate.

**2. Statistical power, not model capacity, is the binding limit.** A RUB 30,000 account trading selective medium-term spreads with integer contracts might produce tens of independent trades per year. Distinguishing a neural filter from a well-tuned tree filter requires a paired difference in per-trade results; under plausible effect sizes that needs hundreds to thousands of independent episodes (§8.3). A delisting-affected daily panel is unlikely to supply them.

**3. The published evidence points the wrong way for this data class.** Shallow networks beat deeper ones in finance, attributed by Gu, Kelly and Xiu to "the relatively small amount of data and tiny signal-to-noise ratio" [E26]. In an S&P 500 statistical-arbitrage study the deep network earned 0.33%/day before costs against 0.43%/day for random forests, and returns deteriorated after 2001 [E27]. Tree models remained state of the art on medium-sized tabular data (~10K samples) across 45 datasets [E28]. One-layer linear forecasters beat Transformer models on nine long-horizon benchmarks [E29]. None of these studies tests MOEX spreads.

**4. The hardware rules out GPU training and makes the neural stack awkward.** Apple documents the PyTorch Metal (MPS) backend as requiring "Mac computer with Apple silicon" [E61]. PyTorch stopped producing macOS x86_64 binaries after 2.2 [E60]. ONNX Runtime 1.31.0 ships only macOS 14+ ARM64 wheels [E59]. The baseline stack (scikit-learn 1.9.1) still installs cleanly on x86_64 [E60]; the neural stack does not. The Radeon Pro 5300M is not a CUDA device and is absent from AMD's supported ROCm matrix [E63].

**5. Inference speed is irrelevant; delay to execution is not.** A small model scores in seconds on CPU, immaterial against a 3–90 minute manual reaction. What matters is how far the price moves between the decision snapshot and the fill. That cost is common to every model, so it shrinks any edge rather than favouring the neural one.

### 1.3 Recommended decision

1. **Gate 0 — rights and data.** Obtain a written MOEX or broker answer on automated personal research and signal generation; audit coverage, timestamps, delistings, contract economics and fees. Stop if this fails.
2. **Gate 1 — label and simulator.** Freeze one economically defensible universe, one horizon, one cost-aware label, and an integer-contract, finite-capital, matched-LQDT simulator. Verify it reproduces zero excess for no-trade.
3. **Gate 2 — non-neural ladder.** Run no-trade, a fixed deterministic rule, a regularized linear model and one restrained tree model under chronological purged walk-forward with a frozen trial log. Stop if none beats the counterfactual net of costs.
4. **Gate 3 — power.** Count independent episodes and actual trades; compute the detectable paired effect. If the minimum economically meaningful uplift cannot be distinguished from noise, record the experiment as underpowered and stop.
5. **Gate 4 — one neural challenger.** A single pooled, shallow MLP on the same features as the tree model; optional single causal 1-D CNN only under a pre-registered temporal hypothesis. Fixed capacity, fixed seeds, bounded trial budget, logged.
6. **Gate 5 — locked holdout.** Open once. Report net RUB versus matched LQDT, drawdown, tail loss, fills and uncertainty. Tuning after the reveal consumes the holdout.

If any gate fails, the answer to R15 is "no demonstrated added value", and the deterministic/linear/tree system stands.

### 1.4 What would change the answer

- A **lawful, complete, point-in-time free panel** with reliable daily open interest, contemporaneous timestamps and delisted contracts retained.
- A **verified execution path** whose fills can be reconstructed or measured, rather than assumed from OHLC bars.
- **Substantially more independent episodes** than the stipulated data class plausibly contains — for example a much longer history, or a broader universe of genuinely distinct underlyings.
- A **new economically motivated feature set** (reliable open-interest dynamics, carry/roll structure, a stable cross-sectional signal) that raises the prior for nonlinearity, rather than a new architecture.
- A **neural candidate that wins the controlled comparison** on the locked holdout, across seeds, environments and cost scenarios, without concentration in one episode.

None of these is a matter of adding parameters, GPUs or search iterations.

## 3. The decision a model must support

### 3.1 Three decisions, not a price forecast

A model is useful here only if it improves one of three decisions so that net RUB excess over the matched LQDT counterfactual rises:

1. **Gate** — take this eligible spread signal or not.
2. **Size** — usually 0 or 1 spread unit, given integer contracts and RUB 30,000.
3. **Exit** — hold to the planned horizon, or exit early.

Predicting a spread level is not the objective. A sign classifier is a useful diagnostic but a weak decision rule: a predicted positive sign can be smaller than round-trip costs, or too uncertain to compensate for delayed execution and margin risk.

### 3.2 Meta-model framing

The strongest formulation across the reports is that any neural candidate should compete as a **meta-model on top of the fixed deterministic baseline**: it scores or filters the baseline's signals and does not invent a separate strategy. This keeps the candidate set identical across models, caps the search space, and makes the incremental contribution measurable. Under this framing the tree model — not the linear model — is the primary competitor.

Three consequences follow:

- Every model sees the same candidate times, universe eligibility, contract mapping, capital, position caps, delay distribution, fill treatment and funding rules.
- The virtual portfolio attempts every eligible signal and records what would have happened to the rest, including stale, rejected, unfilled, partially filled and infeasible signals. It must not selectively omit awkward signals.
- A model that merely reproduces the baseline's decisions is a loss, because it adds maintenance without adding value.

### 3.3 The prediction unit

A **prediction unit** must be fixed before any model comparison:

- a pre-specified, economically defensible spread, or a small controlled candidate set of them;
- hedge ratio, eligible contract months, roll/expiry treatment, entry/exit logic and risk unit frozen in advance;
- no large family of candidate pairs created after inspecting results.

A spread is not necessarily market-neutral just because it has two legs. Basis, contract multiplier, maturity mismatch, liquidity, margin and leg-execution risk must all be described.

The label must refer to **actual named contracts** and their contract-specific economics — settlement and variation-margin accounting, expiry and roll rules — not to a retrospectively back-adjusted continuous series. A spread package may require unequal integer legs; specify and freeze that mapping before fitting. Termination at the horizon, an intervening mandatory close or expiry, and any stop or de-risking rule must be identical for every candidate model.

This is also where the universe is frozen: selecting "economically defensible" spreads after seeing which ones worked is universe-selection leakage, and it is one of the most common ways a small panel produces a fake edge.

## 4. Objective, labels and decision-time information

### 4.1 Horizon

The reports proposed different horizons: 1–5 trading days (`ge`, `mm`), 3–10 days (`gr`), 1–10 days (`ds`), five sessions as a primary research horizon (`ar`). The merged position:

- **One pre-registered medium-term horizon** is the primary research horizon. Five trading sessions is a reasonable default proposal and is explicitly **not a discovered optimum**.
- Other horizons are separate, pre-registered experiments, never a sweep from which the best is reported. A short set such as 5 and 10 sessions may be used as a sensitivity set only if every member is counted in the multiplicity budget.
- The effective label horizon must equal the **baseline's own exit rule** where the candidate is a filter, so that the label describes the trade the filter would actually gate.
- Shorter horizons give more observations but increase sensitivity to overnight gaps and execution slippage. Longer horizons reduce sample size further and blur attribution.
- Labels overlap whenever positions are held for multiple days, so purging must cover the maximum label/holding interval plus signal and exit dependencies.

### 4.2 Target and label construction

**Primary outcome.** The forward gross realized spread P&L of one integer contract package over the fixed horizon, computed on the actual named contracts, net of the cost scenario, minus the matched LQDT return on the capital actually tied up. Variants in the reports are equivalent representations:

- a continuous **net RUB** label (the primary form);
- a **volatility-standardized** label, y_t = (S_{t+h} − S_t) / (σ̂_{S,t}·√h), where σ̂_{S,t} is an exponentially weighted standard deviation of daily spread changes using data up to t and frozen at that as-of value;
- a **binary** label (net P&L > 0);
- a **three-way** label from triple-barrier logic: profit-taking barrier, stop-loss barrier, time-out horizon, labelled by the first barrier hit.

The triple-barrier construction is attractive because the barriers can be set as a function of volatility so that a "success" already exceeds round-trip costs. It does not remove the need to simulate fills at executable prices, and with sparse episodes the three-way label can be hard to estimate.

**Spread construction.** For a pair A, B, S_t = P_t^(A) − β_t·P_t^(B), with β_t estimated by rolling OLS or a Kalman filter so that the hedge ratio tracks structural shifts. This is a modelling choice to be frozen before comparison, not a free parameter to tune across models.

**Normalization and contract economics.** If contract economics differ materially, fit a training-only normalized target and convert predictions to RUB using multipliers, tick values and integer-position constraints. Never normalize using full-sample statistics.

**Label is a training aid; the acceptance metric is portfolio-level.** A positive label or a better forecast error does not establish economic value. The portfolio simulator, not the label, decides.

### 4.3 Decision-time information and timestamps

**Rule.** Features may use only information demonstrably published and available by a fixed decision timestamp. Each field carries two timestamps: its **source/publication time** and its **availability time**. A value eventually shown as belonging to date t is not automatically information available when an alert could have been acted on.

What is available at the decision snapshot:

| Input | Status | Consequence |
|---|---|---|
| Prior completed OHLCV bars | Available after the session; final values only after publication | The day-t bar cannot be used before its final values are available |
| Settlement prices | MOEX publishes futures settlement prices daily; free data is available with a 15-minute delay [E7] | A feature built on the day's settlement price is usable at the earliest about 15 minutes after publication, during the evening session |
| Open interest | FUTOI is described as free with a 15-minute delay and ten years of history [E8], but a retrieval guide for the intraday product says data is available only after subscribing [E8] — **[Conflict]**, see §22.1 | Treat daily OI as optional/missing until the exact field, source, history and rights are verified. Model absence as missing, not zero. Without reliable OI, a large part of the economically meaningful spread signal — carry, inventory and roll pressure — is missing, which weakens the case for any complex model |
| Contract specifications, roll dates, delisting | Only as-of versions | Never use a later contract list; never use final-history adjusted prices that encode later rolls |
| Cross-sectional state | Ranks and z-scores computed from the t-cross-section only | Never rank only surviving contracts, and never use forward-window statistics |
| Macro or factor proxies | Only if release timing cannot leak the label period | Otherwise exclude |

**Workflow.** The end-to-end sequence is: ingest end-of-day settlement, volume and open interest at the close → compute features from statistics fitted only on prior data → infer a forecast → wait out the 3–90 minute human reaction → place the order through the VTB or BCS interface, subject to available liquidity and slippage.

**Execution timestamp chain.** The simulation must timestamp signal creation, notification, the realistic 3–90 minute human response, first feasible order attempt, fill / partial fill / rejection / stale outcome, and any subsequent management. If the source timestamp falls after the relevant contract's trading window, execution moves to the next feasible session. Do not infer an ideal closing-price fill from a post-close decision.

**Hard limitation.** OHLC bars alone do not establish executable intraday fills. With end-of-day data only, execution realism is capped no matter which model is used. The conservative convention is to fill at an adverse price — for example the worse of the next-session open and a stress-slippage-adjusted settlement — and to record trades as stale, rejected or unfilled under explicit rules.

This limitation is also the most likely reason to change the project rather than the model: if daily OHLCV cannot represent the delayed entry and fill process, the correct response is to redesign the rule as a next-session strategy that daily data can honestly simulate, or to obtain better data — not to simulate fills that never existed.

### 4.4 From forecast to position

A frozen **policy layer** converts any model's output into an order/no-order decision:

1. Compute expected net benefit after parameterized costs and the matched LQDT opportunity cost.
2. Require it to exceed a pre-declared cost and uncertainty buffer.
3. Require that integer sizing, initial margin, variation-margin reserve, finite capital, position caps, human intervention quota and the funding rules all pass.
4. Otherwise abstain; zero-trade is a valid output.

In notation, a symmetric activation hurdle δ maps a standardized forecast ŷ_t to a position w_t ∈ {−1, 0, 1}: +1 if ŷ_t > δ, −1 if ŷ_t < −δ, otherwise 0. The important property is not the formula but that δ is fitted or chosen on training data only and then frozen.

The same policy layer, thresholds and capital rules apply to every model. A model is not allowed a more permissive threshold, and no model may train on future realized costs.

### 4.5 Cost model

A per-trade cost specification consistent across the reports:

```
c_t = 2·(f_exchange + f_broker) + ½·Spread_t + Slippage_t
```

plus exchange and clearing charges, spread crossing, roll/expiry costs where applicable, and any explicitly modelled leg or partial-fill effect.

| Scenario | Exchange fee | Broker commission | Spread / slippage | Purpose |
|---|---|---|---|---|
| **Base** | Documented exchange/clearing fee | Broker tariff — **[Unverified]** | Historical median spread if available | Central case |
| **Conservative** | Same | Higher tariff | Wider spread + slippage | Downside |
| **Stress** | Same | Higher tariff + financing | Wide spread + delayed fill | Capital survival |

Evidence and cautions:

- MOEX's derivatives tariff page lists exchange and clearing transaction fees and notes an asymmetric maker/taker arrangement [E11]. One report cites a RUB 1.25 exchange fee per contract as an example [E11]; that is a component, not the total.
- Actual broker commissions, client tariff category, margin eligibility and contract-level fees are **[Unverified]** for this account.
- The exchange fee alone is small relative to RUB 30,000, but broker commissions, spread and slippage can dominate when contracts are small and turnover is frequent. A model that trades more must overcome a higher cost burden, not merely improve accuracy.
- Never assign zero because a fee was not found. Parameterize missing amounts, and stop if conservative values erase the result.
- Present-day rates must not be substituted for historical trades, and exchange fees are not broker commissions.

## 5. The matched LQDT counterfactual and portfolio accounting

### 5.1 Definition

The primary outcome is **net RUB excess over the matched LQDT counterfactual**, with identical true external flows:

```
X_T = V^pilot_T − V^counterfactual_T
```

where both account values include charges, variation margin and mark-to-market, and the counterfactual keeps every ruble diverted to the pilot invested in LQDT. The counterfactual is the return the same money would have earned had the pilot never existed — not a risk-free rate, and not a zero.

### 5.2 Wealth path

With C_alloc the pilot allocation and M_{t−1} the margin committed at the previous step:

```
V^pilot_t = V^pilot_(t−1) × [1 + (M_(t−1)/C_alloc)·R_futures,t−1 + (1 − M_(t−1)/C_alloc)·R_LQDT,t−1]
```

```
V^counter_t = V^counter_(t−1) × (1 + R_LQDT,t−1)
```

This is an accounting identity with attribution assumptions. M_t must be measured or explicitly simulated, never assumed; unallocated cash is assumed to earn the LQDT rate, which itself requires a defensible LQDT return series.

### 5.3 Double counting and collateral

- Margin posted for MOEX futures may use eligible retained LQDT shares, subject to broker collateral discount haircuts. The continuing yield on retained collateral is credited to the account and appears in the account/counterfactual comparison once.
- It must not be **deducted a second time** as an opportunity-cost penalty. Several contributing reports restate this as a hard accounting rule because it silently doubles the hurdle.
- Where collateral eligibility, haircut or the amount actually diverted is unverified, represent alternatives as scenarios rather than pretending the accounting is settled.
- Exclude only the loss of the LQDT long-term holding deduction, per the user's instruction. Other taxes, tax residence and account treatment remain unknown and belong in a scenario or unknown list, not in a point estimate.
- Core collateral is not test capital. Any unapproved broker use of it is an incident, not an invisible capital increase.

### 5.4 From risk rules to simulator constraints

The pilot's governance is a **fixed simulation constraint set**, not a parameter for the model to optimize:

| Rule | Value | Simulation meaning |
|---|---|---|
| Starting allocation | RUB 30,000 all-in | Including margin, variation-margin liquidity and reserve; integer contracts only |
| Warning | RUB 5,000 excess-curve drawdown | Alert and diagnostic review of drift metrics |
| Action | RUB 10,000 drawdown from the excess high-water mark **or** RUB 10,000 cumulative LQDT shortfall | Suspend new entries; flatten existing exposures on signal termination |
| Outer boundary | RUB 15,000 cumulative shortfall | Maximum accepted underperformance |
| Review | 90 calendar days, no loss reset | Formal review point |
| Emergency funding | ≤ RUB 15,000 gross cumulative; ≤ RUB 45,000 total gross contributed | Explicit approval only; de-risking only; never entry, averaging down or loss reset; at the RUB 10,000 shortfall trigger, only to reach flat |

These are **unvalidated action defaults**, not mathematically guaranteed loss caps. A stop rule executed through a gap can lose more than its threshold, which is one reason the outer boundary is a tolerance rather than a guarantee.

### 5.5 Diagnostics that must accompany the primary metric

Cumulative and terminal net RUB excess; the full excess path; worst excess-curve drawdown; cumulative LQDT shortfall; time under water; tail loss; shortfall probability; number and concentration of trades; turnover and fees; gross P&L with each cost component shown separately; capital and margin utilization; variation-margin liquidity stress; unfilled / partial-fill / stale / rejected rates; holding-period and roll outcomes; and the paired incremental excess of the neural candidate versus the best non-neural model at identical decision times.

Prediction metrics — MAE, log-loss, rank correlation, direction hit rate, calibration — are diagnostics only. They can explain a result; they cannot substitute for it. A higher accuracy with no improvement in net RUB excess, drawdown and liquidity is not added value.

## 6. Baseline ladder

### 6.1 The ladder

Models are added in order. Each rung must pass its economic and statistical gate before the next is implemented under the same splits, costs, capital and execution rules.

| Rung | Model | Role | Minimum evidence to proceed |
|---|---|---|---|
| **B0** | **No trade** — 100% allocation to the matched LQDT counterfactual | Defines zero and the opportunity cost of action | The candidate must beat B0 net of costs |
| **B1** | **Fixed deterministic spread rule** — Gatev-style z-score or Bollinger thresholds on a pre-registered spread (e.g. enter at abs(Z) > 2.0, close at abs(Z) < 0.5), fixed carry rule, or a Kalman-filter spread; parameters frozen before evaluation | Tests the pre-existing economically motivated logic; it is also the strategy a neural filter would gate | If B1 cannot beat no-trade, the data or strategy premise is weak |
| **B2** | **Regularized linear model** — ridge / elastic net / logistic on a small pre-registered feature set (spread z-score, carry/roll yield, recent volatility, OI change, days to expiry, liquidity proxy) | Tests whether a stable, approximately additive signal exists | If linear fails out of sample, nonlinearity is unlikely to rescue it on small data |
| **B3** | **Restrained tree ensemble** — shallow LightGBM/CatBoost, XGBoost or random forest, strong regularization, monotonic constraints where defensible, fixed search budget | The strongest cheap competitor on tabular data | Any neural candidate must beat B3, not only B2 |
| **N\*** | **Neural challenger** — at most one pooled small MLP; optional single causal CNN only under a pre-registered hypothesis | Tests whether a compact network captures repeatable residual nonlinear interactions | Must beat **all** prior baselines under identical conditions, after costs, delay, integer sizing and stress |

### 6.2 Why the order matters

- The ladder is not a formality. If the deterministic rule cannot beat the counterfactual, there is no economic problem for a model to solve. If the linear model cannot, the marginal value of nonlinearity on a few hundred episodes is very unlikely to appear.
- The tree model is the decisive comparison. Public evidence repeatedly finds tree ensembles strong on medium-sized tabular data [E28], including a 2026 study on tabular financial crash prediction with limited samples in which tree ensembles significantly outperformed GRU, LSTM, Transformer and logistic regression, with deep models at AUC 0.72–0.81 versus above 0.82 for trees [E33].
- Comparing a neural model against a weaker baseline while giving it richer features is not a neural-value test. It is a feature-engineering test with an ambiguous label.
- Each variant — feature set, threshold, horizon, regularisation — is a trial and consumes the multiplicity budget (§10.5).

### 6.3 Training success is not investment evidence

Falling training loss, high in-sample accuracy, or a better validation score is not investment evidence. Two specific traps recur:

- **Class imbalance.** Predicting "no trade" most days yields high accuracy and zero excess return. This is why the ladder is evaluated on financial metrics — net P&L, excess, drawdown, turnover — rather than accuracy.
- **Benchmark illusion.** The M4 forecasting competition is a useful warning: of its 17 most accurate methods, 12 were combinations of mostly statistical approaches [E35]. Forecast-accuracy rankings do not transfer to after-cost trading results.

The acceptance question is not "does the model predict better?" but "does the model change net RUB excess versus LQDT, on the same trades, after costs and delay, without worsening risk?"

## 7. What the public evidence says

### 7.1 Tabular and small-sample evidence

The most directly relevant evidence class is medium-sized, noisy, non-stationary tabular data.

- **Grinsztajn, Oyallon and Varoquaux (2022)** benchmarked 45 datasets and found tree-based models remained state of the art on medium-sized data (around 10K samples), while explaining why deep learning's relative performance is not universal [E28]. The paper is not a finance result and explicitly excludes time series: "We remove stream-like datasets or time series." It therefore supports strong tree baselines; it does not settle a time-series or trading question.
- **A 2026 IEEE study** on tabular financial crash prediction with limited sample size found tree-based ensembles significantly outperformed GRU, LSTM, Transformer and logistic regression, with deep models ranging from AUC 0.72–0.81 versus tree models above 0.82 [E33].
- **A separate factor-versus-ML analysis**, as reported, concluded that factor models outperform random forests and neural networks when the sample is below 500–1,000 observations, that ML becomes competitive around 2,000 samples and dominant above 10,000 [E34]. The citation for this claim is incomplete in the source report and should be verified before being relied on; the direction is consistent with the other evidence.
- **Gu, Kelly and Xiu (2020)** report useful machine-learning results on a much richer panel — nearly 30,000 U.S. stocks over 1957–2016 — and find that shallow networks beat deeper ones, which they attribute to "the relatively small amount of data and tiny signal-to-noise ratio" [E26]. This is evidence that neural and tree methods can add predictive value in a large, long equity cross-section. It is not evidence about MOEX futures, a RUB 30,000 account or after-cost spread trading.
- **Krauss, Do and Huck (2017)** report a deep network earning 0.33%/day before costs against 0.43%/day for random forests in an S&P 500 statistical-arbitrage design, with returns deteriorating after 2001 as markets became more efficient [E27].

The synthesis these sources support is narrow and useful: on small, noisy tabular financial samples, tree ensembles and regularized linear models are hard to beat, and any neural claim must clear them. They do not prove that a neural model can never help.

### 7.2 Financial time-series evidence

- **Zeng et al. (AAAI 2023; arXiv v3 2022)** report that their one-layer linear models outperform "existing sophisticated Transformer-based LTSF" models on nine real-life long-horizon forecasting datasets [E29]. This supports demanding strong simple baselines. It does not imply linear models always win, and forecasting benchmarks are not traded P&L.
- **Bai, Kolter and Koltun (2018)** report generic convolutions outperforming canonical recurrent networks on sequence benchmarks [E30]. This is an architectural lead, not a financial result.
- **M4** found that most of its most accurate methods were combinations of mostly statistical approaches [E35].
- **Saly-Kaufmann, Wood, Peter-Calliess and Zohren (2026 preprint)** study 2010–2025 daily international futures across commodities, equity indices, bonds and FX and report selected recurrent/hybrid architectures outperforming linear baselines under a Sharpe-focused portfolio design, with VSN+LSTM highest overall [E31]. This is more domain-relevant than generic forecasting benchmarks, but it is a preprint, uses a broader and longer dataset, a different objective, capital and execution context, and states that code is available on request. It is not an independently replicated result and not evidence of MOEX transfer.
- **Guijarro-Ordonez, Pelger and Zanotti** report an annual Sharpe above four on the 550 largest and most liquid U.S. stocks from 1998 to 2016, with millions of stock-days [E32]. Different market, liquidity, data depth, cost structure and period; it says nothing about a RUB 30,000 MOEX spread account.

### 7.3 Evidence specific to spread trading

Several studies show neural models beating classical approaches in spread or arbitrage contexts:

- MLP regression versus ARMA/GARCH and MACD baselines for commodity futures spreads, with superior out-of-sample performance and evidence of nonlinear structure (Dunis and co-authors) [E38].
- Inter-commodity index-futures spread trading with back-propagation networks and genetic programming, where neural networks produced more profitable spread systems than genetic programming alone [E39].
- An LSTM with attention and additional feature decomposition reporting higher prediction accuracy for futures price-spread series than traditional methods [E40].
- CNN/LSTM architectures outperforming linear methods in structural-break-aware pairs trading with transaction costs included [E41].

These are **existence proofs**, and their conditions matter: mostly high-frequency data (minutes to seconds), deep liquid markets, and validation standards weaker than purged, embargoed walk-forward. None is a MOEX daily-spread result.

### 7.4 Counter-evidence

- A 2024 study on low-frequency trading finds that once realistic cost and volume constraints are imposed, neural-network improvements in half-spreads shrink to near zero net alpha [E42].
- Large benchmarks of financial deep-learning architectures, as reviewed in the contributing reports, find cases where shallower algorithms adapt better to financial time series than deep networks, especially when the sample per regime is small.
- Surveys of deep learning for tabular data, as reviewed in the contributing reports, note that it is high-maintenance and computationally expensive relative to tree models, often without commensurate gains.
- A 2023 survey for financial economists emphasizes that while ML expands the function class, data limitations and non-stationarity often make simpler methods more robust [E44]. A 2021 review likewise records logistic regression, random forest and gradient boosting as successful in futures-based statistical arbitrage, typically using spreads as inputs [E45].

### 7.5 MOEX-specific evidence

Direct evidence on MOEX futures-spread neural models is scarce and does not support transfer:

- Russian work has applied LSTM and other networks to MOEX futures **price** prediction (for example Si and Ri contracts) at high frequencies, and one study applies deep learning to SiM3 futures in an hourly-data trading system. These are price, not spread, studies and generally lack rigorous purged validation [E43].
- A Russian paper evaluates market-neutral strategies based on MOEX spot–futures spreads, focusing on basis dynamics and margin/liquidity issues rather than machine learning [E43].
- Broader studies of MOEX–CME derivative pairs find cointegration can persist across sub-samples, but with a changing speed of adjustment and variance [E43]. That supports **regime-dependent mean reversion**, which a nonlinear model could in principle exploit — it does not show that one does.

Net: there is no strong MOEX-daily-spread-specific evidence that neural models beat well-tuned linear/tree methods under strict validation. Every claim of neural superiority on spreads comes from another exchange, a higher frequency, or a more lenient validation standard.

### 7.6 Pretrained and foundation models: contamination and licences

A pretrained forecaster introduces a specific leakage channel that has no analogue in models trained from scratch: **indirect information leakage arising from temporal overlap between correlated training and test series that often share a common causal driver**. Meyer et al. require "strict global post-training test periods" after the latest pretraining timestamp [E21]. Hyndman, summarising work across 22 foundation models and 401 datasets, reports that "only 6% had never appeared in any model's pre-training or fine-tuning corpus" [E22].

The Chronos-2 paper lists its real-world pretraining sets (energy, transport, web, cloud and so on), says that for multivariate and covariate-informed tasks "we relied entirely on synthetic data", and states no explicit training-data cutoff date [E49]. The practical rule: **for any pretrained model, only a holdout that falls after the model's release date is clean.**

Licence status is equally decisive, because personal trading for profit is at least arguably commercial use:

| Model family | Size | Licence | Status for this project |
|---|---|---|---|
| Chronos-Bolt (tiny/mini/small) | 9M / 21M / 48M | Apache-2.0 [E48] | Permissive; optional ablation only |
| Chronos-2 | 120M; 28M "small" variant | Apache-2.0; CPU inference supported [E49] | Permissive; optional ablation only |
| TimesFM | — | Code Apache-2.0; weights Apache-2.0 up to v2.5; v3.0 "restricted to non-commercial, non-production use" [E51] | Exclude v3.0 weights from anything informing real trades |
| Moirai | — | CC-BY-NC-4.0, "for research purposes only" [E52] | Exclude |
| Timestral (Mistral AI) | 5.2M (8 layers, 192-dim) | Modified MIT [E47] | Permissive; optional |
| Kronos (NeoQuasar) | 4.1M / 24.7M / 102M | MIT; up to 512 bars [E50] | Permissive; optional |
| TinyTimeMixer (TTM) | <1M | Apache-2.0 [E46] | Permissive; CPU-oriented by design |
| TabPFN | — | Non-commercial; explicit prohibition of commercial/production use without a paid licence [E53] | Disqualified for a live trading system |
| TabICL v2 | — | Fully open source, commercially usable [E54] | Permissible; static-tabular benchmark only |
| NVIDIA Kumo Tabular Small | ~28M | OpenMDW-1.1 [E55] | Permissible but oversized for this sample |

Two further cautions. A declared licence on a model card is not proof that the weights' training data or upstream material is rights-cleared. And an open-source framework licence — PyTorch, ONNX Runtime, scikit-learn — does not license an arbitrary checkpoint or an exchange dataset.

### 7.7 What the evidence establishes

1. Machine learning can work in rich asset-pricing settings with long panels and many cross-sectional observations.
2. Tree ensembles are a strong, cheap baseline on medium-sized tabular data, including small financial samples.
3. Extensive strategy search creates selection risk that can manufacture apparently significant results.
4. Neural architectures have produced genuine improvements in spread trading in high-frequency, deep, liquid markets under validation standards weaker than this project's.
5. None of the above establishes transfer to free end-of-day MOEX futures spreads, a RUB 30,000 integer-contract account, a 3–90 minute manual delay and a matched-LQDT objective.

The correct reading is neither "neural always wins" nor "neural can never help". It is that the ladder must be fair, the baseline must be strong, and the prior for this data class is sceptical.

## 8. Data sufficiency and effective independent episodes

### 8.1 Rows are not information

A panel of 100 contracts over 1,250 sessions contains 125,000 rows, but far fewer independent learning episodes:

- **Term structure.** Calendar spreads on the same underlying share drivers; neighbouring contracts in a chain are nearly duplicate exposures.
- **Common drivers.** The rouble rate, key-rate decisions, sanctions and liquidity shocks move many contracts at once. One shock day is one episode, not one hundred.
- **Overlapping labels.** With a 20-session holding period, consecutive daily labels share about 95% of their window.
- **Shared legs.** Candidate spreads that share a contract are not independent wins; they must be scored inside the same portfolio simulation.
- **Delisting and survivorship.** Contracts that disappeared must remain in the panel up to their last trading date, or the training set is biased.
- **Roll regimes.** A calendar spread changes identity when the near leg rolls; outcomes across a roll are not comparable observations of the same object.
- **Regime scarcity.** Russian derivatives since 2013 contain only a handful of major structural shocks — the 2014 sanctions episode, COVID-19, and the 2022–23 regime shifts — and volatility persistence is strong.
- **Structural breaks not represented.** A test "only takes into account structural breaks as long as they are present in the dataset", and regimes absent from history are not tested [E16]. A model trained mostly in one regime and evaluated across a break measures luck about the break, not skill.

### 8.2 Illustrative episode arithmetic

**Planning calculation (assumptions, not measurements).** Five years ≈ 1,250 sessions; a median holding period of 20 sessions; K ≈ 15 economically distinct spread families. Non-overlapping windows per family ≈ 62. If the average correlation of outcomes across families is ρ ≈ 0.3, the effective number of independent families is

```
K_eff = K / (1 + (K − 1)·ρ) ≈ 15 / 5.2 ≈ 2.9
```

so the effective episode count is on the order of 62 × 2.9 ≈ 180 for all signals. The baseline trades only a fraction of these, and a RUB 30,000 account can hold perhaps one to three spreads at once (margin per contract unverified). The number of actually tradable independent decisions could therefore be **well below 100 over the whole history**.

A second estimate starts from 200 contracts × 500 days ≈ 100,000 rows and concludes that the effective episode count K × E — distinct spread families times independent macro/regime episodes per family — may be in the **low tens**, not thousands.

The purpose of these numbers is not precision. It is to show that the range of plausible effective sample sizes is one to two orders of magnitude below the row count, and that the honest planning range stretches from "low tens" to "a few hundred". A third report's scenario analysis treats "independent regimes counted on one hand" as a realistic case.

### 8.3 Power to detect a neural improvement

To demonstrate at 5% significance with 80% power that a mean per-trade result differs from zero, the normal approximation gives roughly

```
n ≈ 7.85·(σ/μ)²
```

independent observations. The number that matters is the **paired difference** between a neural filter and a tree filter on the same baseline signals. The two filters mostly agree, so the difference is small relative to its noise.

| Assumed paired effect (μ/σ of the per-trade difference) | Independent trades needed |
|---|---|
| 0.30 | ≈ 87 |
| 0.20 | ≈ 196 |
| 0.10 | ≈ 785 |
| 0.05 | ≈ 3,140 |

These are reasoned estimates from the normal approximation, not computed results. Autocorrelation and fat tails raise them further.

Even optimistic effects need more independent trades than this panel and capital level are likely to supply. The honest expected outcome of a neural test is **"not distinguishable"** — and that outcome must be pre-registered to mean **defer**, not "promising".

### 8.4 The data gate

Two formulations were offered:

- A planning heuristic: if the number of independent, non-overlapping label periods after purging is below about **1,000**, treat neural training as low priority and require an exceptionally strong economic prior. This threshold is explicitly a heuristic informed by the sample-size evidence, not a proven law.
- A more defensible formulation: **there is no universal minimum episode count** that can be specified without the variance of net outcomes and the smallest economically meaningful uplift. Before training, define that minimum valuable uplift in RUB and run a block-based power/sensitivity analysis using development data only. If the observed history cannot plausibly distinguish that uplift from noise, classify the experiment as **underpowered** and stop or extend the history — do not widen the architecture search to manufacture a result.

The second formulation governs. The first is a useful sanity check for planning.

Both formulations agree on the consequence: a large cross-sectional row count does not rescue an underpowered time series, and more architecture trials are not a substitute for independent episodes.

### 8.5 What would change the data verdict

A longer undelisted history, a broader universe of genuinely distinct underlyings, reliable free open-interest and carry/roll data, or a lawful higher-frequency series would all raise the effective sample. These are data changes, not modelling changes.

## 9. Leakage taxonomy

Leakage is best defined functionally: it occurs when training uses information that was not available at prediction time [E71]. In this project it is not one bug. It has at least nine distinct paths, each with a different control. A model that is clean on eight of them and contaminated on the ninth produces a backtest that cannot be reproduced live.

| # | Leakage path | Mechanism | Control |
|---|---|---|---|
| 1 | **Temporal / label overlap** | An h-day label opened at t shares h − 1 days of outcome path with the label at t + 1; ordinary k-fold splits train on the future | Purge every training label whose interval intersects the test interval; add an embargo after the test window |
| 2 | **Cross-instrument contemporaneous** | Training on contract A's day-t outcome while testing contract B on day t, with a shared driver | Split by global calendar date across the whole panel; never split by instrument; purge across all instruments together |
| 3 | **Cross-sectional normalization** | Z-scores, ranks, quantiles or PCA fitted on the full panel, including future dates or future universe membership | Fit scalers per fold on training data only; compute cross-sectional ranks within the cross-section at date t, using only instruments and values available then |
| 4 | **Embeddings / identifiers** | Contract, instrument or sector embeddings learned on full history; contract IDs that encode delisting or future liquidity | Learn embeddings inside each training fold; give new contracts a defined pooled cold-start; run an ablation without identifiers |
| 5 | **Universe selection / survivorship** | "Economically defensible" spreads chosen after seeing which worked; delisted contracts dropped | Freeze universe rules before the holdout; log every change; retain delisted contracts to their last trading date; select pairs on information then known |
| 6 | **Roll / continuous series** | A back-adjusted series uses future roll gaps and erases contract economics | Build spreads from the actual tradeable contracts on each date with roll dates known in advance; keep P&L and labels on tradable contracts |
| 7 | **Future-fitted transformations** | Imputation, winsorization thresholds, feature selection, target normalization, probability calibration or hyperparameters fitted on the whole sample | Fit all of them inside the training fold; early stopping on an inner validation slice that is itself purged |
| 8 | **Pretrained-model contamination** | A foundation model's corpus overlaps the test period or correlated series | Treat any pretrained model as possibly contaminated; evaluate only on data after its release date (§7.6) |
| 9 | **Execution / label leakage** | Filling at the signal close or bar midpoint, or at a price observed before the action could occur | Use the first executable price after the true availability time plus the action delay; record stale, rejected, unfilled and partial outcomes |

Three additional controls cut across the table:

- **The same date belongs to one side of the split for every instrument.** Otherwise a single market shock leaks across the panel in the same way a single stock leaks across a random row split.
- **Group by information set, not by convenience.** Where instruments are grouped, group by underlying plus expiry bucket so that no economically linked group appears simultaneously in training and validation.
- **Leakage must be demonstrated, not asserted.** An ablation that deliberately scales on the full sample, next to the properly folded version, quantifies how much leakage would have inflated the result. If the gap is large, the protocol is doing real work and should be audited again after any change.

## 10. Validation design

### 10.1 Walk-forward skeleton

- Chronological, expanding or rolling folds, with a final untouched holdout. Standard k-fold cross-validation is invalid because serial correlation and overlapping multi-day labels leak between folds.
- The refit schedule must mimic the intended refit cadence, so that the simulated model at each point uses only information a real process would have had.
- A concrete example: train on two years, test on the next six months, roll forward, train on the expanded window, test the following six months, and continue. The exact block lengths are a design choice, not a result.
- Every model — baseline, linear, tree, neural — runs through the same folds, the same candidate times, the same costs, the same capital and the same execution assumptions. No model gets a longer lookback or a more favourable window.

### 10.2 Purging and embargo

- **Purge.** Remove any training observation whose label interval [t_j0, t_j1] intersects the test window [t_test,start, t_test,end]. In formal terms, remove j when t_j,0 ≤ t_test,end and t_j,1 ≥ t_test,start.
- **Embargo.** After the test window ends, exclude training samples commencing within the embargo window M. M should be at least the maximum holding period plus the execution delay, plus an allowance for settlement and roll effects. One report sets M equal to the maximum autocorrelation lag or the holding horizon h; another requires the full relevant maximum label/position interval plus an empirically justified dependence buffer. The stricter of the two governs.
- **Do not shorten the buffer to retain rows.** One report proposes an extra 1–5 days at the train/test boundary as a minimum; that is a floor, not a substitute for sizing by the holding interval. A generic time-split gap does not correctly handle unequal holding times or panel-linked labels. scikit-learn's `TimeSeriesSplit` is time-ordered and exposes a `gap` parameter, but its default gap is zero and its ordinary gap does not automatically purge heterogeneous trade-label intervals or panel-linked rows [E20].
- Purging removes a large share of the training data on a short panel. That is a cost of honesty, not a defect of the method.

### 10.3 Fit discipline

Labels, transforms, feature selection, winsorization, imputation, hyperparameters, thresholds, calibration and the decision policy are all fitted inside the training fold. No setting may change after the holdout is seen. If one does, the holdout is spent and must be declared so.

### 10.4 CPCV, PBO and the Deflated Sharpe Ratio

- **Combinatorial purged cross-validation (CPCV)** generates multiple training/testing paths from the same history. It is mathematically attractive but has a specific failure here: with a short MOEX history and scarce independent episodes it produces **many paths from the same few episodes**, giving a false sense of robustness. It is also compute-heavy; one implementation study illustrates a 21-day purge/embargo setting, which is a worked example rather than a project recommendation [E25]. Use it for diagnosis and sensitivity on final candidates, not for broad hyperparameter sweeps, and never as a substitute for a final untouched chronological holdout.
- **Probability of Backtest Overfitting (PBO)** is the probability that an in-sample-optimal strategy underperforms the mean out-of-sample, estimated with combinatorially symmetric cross-validation (CSCV) [E16]. The authors warn against "applying CSCV to guide the search for an optimal strategy. That would constitute a gross misuse." Symmetric combinatorial partitions can also train on later periods, which does not represent real-time learning. PBO is therefore a **secondary diagnostic of the selection process**, not the primary test.
- **Deflated Sharpe Ratio (DSR)** corrects "selection bias under multiple testing and non-normally distributed returns" and adjusts for the number of independent trials, the dispersion of Sharpe ratios across trials, sample length, skewness and kurtosis [E17]. It is an optional warning diagnostic, not a licence to claim significance: on this data class both the independent-trial count and the stationarity assumption are doubtful.
- **Harvey, Liu and Zhu** argue that a new return factor should clear a t-statistic greater than 3.0 after accounting for the factor zoo [E18]. This is a warning about data mining in cross-sectional asset pricing, not a universal pass/fail threshold for one portfolio's time-series RUB P&L. The relevant actions are complete trial disclosure, paired chronological out-of-sample tests, dependence-aware uncertainty, and a decision hurdle tied to the user's tolerated LQDT shortfall.

### 10.5 Multiple trials and the trial budget

The number of trials is "the most important piece of information missing from virtually all backtests"; without controlling for it, a backtest "is worthless, regardless of how excellent the reported performance might be" [E17]. The DSR adjusts for it, but only if the count is honest. Two related warnings frame the problem: with many predictors and modest samples, substantial "predictive" correlations arise by chance [E36]; and spurious claims come in two kinds — false discoveries from mining many predictors, and false conclusions from abusing backtests [E37].

**Illustrative effect, using the expected-maximum-Sharpe formula with zero true skill** (γ ≈ 0.5772):

```
E[max SR] ≈ σ_SR × [(1 − γ)·Φ⁻¹(1 − 1/N) + γ·Φ⁻¹(1 − 1/(N·e))]
```

| Trials N | Expected best Sharpe under no skill (units of σ_SR) | With ~3 years of data (σ_SR ≈ 0.58 annualised) |
|---|---|---|
| 10 | ≈ 1.6 | ≈ 0.9 |
| 100 | ≈ 2.5 | ≈ 1.5 |
| 1,000 | ≈ 3.3 | ≈ 1.9 |

Hand calculation, not tool-computed; precision is approximate. A modest search of 5 architectures × 20 hyperparameter settings × 3 feature sets = 300 trials can produce an annualised Sharpe near 1.7 from noise alone over three years. That is the bar an honest comparison must clear.

**Log every trial.** For each: ID, timestamp, code and data hash, architecture, hyperparameters, feature set, horizon, cost threshold, fold results, seed, whether the holdout was seen, any peek at it, and the reason for stopping. Failed and abandoned runs count. Unlogged trials invalidate the deflation and the overfitting estimate.

**Budget.** Pre-register a maximum trial count — a common proposal is at most **30 configurations** for the neural family, including architecture variants — and stop when it is exhausted regardless of results. Do not expand ablations in response to a disappointing holdout. Every added architecture, horizon, feature subset, seed-selection rule or threshold is a trial and consumes the budget.

A complementary safeguard is a **falsification audit**: generate synthetic spreads that match the marginal distribution and volatility of the real spreads but contain no predictability (block bootstrap, or ARMA/GARCH simulations), then run the entire pipeline — model selection, cross-validation, hyperparameter tuning — on them. If the pipeline still "discovers" alpha, the protocol is not conservative enough, and any real-data gain is likely spurious.

### 10.6 The final holdout

- Reserve the **last 12–18 months** of the panel (one report proposes 18–24 months) as a frozen holdout before any neural work starts.
- Open it once, after all selection is frozen: model, features, thresholds, cost assumptions, code, data snapshot and reporting rules.
- If the holdout informs another design decision, it is consumed. A new future period is then required; the same data cannot be "unseen" again.
- A final holdout on a few hundred episodes is not powerful. It constrains, but does not eliminate, selection bias.

### 10.7 Uncertainty reporting

- Compare **paired** daily or per-trade portfolio excess differences across chronological folds and regimes.
- Use **block or episode-level resampling** — a date-block or event-block bootstrap that resamples all linked instruments within a block together — with a block length justified by label overlap and observed dependence. Do not bootstrap individual panel rows or report IID standard errors on overlapping trades.
- Report intervals, the number of episodes, the number of trades, and concentration by date, underlying and instrument family.
- Calibration plots and coverage are meaningful only if fitted out of fold. With sparse episodes, state "not estimable" rather than claiming calibrated probabilities.
- The result must survive conservative costs, realistic reaction delays, reasonable data perturbations and regime-by-regime inspection — not merely the base case. Where the universe admits new contracts or new underlyings, evaluate a new-contract/underlying holdout separately rather than relying on pooled performance.

### 10.8 *Advances in Financial Machine Learning*: what it contributes, and its limits

**Reading status — important.** The contributing reports differ materially in what they read of López de Prado, *Advances in Financial Machine Learning* (Wiley, 2018; ISBN 978-1-119-48208-6):

| Report | Recorded reading |
|---|---|
| `gs` | Only the public opening of Chapter 7 (sections 7.1 Motivation, 7.2 The Goal of Cross-Validation, and the title of "Purged K-Fold CV"), O'Reilly edition |
| `ex` | Only the table of contents; cites §7.4.1 "Purging the Training Set" p. 105, §7.4.2 "Embargo" p. 107, §12.2 "The Walk-Forward Method" p. 161, §14.7.3 "The Deflated Sharpe Ratio" p. 204 as **reading leads**, not as evidence read |
| `cg`, `ar` | Located the publisher's table of contents; did not read chapters; make no section claims |
| `ds` | Cites Chapter 7 and Chapter 12 at chapter level |
| `gr` | Attributes specific guidance to Chapters 2, 7, 17–19 and 20–22 without recording a reading of those chapters |

The merged document therefore treats **chapter-level attributions from `gr` as [Unverified]**: plausible, consistent with the book's known contents, but not established by any report that records reading them. The page references above are reading leads for a later targeted pass. No claim in this report depends on a specific sentence of AFML.

**What is directly applicable**

- **Purged and embargoed cross-validation (Chapter 7).** The core warning — standard CV leaks under overlapping labels, and tuning hyperparameters through it causes overfitting — is exactly this case. The public Chapter 7 opening states: "CV is yet another instance where standard ML techniques fail when applied to financial problems... CV will contribute to overfitting through hyper-parameter tuning" [E19]. This is the one AFML element the project should adopt without reservation.
- **Sample weighting by label uniqueness.** Down-weighting observations whose label windows overlap reduces the effective duplication of the same outcome path. It complements, but does not replace, purging.
- **Fractional differentiation.** Preserves memory while achieving stationarity, as an alternative to plain returns. Useful as a feature-construction option; it does not create information.
- **Triple-barrier labelling.** A volatility-scaled profit barrier, stop barrier and time-out, labelled by the first touch. Applicable to daily bars, with the caveat that barriers must be set net of costs and that path-dependent labels need the same execution treatment as trades.

**What does not transfer**

- **Information-driven bars (attributed to Chapter 2).** Volume, tick or dollar-imbalance bars require tick or order-book feeds. Synthesizing them from daily settlement aggregates is not feasible. The project must operate on time-sampled daily bars and mitigate non-normality through robust scaling and non-parametric rank transforms.
- **High-performance cluster computing (attributed to Chapters 20–22).** Distributed computing, multiprocessing vectorization and large parameter grids assume institutional compute. On a single laptop or a 1 vCPU VPS they create resource contention and increase path-dependent overfitting risk. Lightweight models over simple walk-forward splits are structurally superior at this capital scale.
- **Microstructure features (attributed to Chapters 17–19).** Order-book and high-frequency microstructure variables are inaccessible in an EOD panel. The transferable part is **structural-break detection** — for example CUSUM on spread levels — adapted to daily data, to suspend mean-reverting signals when a cointegrating relationship breaks down.

**What AFML does not solve here**

- It assumes enough events to purge, embargo and combine folds. On a few hundred effective episodes, purging removes a large share of training data and combinatorial paths are highly correlated; expect wide uncertainty even with careful technique.
- It does not address execution realism from daily bars, MOEX data rights, or the matched LQDT counterfactual. Those must be built separately.
- It does not make a small final holdout powerful or eliminate structural breaks.

## 11. Candidate model families

### 11.1 Selection principle

A neural model is justified only if it can use structure the tree model cannot: smooth shared patterns across many similar spreads, or sequence patterns too long or too complex for hand-made features. Given the episode counts in §8, that case is weak and must be argued, not assumed.

The order of parsimony is therefore fixed: a shallow MLP on the same features as the tree model first; a small causal temporal convolution only if a specific temporal hypothesis is pre-registered; pretrained forecasters only as a feature ablation; recurrent and attention architectures not at all in this phase.

### 11.2 N1 — shallow MLP (the primary neural candidate)

- **Form.** One to three fully connected layers, 10K–100K parameters in one estimate, ≤10K in another; small width; strong weight decay and dropout; early stopping on inner purged validation; fixed small feature count (≤20 economically motivated features).
- **Inputs.** Exactly the tabular lagged features used by B2/B3: spread z-score, carry/roll yield, recent volatility, volume or OI change, days to expiry, liquidity proxy, and known contract state. This is what makes the comparison a test of nonlinearity rather than a test of feature engineering.
- **Parameterisation.** Share parameters across instrument opportunities; do not train a separate model per contract. A pooled model can borrow strength across similar spreads and does not spend parameters on contract identity.
- **Capacity rule.** Parameter count should be far below the number of effective episodes.
- **Why it is first.** It is the cleanest like-for-like test of "does nonlinearity via a network add anything over trees?" and the least complicated challenger to the linear and tree models.
- **Verdict.** The only candidate worth a first test.

### 11.3 N2 — linear sequence model (DLinear / NLinear)

Zeng et al. found one-layer linear models beat Transformer forecasters on nine long-horizon benchmarks [E29]. A DLinear/NLinear-style model on spread history is close to a linear AR model. It belongs inside the B2 baseline family, not in the "neural value" column; if it wins, the finding is that a linear model wins.

### 11.4 N3 — pretrained forecaster as a feature generator (optional ablation)

- **Form.** Zero-shot use of Chronos-Bolt-small (48M) or Chronos-2 small/base, or TimesFM 2.5, producing forecast ranges that enter the tree model as a volatility or drift feature. No training of the foundation model.
- **Why it might help.** It supplies a distributional view of the near future without fitting parameters to a small panel.
- **Why it probably will not.** Contamination (§7.6); Chronos-2's listed pretraining corpus contains no finance-specific set; CPU/x86 packaging friction; no evidence of edge over a plain rolling-volatility feature.
- **Verdict.** Optional ablation only: "does adding its forecast-range feature to B3 change net RUB?" Evaluated only on data after the model's release date, with the Apache licence and revision hash recorded.

### 11.5 N4 — recurrent or convolutional sequence models

- **Small GRU/LSTM.** One layer, small hidden size, only if there is a genuine sequential structure that linear/tree models cannot capture — rarely justified on daily EOD data with scarce episodes. It must beat both the lagged-feature MLP and the tree ensemble; otherwise reject. Most reports defer it outright.
- **Tabular entity-embedding model.** A small network with learned contract or contract-family embeddings could handle heterogeneity across the panel, but embeddings are both a leakage and an overfitting risk. If tested at all: fit them per training window, use only decision-time-known metadata, and ablate with and without them. There is no evidence that this is needed here.
- **Small causal 1-D temporal CNN.** A conditional second architecture: only if a pre-registered hypothesis says short local time patterns across synchronized spread/contract features matter beyond compact rolling statistics and the MLP. Keep it shallow and causal; inputs must end at t. It adds masking, padding, receptive-field, export and testing complexity. If the episode audit is weak, skip it.
- **Why defer by default.** Many parameters relative to a few hundred independent episodes; unstable and slow on CPU; a large search space that inflates the trial count.

### 11.6 Tiny pretrained forecasters: what the reports found

The model landscape surveyed across the reports, with sizes as stated in their model cards:

| Model | Size / architecture | Claimed property | Caution |

| **Timestral (Mistral AI)** | Timestral-5M: 5.2M parameters, 8 layers, 192-dim | Patch-based transformer; quantile forecasts; past lags and numeric/categorical covariates; CPU or GPU; modified MIT [E47] | A 5M-parameter model still has far more parameters than the panel has episodes |

### 11.7 Tabular foundation models

| Model | Status | Verdict |
|---|---|---|
| **TabPFN** | Strong accuracy but slower inference (order seconds per 1,000 instances) and quadratic scaling with features/instances; releases 2.5–3.5 licensed for non-commercial use only, explicitly prohibiting commercial or production use without a paid licence [E53] | Disqualified for a live trading system by licence and by fit |
| **TabICL v2** | Fully open source and commercially usable [E54] | Permissible; occasional offline benchmark only |
| **NVIDIA Kumo Tabular Small** | ~28M parameters, OpenMDW-1.1, runs on a single CPU core in tens of seconds for small datasets [E55] | Permissible but parameter count excessive for this dataset |

Tabular foundation models are better treated as occasional offline benchmarks for static tabular problems than as the engine for a daily panel strategy.

### 11.8 Other CPU-friendly designs worth knowing

- **NeuralProphet** is CPU-only by design, with built-in seasonality and trend components that are more interpretable than a generic LSTM [E56].
- **N-BEATS** is an MLP-based residual architecture for univariate series; trimmed variants can be small [E57].
- Lightweight neural networks for financial time series have been demonstrated with roughly **2.5K parameters** running comfortably on CPU, and CPU-only time-series inference with latencies on the order of **140 ms per forecast** on commodity hardware has been reported in the source material; neither figure was independently measured here.
- These illustrate the same point: sequence modelling does not require recurrence or attention, and shallow MLP-style sequence encoders are viable under compute limits. They do not change the statistical constraint.

### 11.9 Compute profiles asserted for architecture candidates

One report tabulated expected resource use. These are **estimates by that report, not measurements**:

| Family | Parameters | Training overhead (Intel i7) | Production footprint | VPS latency (1 vCPU) | Operational suitability |
|---|---|---|---|---|---|
| MLP | 10K–100K | < 2 min/fold | ~45 MB RAM (QInt8) | < 1 ms | High: compact, fast, lower overfitting risk |
| TabNet | 100K–500K | ~15 min/fold | ~110 MB RAM (FP32) | ~8 ms | Moderate: capacity risk on small panels |
| Temporal Fusion Transformer | 500K–2M | > 1.5 h/fold | ~280 MB RAM — exceeds budget | ~45 ms | Low: heavy, overfits short series |
| 1D CNN–LSTM hybrid | 50K–200K | ~8 min/fold | ~70 MB RAM (QInt8) | ~5 ms | Moderate: feature extraction with added complexity |

The pattern is robust even if the numbers are not: the MLP is the only family that is comfortably within every stated resource envelope. One report draws the stronger conclusion that LightGBM or a regularized linear model represents the upper bound of useful complexity for this project. A second report's estimates are broadly similar: deterministic rules below 1 ms with negligible memory; linear or elastic-net models below 5 ms and under 20 MB; LightGBM or CatBoost below 50 ms and roughly 50–100 MB; a small MLP or 1D-CNN below 100 ms but 100–500 MB RAM, with slow and unstable CPU training.

| Multi-GPU training, tick/intraday processing | Excluded | Hardware unavailable; data class is EOD |

## 12. Model, code and artefact licences

Licensing is three separate questions, and conflating them is a common error:

1. **Framework licence.** PyTorch (BSD-style), scikit-learn (BSD-3-Clause), ONNX Runtime (Apache-2.0), XGBoost (Apache-2.0) are permissive. They license the software, not the model or the data.
2. **Model / weight licence.** Each checkpoint carries its own terms. Apache-2.0 and MIT are usable; CC-BY-NC-4.0 (Moirai) and the TabPFN licence are not, because personal trading for profit is at least arguably commercial use. TimesFM weights are Apache-2.0 only up to version 2.5; 3.0 is restricted to non-commercial, non-production use.
3. **Data licence.** MOEX data rights are governed separately (§14) and are not granted by any model or software licence.

Practical rules:

- Use only fully open-source code and permissively licensed weights if a model could inform real trades.
- Save the licence text, model revision/commit hash and model-card metadata next to each artefact.
- A model-card "license" field is not proof that the weights' training data or upstream material is rights-cleared.
- Do not assume that downloading a model grants rights to use it commercially, or that a data subscription grants rights to redistribute derived features.
- No gated-model, authentication or licence bypass, and no paid-resource assumption.

| ROCm | AMD's compatibility matrix does not list Radeon Pro 5300M or macOS; Radeon 5000-series mobile GPUs are unsupported [E63] | Do not rely on the GPU for training or inference |

**Consequences.** All research and inference should be planned **CPU-first**. The GPU is at most an opt-in, measured compatibility experiment, never a prerequisite. Do not install an unsupported stack just to make the experiment happen.

**Training cost is not one fit.** A 1–2-layer MLP on ≤10⁵ rows × ~20 features trains in seconds to minutes per fit on six CPU cores — a reasoned estimate, not a measurement. The real cost is folds × trials × seeds: for example 10 × 100 × 5 = 5,000 fits, plus the logging and review burden. That is the operational argument for a small trial budget, independent of the statistical one.

**Pretrained-model inference.** Chronos-2 is 120M parameters; its 28M "small" variant is described as suitable for CPU-only settings. 120M fp32 weights are roughly 0.5 GB before runtime overhead — fine overnight on 16 GB, but to be measured, not assumed.

### 13.2 The VPS

VPS (project-supplied, unverified): 1 vCPU, 1 GB RAM + 2 GB swap, 20 GB disk, an active VPN and other workload, and a shared 250–350 MB background budget.

- **No neural inference belongs on this VPS.** A PyTorch runtime plus even a 48M-parameter model is likely to exceed the shared budget; importing `torch` alone has been estimated at 800 MB–1.5 GB of process memory, which is infeasible there. Swapping would risk starving the VPN and the other workload.
- If anything model-related ever runs there, it should be a **tiny exported linear or tree scoring function**, or simply a precomputed signal file produced on the Mac after the session closes.
- Any future test must measure peak resident memory, cold-start and warm latency, disk footprint and failure behaviour under the **actual** shared workload — not in isolation.
- The 250–350 MB budget is unverified. A sub-second model does not establish a 3–90 minute human-fill response or VPS fitness.
- No production probing or deployment is authorized now.

### 13.3 Packaging and export

A plausible build-to-execution pipeline, all of it proposed rather than performed:

1. Train and tune on the local Mac CPU.
2. Freeze the artefact; export the computation graph to ONNX.
3. Optionally apply dynamic 8-bit integer quantization (QInt8), which one report estimates reduces file size by up to 75% and accelerates single-thread CPU execution without material accuracy loss on tabular models.
4. Execute with the lightweight ONNX Runtime, preferably the C++ engine, on the target CPU.

Reported footprint estimates — **not measurements** — are 40–150 MB RAM for tabular networks and single-digit millisecond latency; another report cites a vendor claim of 2–10× CPU inference speed-up versus baseline frameworks. ONNX Runtime documentation does confirm CPU packages for Windows/Linux/macOS x64, a default CPU execution provider, fallback to CPU for unsupported nodes, and a CPU memory-arena control (`enable_cpu_mem_arena`) relevant to tight RAM budgets [E58]; that is **portability evidence, not performance evidence**. Its thread-management documentation notes that the CPU provider defaults to physical-core threading, which is a reason to cap and test concurrency on a 1 vCPU box.

Export is not automatically safe. After any export or library update:

- compare packaged outputs against the reference implementation on frozen inputs, within pre-declared tolerances;
- check finite values, NaNs, overflow and threshold-adjacent decisions;
- test missing, stale, corrupt and out-of-range inputs;
- define a timeout and a fail-closed path to baseline or no-trade;
- record package/runtime versions, seeds, precision and checksums.

## 14. Data rights and prerequisites

### 14.1 The question

May a private individual lawfully obtain, retain, process and generate trade signals from MOEX futures data, and on what terms? This is unresolved and it gates every model, not just neural ones.

**Practical consequence.** "Free end-of-day daily panel" is a **research hypothesis**, not a settled input. The exact source, fields, historical completeness, release timestamps, permitted non-display use and redistribution terms must be checked. A displayed sample or endpoint does not imply rights to archive or automate the data.

### 14.3 Minimum request

Obtain a written MOEX answer — for example through the feedback form named on the data-policy page — or the broker's terms if data arrive through VTB or BCS terminals, stating whether **automated personal research and signal generation on delayed or archive ISS data requires an information agreement**. Until then, the rights question is open.

### 14.4 Point-in-time panel prerequisites

The ISS query reference exposes interface families for instrument descriptions, candles and history, but not coverage or rights [E10]. Before any label can be built, the panel needs:

- historical contract identifiers, board/session/date, listings and delistings;
- settlement versus close, and the exact availability time of each;
- EOD OHLCV and **actually published** open interest, with release and revision timing;
- contract multipliers, tick values, roll and expiry calendars;
- the trading-session and holiday schedule by instrument and date;
- missingness, suspensions and duplicate or revised observations;
- dated exchange and broker fees, and bid/ask or defensible spread bounds;
- margin history and broker collateral / variation-margin treatment;
- separately, admissible LQDT prices and flows.

Pairs must be selected on information known at the time, not on survivors known today. The historical instrument universe and contract definitions used in every fold must be persisted, including expired contracts.

### 14.5 Market structure facts relevant to execution

- **Settlement publication.** Daily, free with a 15-minute delay [E7]. This sets the earliest feasible decision time for a settlement-based feature.
- **Trading hours.** From 14 July 2026, weekday derivatives trading is stated as 06:50–23:50 Moscow time [E12]. An earlier FX-futures contract example lists main 10:00–18:50 and evening 19:05–23:50 MSK [E13]. Hours vary by instrument and date; "24/7 monitoring" is not 24/7 execution. Holidays, weekend sessions and individual contract eligibility must be checked against the current calendar.
- **Tariff effective dates.** The derivatives tariff index consulted states a current edition effective 08.09.2026 and an underlying list effective 29.09.2026 [E11]. Present-day rates must not be substituted for historical trades.
- **Fees.** Exchange and clearing components, with asymmetric maker/taker treatment [E11]. The RUB 1.25 exchange-fee example is a component only.
- **Historical data product.** A specification describes "OHLC prices, volumes … open interests" but does not establish a free full archive [E14]. Calendar-spread and contract-specification pages define products and parameters, not data rights [E15].

### 14.6 Privacy and redistribution

- **Use rights.** The ISS restriction and the non-display classification apply to any systematic signal generation, including the simple baselines.
- **Redistribution.** Uploading the MOEX panel, or a derived dataset, to Kaggle, Hugging Face, Colab or any third party could count as passing data to third parties. Keep raw and derived data local; do not publish Spaces or datasets.
- **Account privacy.** Never put broker statements, positions, LQDT balances, account identifiers, signal history or the trained artefact into public notebooks, Spaces or hosted inference. Even private cloud needs a separate contractual and privacy review; the no-cloud route avoids that dependency.
- **Model artefacts.** Save the licence text and revision hash next to each artefact.
- **No gated or paid workarounds.** No login-bypass tools, paid data or paid compute are assumed.

## 15. Reproducibility and artifact governance

A result that cannot be re-run on the same inputs is not evidence. The minimum governance set:

### 15.1 The trial manifest

For every run, record:

- data snapshot hash, source and retrieval date;
- universe eligibility rules and the historical instrument universe used;
- feature list with **as-of** definitions and availability timestamps;
- label definition and horizon;
- split boundaries, purge and embargo sizes;
- every fitted transform (imputation, scaling, winsorization, feature selection, target normalization, calibration);
- architecture, parameter count and optimizer;
- early-stopping rule and the inner validation slice;
- random seed and seed-retry policy;
- library, runtime, OS and CPU versions;
- compute device and thread configuration;
- cost scenario, decision policy and order assumptions;
- result and the reason the run was stopped.

Save **all** trials, not only the winner. An unlogged trial invalidates the deflation arithmetic and the overfitting estimate.

### 15.2 Pinning and hashing

- Pin exact package versions in a lock file. On this Mac that means either a conda-forge environment or a pinned torch 2.2.x; record which, because the two are not equivalent.
- Hash data snapshots and record download dates. MOEX may revise data, and the governing rules themselves change; the 2026-10-15 edition is the ninth listed period [E4].
- Pin pretrained model revisions by commit hash. A Hugging Face "main" branch can change under the same model name.
- Keep a frozen source/data manifest with observed vintages and rights, raw hashes, point-in-time universe and pair mapping, feature/label schema and cutoffs, the complete split and embargo specification, dated fees, a deterministic portfolio simulator and an immutable decision/attempt ledger.
- Write a short model card: intended use, limitations, training dataset, training parameters and evaluation results [E67].

### 15.3 Seeds and numerical stability

- Fix random seeds and report results across **at least five seeds**. A neural result that holds for one seed only fails.
- Deterministic flags alone do not guarantee bit-identical results. PyTorch's documentation states that "Completely reproducible results are not guaranteed across PyTorch releases … or different platforms", and that results may differ between CPU and GPU even with identical seeds; deterministic operations can also be slower [E24].
- CPU float32 results may differ across BLAS libraries and versions. Re-run the frozen model in two environments or two versions and require identical **decisions** on the holdout — count decision flips, not just score differences.
- Use float32 CPU as the reference; compare exported outputs within frozen tolerances; reject decision changes under tolerated numerical variation.
- Treat NaN, infinite values, stale data, unknown contract, non-positive risk scale, file/version mismatch, timeout, memory pressure or invalid output as **no signal / fail to baseline / no trade** — never as permission to improvise.

### 15.4 Offline replay

The final artefact must be re-runnable offline on identical inputs, on CPU, with pinned preprocessing and calibration, and must reproduce the recorded decisions and portfolio results. This is the operating gate before any later paper or live discussion.

## 16. Calibration, uncertainty, drift, fallback and maintenance

### 16.1 Calibration

Because the decision is a threshold on expected net value, **calibration matters more than ranking**.

- Report reliability curves and Brier scores per fold.
- Use fold-internal calibration — isotonic or Platt — fitted on training data only.
- For quantile outputs (Chronos-family, Timestral), check coverage: a 90% interval should cover about 90% of held-out outcomes.
- Gneiting, Balabdaoui and Raftery recommend "maximizing … sharpness … subject to calibration" [E23]. A calibrated forecast can still be uneconomic; calibration is necessary, not sufficient.
- A poorly calibrated model trades too much or too little against costs. One report's operational verdict is concrete: a miscalibrated neural probability that triggers false-positive trades can consume the RUB 5,000 warning threshold through fees, slippage and opportunity cost before any genuine edge appears.
- Public evidence on calibration in small financial samples is mixed, as reported: some Bayesian deep-learning approaches claim better calibration, while others find calibration accuracy "not particularly convincing" in small samples. Evaluate explicitly; do not assume.
- With sparse episodes, the honest output is "not estimable". A neural probability is not a confidence guarantee.

### 16.2 Uncertainty

- Conformal prediction offers distribution-free intervals and has been applied to portfolio selection and to market-making uncertainty bands. It can sit on top of any point-forecasting model, linear or neural.
- Distribution calibration is an alternative for regression outputs.
- The decision rule should require **both** positive expected excess and a sufficiently tight interval (or a high calibrated probability); otherwise default to LQDT.
- Estimate uncertainty over time blocks, respecting dependence; never from row-wise independent errors.

### 16.3 Drift

Monitoring must cover input distributions, missingness, out-of-range values, specification changes, calibration, outcome residuals, execution slippage and actual-versus-simulated fills.

Two standard diagnostics were proposed for feature and output stability:

- **Kolmogorov–Smirnov two-sample statistic.** D = sup_x |F_1,n(x) − F_2,m(x)|; a p-value below 0.05 rejects the null of identical distributions.
- **Population Stability Index.** PSI = Σ_b (P_b − Q_b)·ln(P_b/Q_b), where P_b is the training-period share in bin b and Q_b the rolling evaluation share. Operating tiers: **< 0.10 stable**; **0.10–0.25 moderate drift** — warn and increase auditing; **≥ 0.25 severe** — suspend new entries and revert position logic to the deterministic baseline.

One report additionally sets a discard rule when the PSI of **model output probabilities** exceeds 0.25 across two consecutive rolling 15-day windows.

Concept drift is acute in Russian markets, where sanctions and policy shocks have altered microstructure and volatility regimes. Drift thresholds and monitoring operations are later gates, because the project is not deploying now.

### 16.4 Fallback and fail-closed behaviour

The fallback must be deterministic and fail closed:

- A failed model load, version or checksum mismatch, non-finite output, missing expected feature, failed calibration or drift check, timeout or memory pressure means **no neural-generated new exposure**.
- Use the already-tested baseline only if it remains independently eligible under the same risk gates; otherwise do not trade.
- The neural layer must never override the RUB-based risk triggers (RUB 5,000 / 10,000 / 15,000 and the 90-day review), the emergency-funding rules or the capital rules.
- Pre-register the fallback rule: if the neural filter's rolling paired excess versus the tree model falls below zero over N signals, or input drift exceeds the set level, switch to the tree or deterministic baseline automatically. Lower model complexity; never raise exposure.
- No automatic retraining from live outcomes.

### 16.5 Maintenance burden

The neural arm must demonstrate an incremental economic gain large enough to compensate for:

- environment fragility on Intel macOS;
- a retraining schedule and seed management;
- calibration and drift monitoring;
- pretrained-model licence and revision tracking;
- explaining decisions during manual execution and emergency de-risking;
- a larger trial log and audit surface;
- alert triage, manual intervention quota and emergency availability.

The model should be treated as a replaceable component: keep the training scripts, feature pipeline and portfolio simulator modular, so that discarding the neural branch does not require rebuilding the rest of the system.

Two quantitative anchors from the reports: if the neural branch adds more than **1–2 person-days per month** without a clear net RUB benefit, it is not justified; and **a neural model that matches the tree model's net result is a loss**, because it adds maintenance without adding value.

Monitoring coverage is not emergency-response coverage. Human availability, trade quota and escalation responsibilities remain undefined and must be specified before any future live gate.

## 19. Falsification and early-discard criteria

The neural added-value claim is **falsified for this project** if any of the following holds.

### 19.1 Data, rights and execution

1. **No lawful point-in-time data.** The daily panel or contract history cannot be lawfully obtained or retained, or the terms do not permit the intended use, without assuming payment or accepting terms inconsistent with the project.
2. **Missing timestamps or contract economics.** Essential availability timestamps, contract specifications, roll/settlement rules or fee parameters cannot be reconstructed.
3. **Unrealisable fills.** Daily OHLCV cannot reconstruct a credible entry/exit and lawful, sufficiently complete intraday or executable-price history cannot be obtained. Either redesign as a next-session strategy that daily data can honestly simulate, or stop. Do not fake intraday fills.

### 19.2 Sample and baseline

4. **Too few independent episodes.** The pre-defined economically meaningful uplift cannot be distinguished from noise, even if row counts look large.
5. **No economic signal in the baselines.** No-trade, the deterministic rule, the linear model or the tree model already matches or beats the neural portfolio excess after the same costs and constraints. There is nothing to filter.
6. **Neural fails to beat the tree ensemble** on the primary metric in purged walk-forward, even before the final holdout. Beating only the linear model is insufficient.

### 19.3 Economics and robustness

7. **The improvement disappears after costs and delay.** A statistically significant accuracy gain that does not survive integer contracts, fees, spread, slippage and the 3–90 minute delay is not economically useful.
8. **It exists only in the base case** or only under one seed, one instrument, one year, one regime or one selected horizon; or it reverses under plausible stress costs or delay.
9. **Concentration.** Nearly all gains come from a single episode. A pragmatic robustness flag, not a universal law: treat any result where one contiguous event or block supplies more than half of the total uplift as concentrated and not yet reproducible.
10. **Worse risk than the comparator.** Higher excess drawdown, tail loss, margin-liquidity stress, cumulative shortfall or operational burden than the pre-declared tolerance permits.
11. **The result is smaller than the pilot's noise level**, or the extra maintenance cannot be justified within the 90-day review horizon.

### 19.4 Statistics and selection

12. **Deflated Sharpe is not significant** after logging all trials, or the number of trials is so large that deflation cannot distinguish skill from search.
13. **PBO of the neural selection process is above 0.5**, or the trial count is unknown or unlogged.
14. **The apparent advantage depends on future-fitted preprocessing**, survivor-only universe, post-hoc continuous-series adjustment, test-set calibration, a favourable fill convention, unverified fees/margin, discretionary omission or emergency funding at entry.
15. **Model selection has already influenced the "untouched" holdout.** The holdout is spent; a new future period is needed.

### 19.5 Operations

16. **Calibration is poor**, or uncertainty intervals are too wide to support any position size within the risk rules; or holdout calibration error makes the trade count differ materially from the training-period rate.
17. **Predictions are unstable** across seeds or environments, decisions flip under library/version changes, or drift makes uncertainty unusable.
18. **Failure is not safe.** A failed model cannot reliably fail closed to baseline or no-trade.
19. **Resource footprint exceeds the measured budget** — for example more than 250 MB RSS on the execution VPS, or inference that cannot be run within the operational envelope.
20. **Maintenance burden is disproportionate.** The neural pipeline adds material operational complexity and monitoring risk without a clear, repeatable net RUB advantage.

### 19.6 What would strengthen the claim

The claim is **strengthened, not proven**, only if one pre-declared tiny model produces a positive **paired** net-RUB excess over **each** required baseline, under conservative costs and realistic delays, across multiple independent chronological episodes, stable across the fixed seeds and ablations, with uncertainty narrow enough to exceed a minimum economically meaningful RUB hurdle chosen **before** the holdout, and with no reliance on emergency funding or unverified accounting.

Even then, the correct next step is extended paper monitoring, not deployment or scale-up.

## 20. Scenario analysis: when would a neural model be justified?

The answer is conditional. Three states of the world were analysed; only one admits a neural candidate, and even there it is optional.

### Scenario A — Data-rich, high-dispersion spreads (neural optional)

**Conditions**

- Several spread pairs display persistent, regime-conditional nonlinearities that deterministic, linear and tree models fail to capture, evidenced by sizeable and consistent residual patterns rather than a single good backtest.
- The effective sample after purge and embargo is at least in the low thousands of independent trades across regimes.
- Deterministic and tree models are near breakeven net of conservative costs — small positive alpha, but below the desired buffer.

**Action**

- Introduce a single, very small, CPU-friendly architecture: a 1–3 layer MLP with ≤10K parameters, or an equivalently tiny mixer.
- Restrict the search to a hand-tuned grid of architectures, regularization strengths and learning rates. No large neural architecture search, no hyperparameter sweeps.
- Evaluate only inside the fixed walk-forward skeleton; run synthetic falsification audits.
- If deployed at all, use a **tiny-weight ensemble** in which neural predictions can tilt but not override the baseline signal.

### Scenario B — Data-poor, highly non-stationary panel (neural discouraged)

**Conditions**

- Most spreads have short, irregular histories due to listing changes and liquidity; effective independent regimes are counted on one hand.
- Regime-shift evidence is strong: volatility persistence, parameter instability, changing speed of adjustment.
- Deterministic and tree models are already fragile; net of conservative costs they oscillate around zero or negative excess.

**Action**

- Treat this as a **capacity-limited environment**. Non-linear models will likely increase variance more than they reduce bias, worsening selection risk.
- Focus on refined deterministic baselines conditioned on basis, open interest and calendar structure; robust tree ensembles with strong regularization and minimal features; cost modelling, execution constraints, and better selection of which spreads to touch at all.
- Neural experiments may be run as academic exercises only, behind strict walls that keep them out of real trade decisions.

### Scenario C — Deterministic and tree baselines robustly beat LQDT

**Conditions**

- After full validation, one or more simple baselines deliver stable positive net excess versus LQDT within the RUB 10,000–15,000 tolerance window, over backtests and a held-out period.
- Performance is not highly sensitive to small hyperparameter changes or regime boundaries.

**Action**

- There is **no compelling economic reason to introduce neural complexity now**.
- At most, consider limited experiments as a hedge against future capacity scaling, if the universe, frequency or capital later grows. Keep them out of pilot capital allocation entirely.

### The missing ingredient

A genuinely new, economically motivated feature set — reliable free open-interest dynamics, carry/roll data, or a stable cross-sectional signal — would raise the prior for a nonlinear model. Without such a feature, the neural branch is a solution looking for a problem.

## 21. Project changes and deferrals

### 21.1 Change now

1. **Make the rights and data audit (Stage 0) a hard gate for every modelling investigation, not just R15.** Data rights apply to every model, not only neural ones.
2. **Amend "free daily panel"** from a settled input to a testable source-and-rights condition.

8. **Obtain the exact LQDT benchmark ledger and flow convention**, plus futures contract, fee, margin and settlement specifications, before even a credible simulator is built.

### 21.2 Keep unchanged

- All comparator, cost, risk, capital and funding scenarios.
- The matched-LQDT accounting convention, including identical external flows, single counting of retained-collateral LQDT return, and exclusion of only the long-term holding deduction.
- The rule that a model may not alter these assumptions to improve its score.
- Entry must pass with zero emergency funding; emergency money is de-risking-only, never entry capital.
- Funding cannot repair selection risk. Additional money does not make an invalid comparison valid, and a result that requires emergency funding at entry is a failed result by construction.

### 21.3 Defer

- Neural architecture choice beyond the single-MLP default.
- Cloud resources and any hosted experimentation beyond synthetic/public data.
- The production stack, VPS deployment, notifications and automation.
- Paper and live trading, broker/API permissions and account eligibility.
- Tax, legal and KPUR conclusions. For Russian brokers the broker withholds NDFL on futures, but the interaction with the LQDT holding, account treatment and KPUR status requires separate verification.

### 21.4 If a gate fails

- Reduce the universe to fewer, defensible, sufficiently liquid spreads.
- Narrow the target to a strategy with clear economics and observable fills.
- Obtain longer or different legitimate data.
- Change the decision schedule so it matches actual data availability — for example a next-session strategy rather than immediate manual execution.
- Or keep the deterministic/linear/tree system and omit neural methods.

More architectures, GPUs and parameter sweeps are not valid substitutes for independent episodes or real execution evidence.

**Statistical.** The true number of independent economic episodes; whether any neural model produces a stable, calibrated signal on this data class — **this is the open question the staged experiment is designed to answer, not a result claimed here**.
