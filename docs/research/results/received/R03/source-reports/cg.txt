# R03 — BCS Trade API: возможности и ограничения автоматизации

Предварительный вывод по официальной документации, проверенной 21 октября 2026 года

BCS Trade API документирован как интерфейс для автоматической торговли, который поддерживает Московскую биржу, включая фьючерсы. В нём предусмотрены HTTP-запросы для торговых операций и WebSocket для потоковых рыночных данных и состояния портфеля. Это не просто API для чтения котировок: БКС прямо документирует создание рыночных и лимитных заявок с торговым токеном.&#x20;

Но возможность выставлять заявки ещё не доказывает, что интерфейс подходит для безопасной торговли среднесрочными фьючерсными спредами. Ключевые нерешённые вопросы — доступ конкретного счёта, поддержка требуемых инструментов и типов заявок, восстановление состояния после сбоев, достаточность данных и отсутствие атомарного исполнения спреда.

## Важное уточнение: на бирже уже существуют нативные календарные спреды

На самой Московской бирже календарный спред — самостоятельный торговый инструмент, позволяющий одновременно купить один фьючерс и продать другой с тем же базовым активом, но другим сроком экспирации. Биржа документирует синтетическое сопоставление заявок спреда с заявками из стаканов обоих фьючерсов и указывает для спредовых заявок типы `limit`, `market` и `FOK`.&#x20;

Не обязательно эмулировать спред двумя независимыми заявками: возможно, БКС предоставляет доступ к биржевому инструменту календарного спреда через обычный интерфейс заявок. Но публичная документация сама по себе пока не подтверждает, что конкретные спредовые тикеры доступны через BCS Trade API и принимаются его торговым сервисом. Для этого нужно отдельно проверить справочник инструментов и получить подтверждение БКС.&#x20;

## Полный отчёт

Скачать отчёт R03 в Markdown

В отчёте разобраны:

- Доступ и экономика: тарифы, квалификация и категории риска, права счёта, авторизация и ротация токенов.
- API и данные: справочник фьючерсов, котировки, стакан, свечи, история сделок, портфель, ГО и вариационная маржа, лимиты HTTP/WebSocket.
- Исполнение: типы заявок, `timeInForce`, идентификаторы, частичные исполнения, отмена и замена заявок, восстановление состояния.
- Отказоустойчивость: таймаут после принятия заявки, дубликаты, пропуск событий, истёкший токен, устаревшее ГО, ручное вмешательство и принудительное закрытие брокером.
- Практический план: предварительная проверка только на чтение, вопросы поддержке БКС и минимальные границы будущего адаптера.

У каждого существенного вывода есть ссылка на официальный источник и подтверждающий фрагмент. Также отдельно перечислены проверки, которые предложены, но не выполнены.

### Главный нерешённый вопрос

MOEX поддерживает нативные календарные спреды, но пока нет достаточного подтверждения, что БКС разрешает создавать и сопровождать такие заявки через BCS Trade API для конкретного счёта. Именно это стоит выяснить у поддержки прежде, чем проектировать исполнение стратегии.

Текущий статус: можно продолжать исследование и проектирование в режиме чтения; допуск реальной торговли не подтверждён.
