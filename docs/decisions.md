## Product direction (confirmed 2026-11-08, revised 2026-11-18/20)

The user prioritizes a private research screener over a signal-first workflow: select a futures pair, strategy and parameters, inspect the strategy and matched-LQDT wealth curves and return/risk measures, and search parameters for a chosen pair or basket of pairs. The saved `СКРИНЕР_epub.md` is a detailed product hypothesis, not evidence of an existing product or validated trading rules.

The proof workbench supersedes the S2 pair table at `/`: library-based auto-tuning per selected strategy, per-field plateau lamps and a fresh proof on every search. It does **not** override A-03's single shared-capital virtual portfolio, the research/live boundary, or any trading authority. Key product boundaries: a table-first interface (each row a pair with source context, trade count, annualized performance versus LQDT and percentage risk, never absolute RUB metrics; one strategy and its parameters apply to all pairs; row checkboxes select pairs for automatic search of a stable parameter plateau); honest later-period validation rather than a best historical curve; a zero-trade or inconclusive result is valid. The original brief remains the source record; current priorities are in Stages 4–8.

**All UI/parameter controls are research-hypothesis changes only.** They never alter A-02/A-04, the pilot's fixed RUB 5k buffers / 10k risk trigger / 15k shortfall boundary, emergency-money rules, broker authority, or any claim about executable returns. Current settings, scores and diagnostic limits are in [`packages/proof/docs/execution-proof.md`](../packages/proof/docs/execution-proof.md); product direction is tracked in the [Issue #12](https://github.com/vernikr/moex-spread-lab/issues/12) workstream.

## Implementation decisions (2026-11-26 – 2026-11-28)

- **Remote workspace ownership (#362).** Workstation bridge and isolated benchmark tooling live in `packages/remote`, depend on `core`, and retain the `moex_spread_lab.remote` import path. The root application retains the CLI composition and namespace initializer.

- **Completed ISS history has no age-based expiry (#332).** The user replaced #284's conservative 24-hour limit: a closed range captured after its Moscow end date is reusable without a time limit, subject to page and pagination validation. Open ranges, unknown or future capture times remain ineligible. Historical corrections are possible, so reconciliation is explicit, not automatic; raw-body retention is unchanged.

- **Retired W1–W7 research pipeline and sealed W7 validation (#190).** Stage-9 accounting is costs, VTB account risk, causal sizing and the portfolio overlay; `import moex_spread_lab.accounting` no longer loads research/validation/replay/ledger/Parquet code. No change to proof/screener validation shares, costs, capital controls or trading authority.
- **Retired S2 compatibility surface / maximum-reduction policy (#243).** The S2 API (`/api/run|screen|optimize|catalog|runs|searches`, `proof.screener_search`, `proof.web_legacy`, `moex_spread_lab.screener_search`) and the `research`/`validation` root shims were deleted. Standing policy: delete unused code/routes/shims instead of preserving them, with behavioural tests (incl. negative) and a register entry. Retained: `strategies.pair_screener`, `/api/proof/*`, settings/timeframes/dev routes.
- **Calendar dead-code removal / no fabricated margin rows (#232).** Removed unreachable `proof_runner` branches and the fabricated zero-margin cross-expiry/synthetic-triangle rows emitted by `catalog_builder`; missing safety-critical margin data must never become zero cost. Proof/accounting/capital contracts unchanged.
- **Pair-strategy consolidation (#234).** Consolidated the P7.2 mean-reversion and pair-screener shards into their owning modules; `screen_pairs` retired in favor of the proof workbench; pair input caches use bounded LRU `HashedJSONCache`; `signal_day` follows positive-volume rows. No pricing/accounting/strategy rules changed.
- **Retired S3 reference loader & dead strategy-registry exports (#231).** Deleted the obsolete S3 reference loader, its CLI/manifest entries and root shim; `StrategyRegistry.for_universe/items` removed (`.as_dict` kept); `strategies/signals.py` simplified without changing strategy math, fills, levels or `run_id` parity. Negative tests verify the retired pieces stay absent.
- **Retired server-instance discovery record and dead CLI aliases (#210).** The loopback server no longer writes/removes `data/analytics/server-instance.json`; unreferenced CLI aliases deleted. Retained `/api/proof/*`, settings/timeframes/dev routes, `strategies.pair_screener`.
- **Retired `funding_screen` / consolidated `funding_carry` engine (#233).** Deleted the unreferenced `funding_carry.funding_screen` one-off; collapsed the P7.2 carry-strategy shards into `engine.py`; fixed `parameters.exit_conditions` to interpolate `warmup_observations`. Retained `HashedJSONCache` LQDT caching and `build_carry_strategy`/`replay_carry_intents` parity.
- **Single-pass architecture DAG suite (#203).** `test_architecture_dag.py` parses each file once into a shared `(source, AST)` cache; cycle detection reports DFS paths; every owned function at cognitive complexity ≤15, so the five Ruff `PLR0912` per-file ignores were retired. No production/layer/gate change.
- **Strategies CLI cut & deduplicated pair loaders (#237).** Deleted the pre-Stage-9 study/screen subcommands and `cli_parsers.py`; `strategies/cli.py` registers only `calendar-study` and `screener-run`. `analytical-baseline.v1` contract unchanged (produced by the scheduler baseline); pair data math moved to shared `strategies/pair_data.py`. `packages/strategies` now has zero `complexipy > 15`.
- **Lake dead-surface retirement & typing-ceremony removal (#245).** Deleted `ParquetBarStore.read_bars`, `RawResponseArchive.pin` and the `BarStore` protocol; collapsed self-referential/typing-ceremony classes to concrete types; `catalog_path` gone. No payload/CLI/import-path change; `packages/data` ≈ −28% tokens.
- **Retired W1–W7 pair audit and proof runtime alias (#219).** Removed the 12-pair offline audit, `audit-pairs` CLI, root audit shim and `proof_runtime` alias; the manifest no longer advertises `offline_pair_audit`; negative import tests keep them absent. Active proof/cohort/accounting contracts unchanged.

Warm path ≈30×.
- **Proof worker/window shard consolidation (#222).** Deleted the single-caller `pool_reports` facade and `worker_window` shard; collapsed the duplicated window-summary loop; replaced module-passing ceremony with direct imports. No public entrypoint change; proof/cohort/accounting behaviour and the canonical replay pipeline unchanged.
