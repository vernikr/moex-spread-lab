**Status:** Published. S0 acceptance artifact for [plan.md](plan.md) §4 (S0) and §2 (measurement contract). Companion implementation: `scripts/verify_record.py` (S0), quiet/CPU-capped/change-aware gate (S1). **Every later slice cites this document; no number may be quoted as measured without a row here or a newer dated baseline.**

## 1. Measurement contract, as implemented

- **Recorder**: `scripts/verify_record.py` wraps any verification command and appends one JSON line per run (`msl.verification-record/1`) to `reports/perf/records.jsonl` (gitignored, local; raw logs never enter the record). Fields per plan §2: task class, phase, base SHA, candidate input fingerprint (SHA-256 over `HEAD` + `git diff --binary` + untracked file bytes), selected checks with reasons, runner (platform/machine/CPU count/Python), explicit worker count (parsed from `-n`/`-p`, else `os.cpu_count()`), cold/warm marker, durations (`call_s` measured; `queue/setup/collection/teardown` reserved `null` where the wrapper cannot see them), outcome, retries, publication and promotion status, phase start/end.
- **Sanitizer**: absolute home/repo paths → `<HOME>`/`<ROOT>`; credential-shaped tokens (`ghp_*`, `github_pat_*`, `Bearer …`, `sk-*`, `AKIA*`, `token|secret|password|api_key` values) redacted; verified on a planted `ghp_…` token.
- **Environment pinning (S0.2)**: `uv sync --frozen` once per machine; every wrapped command runs with `UV_NO_SYNC=1` and `MOEX_OFFLINE_ONLY=1`. Worker count is in every record.
- **Failure honesty**: failures are recorded as `failed`, never cached or re-reported as passes. Outcome mapping: exit `0` → `passed`; `124/137/143` → `timeout`; `2/127` → `unavailable`; otherwise `failed`. When the wrapper drives `check_health.sh`, the gate's per-check status JSON (`MSL_HEALTH_STATUS_FILE`) takes precedence over the exit code — a check that could not run is `unavailable`, never `passed`.
- **Guardrails unchanged**: proof/accounting numerical equivalence, replay coverage, browser/macOS/C99 gates — all untouched; `check_health.sh` runs exactly the same seven checks as before in full mode.

## 4. Honest gaps vs the plan's acceptance table

- **S1 acceptance "`--changed` <2 s on a 2-vCPU runner": not met on this throttled Intel Xeon @ 2.6 GHz** (2.65–2.88 s, n=2). The floor is `basedpyright` process startup on touched files (~1.8–2.1 s alone); `architecture --fast` adds ≤1 s and is correctly skipped when imports are unchanged. On a faster pinned 2-vCPU runner the target is plausibly met; this runner is recorded as the reference, so any claim otherwise would be false. No check was weakened to approach the target.
- **≤3 lines on success: met** (`passed in Ns (…)`, `skipped (full gate): …`, `full verification: …`).
- **macOS workstation timings are not in this baseline** — samples above are the Linux CI sandbox. The recorder runs identically on the workstation; its first recorded runs there belong in the next dated baseline.
- **Changed-gate sample n is small**; treat 2.7 s as an order-of-magnitude pin, not a p90.

## 5. What is explicitly not claimed

- No end-to-end task-time improvement is claimed (that is S3's shadow-run metric).
- No number here is a before/after benchmark across machines; the three sessions in plan §8 ran on different revisions and CPU quotas.
- The two failed suite samples are published as failures; they were fixed in-tree and re-measured (both suite samples shown passed).

## 6. Reproduce

```bash
uv sync --frozen   # once per machine
export UV_NO_SYNC=1 MOEX_OFFLINE_ONLY=1
uv run --no-sync python scripts/verify_record.py \
  --task-class full-gate --phase S0 --cold-warm warm \
  --check "check_health:all-seven" -- ./scripts/check_health.sh
./scripts/check_health.sh --changed [--base origin/main]   # inner-loop gate
uv run --no-sync pytest packages/<name>/tests -q            # focused package run
```

Records land in `reports/perf/records.jsonl` (gitignored). Inspect with:
`python -c 'import json,pathlib; [print(json.loads(l)["task_class"], json.loads(l)["outcome"], json.loads(l)["durations"]["call_s"]) for l in pathlib.Path("reports/perf/records.jsonl").read_text().splitlines()]'`

## 7. S4a — suite cost reduction (same day, same 2-vCPU sandbox)

Measured after the S4a changes on the tree that adds the tier split, the discovery
memo, the in-process CLI-help test and the cgroup-aware worker policy. Commands as
in §6, whole offline suite with `MOEX_OFFLINE_ONLY=1`.

| Run | Command | Samples | Result |
| --- | --- | --- | --- |
| Default profile (canary only) | `pytest -q -n 2 --dist loadfile` | n=2 | **38.84–39.79 s**, 658 passed, 232 subtests |
| Whole suite, every tier | `pytest -q -n 2 --dist loadfile -m ""` | n=3 | **40.76–41.97 s**, 664 passed, 232 subtests |
| Whole suite, outbound network blocked | same, non-loopback `connect` raises | n=1 | **43.73 s**, 664 passed — clean process, loopback server still allowed |
| Worker A/B, whole suite | `-n 0` / `-n 2` / `-n 3` / `-n 4` | n=2 each | **73.5 s / 42.5 s / 37.5 s / 37.0 s** |
| Tier-1 full gate via launcher | `python scripts/verify.py --profile full` | n=2 | 53.1 s / 59.5 s (gate 14.6–15.2 s + suite 38.5–44.2 s) |
| Equivalence tiers only | five `test_perf_equivalence*.py`, `-m ""` | n=2 | 13.2–14.6 s (was 28.84 s as one file) |
| CLI `--help` parity | `packages/core/tests/test_cli_plugins.py` | n=2 | 1.21 s (was 17.08 s) |
| `packages/core` tests | `pytest packages/core/tests` | n=1 | 4.67 s; slowest drop-in case 1.50 s |

**Acceptance.** The reference §2 row is 63.27–64.53 s (n=2) for the whole suite, and
87.48 s for the baseline tree in this sandbox before any S4a edit. Against that
baseline the whole-suite p90 falls from 87.48 s to 41.97 s (**−52 %**, target was
≥25 %): 39.79 s of it is the default profile. Identical test-ID coverage was verified
by collecting both trees: the five relocated equivalence cases map 1:1 onto
`_pair`/`_pool`/`_stream`/`_full`, and no test ID disappeared. `packages/core` no
longer carries a 40 s-plus drop-in tail (1.50 s slowest); it never did on this runner
— the 40 s figure is the export runner, so the criterion is met with margin rather
than by a local regression being removed.

**Worker policy.** The suite is I/O- and subprocess-bound: `-n 3` still beats `-n 2`
on a 2-vCPU box (37.5 s vs 42.5 s), and `-n 4` adds nothing (37.0 s, within noise).
The default stays at the usable CPU budget (`cpu_budget()`: host count capped by
affinity and the cgroup v1/v2 quota) and `MSL_VERIFY_WORKERS` overrides it; no
duration file and no duration-based deselection exist. Recorded here rather than in
code so the measurement cannot go stale silently.

**What the split deliberately did not do.** No trial count, history length or
cohort size was trimmed: the canary keeps the four cheap full-resolution cases and
every expensive case moved verbatim into a `slow_equiv` tier that the pre-push
profile, the CI `perf-equivalence` job, the weekly job and the sanitizer gate all
name explicitly. `packages/proof/tests/test_equivalence_tiers.py` fails if a case
leaves its tier, is duplicated, or if a whole-suite caller stops naming a tier file.
