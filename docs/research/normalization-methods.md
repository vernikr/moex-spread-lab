# Score карточки нормализации на /proof — методика и ограничения

Дата: 2026-11-16. Код: `src/moex_spread_lab/proof_ui.html`
(`seriesQuality`, `updateNormScores`, `applyNormHint`). UI: раскрывающийся список
«Normalization» на панели spread; в названии каждого варианта показывается оценка
для **текущей выбранной пары/стратегии** (`Label · 8.6`), а под подсказкой —
разбивка по субметрикам. Оценка пересчитывается после каждого запуска proof.

## Зачем и по каким гипотезам

Постановка (пользователь, 2026-11-16): нужна интегральная оценка метода
нормализации по *результирующему графику*. Рабочие гипотезы (не догма):

1. чем **горизонтальнее** итоговый график — тем лучше;
2. чем **равномернее распределена волатильность** во времени (график колеблется
   примерно одинаково всё время, волатильность не затухает/не нарастает) — тем лучше.

Плюс третья ось — **средневозвращение** (мотивировано тем, что proof заточен под
mean reversion; см. OU / half-life в `СКРИНЕР_epub.md` §4.4): чем сильнее график
«отскакивает» к равновесию, тем пригоднее он для стратегии, для которой строится.

Итоговая оценка 0–10: **0.4·горизонталь + 0.3·reversion + 0.3·равномерность волы**.
Если равномерность невычислима (слишком короткая серия) — 0.6/0.4 горизонталь/reversion.
При n<20 конечных точек оценка не показывается (`—`).

## Субметрики (точная семантика реализации)

Вход — трансформированная серия `spreadDisplayValues(S, mode)` (та же, что идёт в
график; null-пропуски пропускаются с индексами времени как есть).

- **Горизонталь** = `100·(1 − R²)`, где `R²` — квадрат корреляции OLS-регрессии
  ряда на время. R²=0 → 100 (идеально горизонтально), R²→1 → 0.
  Слепое пятно: длинная детерминированная осцилляция (синус) даёт R²≈0 без тренда;
  плюс любой детрендированный трендовый ряд получает механическое преимущество.
- **Reversion** = `100·clamp(1 − φ, 0, 1)`, φ — коэффициент AR(1):
  `φ = Σ(xₜ−m)(xₜ₋₁−m) / Σ(xₜ₋₁−m)²`, m — среднее ряда. φ≤0 → 100 (чередование,
  сильное возвращение), φ=0.5 → 50, φ→1 (случайное блуждание) → 0, φ>1 → 0.
- **Равномерность волы** = `100·clamp(1 − CV, 0, 1)`, CV — коэффициент вариации
  волатильности первых разностей по до 6 равным блокам (последний блок добирает
  остаток; CV = σ(blockVols)/mean(blockVols)). CV=0 → 100 (идеально ровная вола),
  затухание/разгорание волы → CV↑.
- Итог = `(0.4·L + 0.3·MR + 0.3·U) / 10` → одна цифра после запятой в опции списка.

Пример на синтетике (155 точек, тренд + шум): `raw` 2.8 (R² высокий, φ≈0.99),
`rm20` 9.3, `ols60` 9.9, `garch` 9.7 — детрендирующие методы доминируют, что
честно укладывается в ось «горизонтальность». На серии с затухающей волой
`rz20` (9.5) и `stoch20` (9.3) обгоняют `raw` (8.0) именно за счёт оси равномерности.

## Известные ограничения (читать перед выводами)

- Оценка — **свойство отображаемой кривой**, не доходность, не просаадка, не
  сигнал на сделку. Издержки, заливы, ledger, reconciliation она не видит и на
  них не влияет (всё display-only, как и сама нормализация).
- **ols60/ols20 получают механическое преимущество** на трендовых рядах: OLS внутри
  скользящего окна ортогонален времени по построению. Высокая оценка ≠ лучший
  момент для входа; судить по маркерам сделок и ledger, не по цифре в списке.
- **GARCH тут почти всегда выигрывает** по построению: σ̂ делит кластеры волы,
  ряд нормированных остатков ≈ плоский с равномерной волой. Дополнительно учесть,
  что используемая рекурсия упрощена (см. ниже) — оценка завышена.
- R² слеп к тренду-осцилляции; φ AR(1) на нормальных остатках не обязан быть <1;
  CV по 2–6 блокам шумный на коротких выборках (n≈27: всего 2 блока).
- Оценки считаются **для текущей пары/окна/стратегии** и меняются при переключении —
  сравнивать методы нужно на одной и той же выборке, цифры между парами несопоставимы.
- Нормализация (и оценки) могут маскировать смену режима: «красивая» плоская кривая
  ≠ живая коинтеграция. Для диагностики режима — rolling cointegration, half-life,
  ERT из `СКРИНЕР_epub.md` (§3.2.3–3.6), в proof не реализованы.

## Честно о качестве реализаций (зафиксировано 2026-11-16)

- **GARCH** — упрощённая рекурсия с фиксированными α=0.10, β=0.85, ω→0 (1e-10),
  без MLE-подгонки параметров и без ковариат. Отвечает на «необычно ли это при
  кластеризации волы», не «необычно ли vs среднее». Качество оценок именно этого
  варианта систематически завышено (см. выше).
- **Kalman** — local-level модель (уровень — random walk), фиксированные Q и R
  (1e-4 / 1e-2). Нет окна и нет подгонки; только настолько хорош, насколько верны
  фиксированные Q/R. На устойчивом тренде уровень «догоняет» ряд, инновации малы.
- **OU60** — AR(1) `x[t] = a + φ·x[t−1]` на trailing 60 obs; residual vs
  равновесный уровень `a/(1−φ)`. Если окно не показывает возврата (`|φ| ≥ 1`) или
  φ < 0 — откат на plain residual vs window mean. φ и half-life шумные при n=60;
  half-life по trailing-окну — грубая оценка, не калибровка.
- **stoch20** — «положение внутри диапазона» (min/max trailing 20 obs), не оценка
  σ и не mean-reversion: ровно горизонтальная кривая возможна без всякой
  стационарности. Использовать как визуальный индикатор, не как z-аналог.
- **ema10 / ewma10** — рекурсивная EWM-аппроксимация (halflife ≈ 10 obs),
  старт с первой точки; жёсткий «устаревания хвоста» нет, но ранняя история
  получает полный вес для первой точки.
- **mad20** — робастный σ̂ = 1.4826·MAD вокруг медианы окна: переживает
  одиночные плохие тики и гэпы, но притуплён к реальным раздуваниям волы.
- **rz20** — σ масштабирует ходы: большой чистый дрейф может выглядеть «маленьким»,
  если вола растёт вместе с ним.
- **expanding** — длинная причинная память, но практически не защищает от
  структурного дрейфа (весь период усреднён).
- **ols60 (и ols20)** — лучший стабилизатор уровня на дрейфующих рядах, но
  «съедает» реальный структурный сдвиг как «тренд»; оценка из-за этого завышена.

## Как менять/отключать

Веса и границы — inline в `seriesQuality()` (`proof_ui.html`): веса
`0.4/0.3/0.3`, число блоков `K=min(6, floor(n/10))`, минимум данных `n>=20`,
порог R²/φ/CV — там же. Список опций и базовые подписи — `NORM_HINTS`/разметка
`#norm`. Полное отключение: убрать вызов `updateNormScores()` из `render()`.
Скоринг не трогает CSV, маркеры сделок, ledger и reconciliation — ломаться там
нечему.

## Что НЕ покрыто (кандидаты на следующие шаги)

- ADF/KPSS/Hurst-тесты стационарности (§3.2.3 того же документа) — в JS не
  реализованы; в proof показываем индикаторы, а не тесты.
- Оценка half-life как распределения, а не точечная (§3.2.4).
- Theil–Sen / Huber detrend, winsorize (§3.3) — робастная альтернатива OLS.
- Log-spread / ratio / carry-adjusted координаты и ERT (§3.4).
- Vol-adaptive пороги входа (§4.3) и HMM-режимы (§4.5) — это сигнальная часть,
  не display.
