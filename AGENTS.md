# Working rules

- Chat: Russian, outcome first, brief business language. Authored project files: English by default. User-requested exception: R01–R06/R12 research prompts and the user-facing sections of the research README are Russian; reports may follow their prompt language. Preserve user-supplied source documents in their original language; explicitly label redactions.
- `docs/inputs/brief.md` defines scope and stage gates. Each stage occupies at least one separate user/assistant turn and produces a committed artifact. Never combine later stages into the current one.
- Current stage: Stage 9 development. See `README.md` for status, `docs/decisions.md` for confirmed boundaries, and `docs/stages/08-planning.md` for S4 and later work.
- Canonical workspace layout: `core` (contracts/settings/hashing/timeframes/universe/C99 fastcore), `data` (ISS/lake/retention/benchmark), `accounting` (costs/risk/sizing/ledger), `strategies` (plugins + pair/calendar datasets), `proof` (orchestration/replay/search/audit), `web` (loopback server/UI), `remote` (workstation bridge/benchmark tooling); imports flow `core -> data|accounting -> strategies -> proof -> web` with `data`/`accounting` siblings; `remote` depends on `core` and the root CLI composes providers. Workspace code/tests use canonical `moex_spread_lab.<domain>` imports; only `src/moex_spread_lab/cli.py` and `__init__.py` are public entry points.
- Reduction policy: delete unused internal code, routes, shims and dead subsystems instead of preserving them when it does not harm functionality or performance — no separate owner approval needed; keep behavioural contracts covered by tests (incl. negative) and record the rationale in `docs/decisions.md`.
- Default agent scope is one `packages/<name>/` subtree, including its tests/docs/fixtures/manifest. Cross-package contract changes start with an additive contract and conformance test, then fan out to consumers. Keep root governance files (`pyproject.toml`, `uv.lock`, workflows, `README.md`, `AGENTS.md`) minimal and coordinate cross-cutting edits.
- Adding a strategy is one new folder `packages/strategies/src/moex_spread_lab/strategies/<subpkg>/{__init__,engine,plugin}.py`; never edit `packages/strategies/pyproject.toml`, `test_architecture_dag.py` or a registry module (the folder is discovered, layer-classified and isolation-checked from disk), and never import a sibling strategy subfolder. Reach the registry via `proof.strategy_catalog` accessors (`get_strategy_registry` / `get_proof_adapter_ids` / `get_strategy_axes`, `registry=` injection in tests) — no import-time globals, no patching module attributes.
- Package tests are collected only from `packages/{core,data,accounting,strategies,proof,web,remote}/tests`; root `tests/` holds shared synthetic fixtures. Run a focused suite with `uv run pytest packages/<name>/tests -q`, the dependency-light global check with `uv run python scripts/architecture_gate.py`, and the full suite with `uv run pytest -q -n auto --dist loadfile`. CI schedules dynamic xdist `loadfile` work per package; do not add a central test-duration JSON.
- **Verification cadence (plan S3, two-tier).** Continue across internal sub-slices within one turn until the work package is complete, a genuine product/accounting/design decision is needed, or the turn nears its call budget (~75%); stopping after a few tool calls to ask for "продолжи" is a defect. Inner-slice verification (between atomic commits): `./scripts/verify.py --profile affected` (or `--profile quick`). End of a deliverable (before push): `./scripts/verify.py --profile full` on the integrated tree; an `affected`/`quick` result is advisory only. Browser smokes and C99 sanitizer runs are mandatory only when their contracts are touched.
- Code-health gate: before committing code, run `./scripts/check_health.sh --changed` (inner loop) or `./scripts/check_health.sh` (full gate before push); never raise ceilings in `config/code-health-baseline.json` or `.basedpyright/baseline.json`, never add `# noqa` / `# type: ignore` / broad `except Exception` without an inline justification, and always run `packages/proof/tests/test_perf_equivalence.py` (plus `scripts/run_sanitized_pytest.py` under ASan) when touching `_fastcore.c` or its pure-Python mirrors.
- File-size budgets are tiered (TD-1, #151): production `400`/`4,000` → `600`/`6,000` hard; declarative registries/static catalogs `550`/`5,500` → `800`/`8,000`; parameterized test suites `600`/`6,500` → `900`/`9,500`; the C99 kernel `900` → `1,350` LOC. Tokens are `utf8_bytes * 10 // 42`; only the hard ceiling fails. Never shard a cohesive module to satisfy a budget (`*p72*`, issue-numbered and path-encoded filenames rejected; `<40`-LOC production modules with ≤1 intra-package caller warn). Function-level cognitive complexity (`> 15`) and the acyclic import DAG stay strictly hard; `scripts/code_inspect.py check|outline` prints `loc`/`tokens`, archetype, soft target, hard ceiling and band.
- Always set `MOEX_OFFLINE_ONLY=1` in standalone/browser harnesses so `CalendarData` never probes MOEX ISS over HTTP; never wait with `nohup <cmd> & sleep <N>` loops (use synchronous `timeout <sec> <cmd>` or native background tools); prefer structured Read/Edit/Grep tools over `Bash` `sed`/`cat <<EOF` dumps.
- Read `docs/decisions.md`, `docs/risk/pilot-policy.md` and the current stage artifact before continuing. The user clarified 10–15k means LQDT shortfall and delegated risk-default selection; numeric defaults are versioned judgment, not verified safety or authorization to fund/trade. Track unresolved groups in `docs/blockers/bNN-slug.md`; use bNN.N subitems and archive resolved groups.
- Keep durable documentation compact and nonduplicative. Put temporary work plans, checklists, execution reports and dated verification evidence in GitHub Issues/comments only; do not retain tracked Markdown/JSON copies after migration. Keep durable contracts, decisions, blockers, formal stage artifacts, runbooks and research evidence in the repository; clearly separate facts, evidence, hypotheses, proposals and approved decisions.
- Keep the repository private. Make atomic local commits per inner slice (Conventional Commits); push once after the full gate passes on the integrated tree and verify remote success (never claim a failed push). Apply SemVer when software releases begin.
- Preserve the proof search and accounting contracts in `packages/proof/docs/execution-proof.md`; never infer shared capital or expanded trading authority from the offline UI.
- Workstation handoff (end of coherent deliverable only): after the full gate passes and the push to `origin/main` succeeds, fast-forward the checkout at `~/Downloads/projects/moex-spread-lab`. With bridge credentials, run `moex-spread-lab remote sync` then `remote status`; sync skips `uv sync` unless dependency inputs change or `.venv` is missing, restarts only runtime paths, and confirms loopback health with a matching head (docs/tests/workflows/`AGENTS.md` fast-forward without restart). With a runtime bridge, prefer loopback HTTP APIs/CLI over browser automation except UI smoke tests; never mutate `data/analytics/research-settings.json` during benchmarks.

- Broker terms, KPUR effects, collateral eligibility, margin offsets, market sessions and API/data access are unverified until evidenced; missing safety-critical data must never become zero cost or unlimited capacity.
- All performance comparisons must address LQDT; do not assume a return guarantee, risk-free arbitrage, fixed carrying yield or that an internal allocation ring-fences the account.
- Research localization must preserve complete context, evidence requirements, dependencies and risk authority; every prompt states search languages, maximum-breadth priority and conditional public-page retrieval priority, with no claim of tested bot protection.
- Keep benchmark-relative peaks, losses and lifetime gross top-up usage continuous across funding/reviews; no hidden resets, automatic rescue capital or unapproved access to core collateral.

## GitHub Project & Issue workflow

- Before starting work, set Project Status to `In Progress`. Full specification: [`docs/development/github-project.md`](docs/development/github-project.md); board: [`https://github.com/orgs/vernikr/projects/2`](https://github.com/orgs/vernikr/projects/2).
- **Source of truth:** GitHub Issues/comments own plans, work-package checklists, execution reports and dated verification/benchmark evidence; repository docs hold durable contracts, approved decisions (`docs/decisions.md`), cross-issue blockers (`docs/blockers/bNN-*.md`), formal stage artifacts, reusable runbooks and research evidence. Never create `TODO.md` or a parallel master backlog; write all Issues and comments in English. GitHub Project #2 owns live status (`Inbox`/`Ready`/`In Progress`/`Blocked`/`Deferred`/`Done`), `Work Kind` (`feat`/`fix`/`docs`/`refactor`/`chore`/`perf`/`test`/`research`/`plan`/`revert`), `Module` (`core`/`data`/`accounting`/`strategies`/`proof`/`web`/`Cross-module`), `Effort`, `Business Value` (`0–5`) and `Verification Gate`. Before changing tracked files, ensure an open Issue covers the work (or create one, add it to Project #2, apply `area:*` labels, set Project fields); move `Status` to `In Progress` when claiming an unblocked `Ready` item and reference `#N` in commits. Close as `completed` only after all acceptance criteria and the Issue's `Verification Gate` pass on `origin/main`, then unblock `blocking` dependents.
- **Hierarchy:** Parent workstream Issue (canonical plan in its body/comments) → Work Package native sub-issue (one coherent pushable deliverable verified with `--profile full`) → `## Slices` checklist inside the Work Package body (atomic inner commits). **Deviations:** minor implementation deviation → proceed, add `plan-deviation` label, post `**Deviation from plan:** <change> / **Why:** <constraint> / **Invariant check:** ...`; material scope/contract/invariant conflict → stop, add `blocked`+`decision`, set `Status = Blocked`, post `**Blocked by:** owner decision`; partial completion → narrow the Issue to the green delivered prefix (`plan-deviation`), push and close it, split the remainder into a sibling sub-issue; defer vs retire → `deferred` + `Status = Deferred` with `**Deferred:** <reason> / **Revisit when:** <trigger>`, or `not_planned` when permanently invalidated.

## Multi-step task autonomy template (plan S3)

1. **Decompose before coding.** List the planned atomic sub-slices, their scope (packages/files), and the verification profile each will use; identify decisions that need user input versus those resolvable from existing code/docs.
2. **Execute sub-slices continuously.** For each: read → change → `./scripts/verify.py --profile affected` (or `--profile quick`) → atomic local commit; continue without asking for "продолжи". Stop only when the deliverable is complete and the full gate passes, a genuine decision is needed, tool failures block progress, or you approach ~75% of the tool-call budget.
3. **Full integrated gate before push.** After the last sub-slice, run `./scripts/verify.py --profile full` on the integrated tree; fix until green, then push once to `origin/main` and (if required) sync the workstation.
4. **Fail-to-full switch.** If the change-scope router errors or non-`.py` inputs/fixtures/new files changed, run the full gate rather than relying on testmon deselection; never report an affected/advisory run as full verification.
5. **Router regression table.** When modifying `scripts/change_scope.py` or the testmon integration, extend `ROUTING_TABLE` in `packages/core/tests/test_change_scope.py`; a router change that drops a leg some row expects is a missed failure.
6. **Turn-end report.** State what was committed locally, what was pushed (if anything), which sub-slices remain, and the exact decision or next step needed.

For native GitHub sub-issues, ensure `.github/workflows/issue-parent-sync.yml` exists with `issues: [opened, edited]`, `permissions: issues: write`, and a job calling `vernikr/mother/.github/workflows/issue-parent-sync.yml@v1` (create the caller workflow if missing); then put `<!-- issue-parent: #N -->` on its own line in the child Issue body, or use `<!-- issue-parent: none -->` to detach (or use GraphQL `addSubIssue` directly when `gh` has `repo` scope).
