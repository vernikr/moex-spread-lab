# Unified execution proof (`/`, `/proof`)

Status: **slices 1–3 delivered** (payload + adapters + tests 2026-11-16; LWC UI rewrite 2026-11-16; screener deep links + docs 2026-11-16). Design: `execution-proof-screen-design.md` (workspace artifact, not committed).

## Homepage, automatic parameters and stability lamps (2026-11-18)

`/` and `/proof` serve the same screen and accept the same deep links. The old S2 homepage and its back-link have been removed. Its compatibility API (`/api/optimize`) still implements the original hand-coded neighborhood grid; it is **not** used by the proof UI.

### Scope and compatibility

Click a name to inspect its chart; check its box to include it in **Подобрать параметры**. Checks survive switching assets. Asset/family boxes cascade and show a mixed state for a partial subtree. Upper **Все** controls the entire catalog; lower **Все** controls just the open asset. No checks means exactly the open window. An unchecked focus is never silently added. The first check initializes a shared parameter editor from the current controls. Its vector and strategy stay pinned when browsing another row or universe. Compatible checked charts can preview the common settings; an unchecked focus keeps its own settings and never enters the mean. Clearing all checks restores the ordinary per-leaf editor.

One active strategy and one common vector, never a separate optimum per instrument. Pair `mean_reversion.lookback` maps to calendar `zscore_mean_reversion.window`; thresholds share their intersecting stepped domains. Pair MR requires next-open fills. Carry and RUONIA do not cross universes; RUONIA is restricted to its configured assets. Quantity, slippage, fill, calendar conventions and chart transforms are not tuned.

`POST /api/proof/optimize` accepts the normal focused request plus optional `targets` (unique `{universe, pair}` / `{universe, asset, pair}`). An omitted or empty array uses the focus. **Before** removing any explicit check, `selection_requires_confirmation` returns all exclusions, reasons and remaining count, with zero trials. Cancel/Escape leaves the selection unchanged. Acceptance resubmits only the confirmed remainder. If none remain, stop; only a subsequent click will use the empty-selection fallback. A trial-level failure does **not** authorize removing that window.

**Research screens (settings dialog).** `allow_failed_volume` and `allow_failed_capital` default to `true`, independently. Checked = allow the respective failed check; unchecked = enforce it. A window failing both needs both permissions. The switches govern proof search (checked or focused), its live stability probes and the matching proof/evaluation. They do not check additional windows, change the raw V/C verdicts, alter ordinary S2/CLI gates, or enable trading. Whole-window failures are shown with the result. A relaxed capital stress test is not extra funding: a position that cannot pay actual margin cannot contribute a trading return.

### Selection, accounting and evidence

- [BR-10](../stages/04-requirements.md): **Настройки → Доля истории для проверки** is one persistent 0–50% preference, default 0 (`GET/POST /api/settings`; ignored `data/analytics/research-settings.json`). Old split-only settings files retain their exact share and use both default permissions, without being rewritten on read. Partial saves preserve omitted fields; booleans are not coerced from numbers or strings. Pre-preference search logs used both strict screens, irrespective of today’s defaults. Snapshot all preferences once per request; split **each window's own eligible sessions**, not their intersection. At 0%, report on full training. Otherwise reserve the last `max(1, floor(n × percent / 100))` sessions. Journal-only rows do not consume the share. No confirmation interval and no training substitution for unavailable validation.
- For each window start with an independent RUB 30,000 account. Reinvest free cash in LQDT; posted entry margin earns nothing until released. Incorporate the proof ledger's net daily P&L (costs and applicable funding). The matched benchmark is fully invested in LQDT. For `d` actual elapsed calendar days, score `100 × [(V_end/V_start)^(365/d) − (LQDT_end/LQDT_start)^(365/d)]` in percentage points per year. Counts weight neither by session count nor invested margin. Positive sub-year spans, even a single validation session measured from the previous mark, are annualized **projections**, not realized yearly returns. Nonpositive spans, balances, invalid prices or unfundable margin cannot supply a valid score.
- The objective is the **arithmetic mean** of these annualized excesses on the fixed cohort. A legitimately idle LQDT-only book contributes zero with its full weight. Missing/unmeasurable/risk-blocked training is not zero: prune the entire proposal. Require defensible funding coverage under the policy below and all other required inputs, any non-waived training liquidity or stress gate, warm-up with room for a signal, and the existing 10k excess-drawdown / 15k shortfall limits. Each training replay ends at its own cutoff, including carry's fee reference and the usual terminal marking convention.
- Optuna **TPESampler** (seed 41, 8 startup trials, 40 proposals). Integer windows, 0.1 threshold steps, `exit_z < entry_z`. Include the current vector when on the common feasible grid. Apply the maximum admissible **tested proposal**, including nonpositive maxima; prefer the current vector on an exact tie, otherwise the first tied proposal. No admissible score → leave settings unchanged. This is not a claim of an exhaustive global optimum.
- **Only after selection**, measure the chosen rule on each continuous full ledger. Validation begins economically at the last training mark; do not reset cash, positions, costs, funding or warm-up. The expandable group result shows members, their rates, the equal-weight training mean and the separately labelled result-period mean. A missing validation rate leaves the mean unavailable, never divided by fewer members. The focused period strip also retains net RUB and the booked LQDT hurdle on entry margin; those RUB measures are not the search objective.
- **Lamps are diagnostics, not vetoes.** Probe ±1/±2 feasible input steps, everything else fixed, training only. `100 × clamp(worst neighbor / center, 0, 1)`: green ≥70, amber ≥40. A nonpositive measured center scores zero; absent exposure, insufficient history (<24 training sessions) or unavailable evidence can leave a lamp unscored. Size/slippage are sensitivity-only. With checks, both the form lamps and the search summary profile the common vector: first average all members’ annualized excesses at the center and each neighboring point, then score the worst neighboring **mean** against the center **mean**. Do not average individual lamp scores or colors. With no checks, the form profiles the open window. An incomplete cohort shows no group estimate and keeps every check. Neighbor probes are not Optuna proposals or a second ranking step.
- `POST /api/proof/plateau` probes the explicit strategy/vector on `targets` without starting Optuna, applying parameters, writing a trial log or using a focus instrument. Refresh on changes to checks, parameters, execution assumptions, either screening preference or the BR-10 split. Navigation replays only the inspected chart; it cannot clear, replace or restart group lamps. Request keys, cancellation and separate response guards prevent stale results. A completed search can supply the same profile directly.
- `proof-search.v3` records every proposal, rank score, member scores in canonical member order (or reason for pruning), selection, dated evaluation metadata (including both screen preferences and full-window failed checks) and member run IDs in ignored `data/analytics/proof-searches.jsonl`. Single-window searches retain the focused result ID. The UI requests a fresh `/api/proof/run` after an actual search, with accepted or unchanged settings. The proof/evaluation IDs distinguish full replay from period evaluation. The full chart, journal and CSV mark the validation boundary without changing the ledger.
- Calendar data and member input snapshots are reused per request. Only the local optimize and checked-plateau endpoints permit a larger body (192 KiB, ≤1024 targets). Serialize group profiles separately from searches, with cancellation checks. No shared capital, broker connection or prospective performance claim. Historical W7 and the separate S2 compatibility grid are not changed.

Optional Chromium regressions (synthetic data): install Chromium with `uv run --with playwright python -m playwright install chromium`, then run `uv run --with playwright python tests/browser/checkbox_tuning_smoke.py`, `uv run --with playwright python tests/browser/period_settings_smoke.py`, `uv run --with playwright python tests/browser/group_lamps_smoke.py` and `uv run --with playwright python tests/browser/screen_settings_smoke.py`.

## Signed funding in mean reversion (2026-11-17)

- For `perpetual_quarterly_same_asset`, `mean_reversion` joins local MOEX ISS FORTS EOD history on trade date and requires a published, verified or explicitly estimated rate for each analysis clearing. The cash effect per clearing is `−position × SWAPRATE × near_lot × quantity` (`position=+1` long near, `−1` short near); it feeds per-day ledger P&L, cumulative equity/LQDT comparison, trade gross/net and summary reconciliation. On next-open proxies, funding is counted only when the modeled position remains open through that day's proxy clearing; an exit at that day's open does not receive/pay that day's funding.
- The pair screener requires a local near-perpetual funding-history cache for mean-reversion availability. An unresolved funding gap prevents the proof; missing values are never silently treated as zero. Non-perpetual dated calendars do not receive funding.
- MOEX's EOD `SWAPRATE` is used as the exchange-published clearing result; it already reflects its operative funding calculation/caps. The application does not attempt to reconstruct minute-average deviation `D` or point-in-time `K1/K2` regimes from EOD candles. The lot currently comes from the contracts intake snapshot, not a point-in-time specification. These are exchange-data proxies, not broker statements or account reconciliation. Current MOEX description for `GLDRUBF` states `K1=0.05%`, `K2=0.15%` and its minute observation interval; see [MOEX perpetual gold one-pager](https://fs.moex.com/f/19628/onepager-vechnye-fjuchersy-na-zoloto.pdf) and [perpetual-futures hub](https://www.moex.com/ru/derivatives/perpetual-futures).
- The table labels each row `начислено` / `списано` / `нет платежа` and shows `−position × SWAPRATE × lot × contracts`; exported CSV carries the rate, lot, quantity and source. The funding chart's signed values and net total now apply to both pair strategies whenever coverage is complete.

### Exchange check and short gaps (2026-11-18)

- One offline resolver serves the pair catalogue, `mean_reversion`, `funding_only`, their training replays and the S2 pair screener. Existing recorded W7 studies and native calendars are not restated. A finite published rate, **including zero**, wins. A supplemental MOEX re-download can supply a missing number. A documented extra session without clearing has **no payment and no rate**: keep genuine candles in price replay, never add a weekend settlement to carry, and never move or duplicate the next regular rate. If such a candle has no same-day LQDT quote, use only its last observed close and identify its date; futures prices are never filled by this policy.
- For **1–3 consecutive missing clearing sessions** only, book the **same** signed `(previous + next) / 2` per underlying unit on every missing date. Resolve the run on the perpetual's complete local EOD/candle history **before** selecting a quarterly or its positive-volume dates; other observed FORTS settlements can confirm a clearing and reveal absent EOD rows. Do not bridge 4+ sessions, an unbounded edge, an unverified clearing, the 2022 FX regime change, the sample end, or the training/validation boundary. No midpoint can restore either leg's missing `SETTLEPRICE`. Input pages remain unchanged.
- Cash is attributed retrospectively to its session under the existing position/sign/lot rules. A carry decision uses a complete prior window: a midpoint is available **after** its right-hand clearing, never for the same settlement decision. While it is unknown there is no funding-triggered entry or exit; independent expiry/assignment exits still work. A prefix or training account that would need a later rate is unavailable, not computed with validation data.
- Ledger/CSV distinguish a published zero, a flat position, `rechecked`, `midpoint` (both source dates/rates) and `no_clearing` (notice). Policy/exception dates and recheck page hashes appear in provenance. The checked group and both V/C permissions are not altered if a rate cannot be resolved.
- See [historical intake](historical-pair-intake.md#funding-reconciliation-2026-11-18) for live-source evidence, coverage counts and the explicit read-only-by-default recheck command.

## Spread display & causal normalization (2026-11-16)

- Series now carry `spread_rel` / `spread_open_rel` / `spread_last_trade_rel`: the spread as a percentage of the far leg — pair screen: spread ÷ far contract value (RUB-normalized near−far over far contract value); calendar: spread ÷ far price (points over points). Pure same-row ratio; no look-ahead anywhere.
- Per-fill blocks carry `spread_fill_rel` (used for marker labels); the spread pane plots the relative spread. The chart has a normalization select (`#norm`, spread chart only): raw; residual vs expanding mean; residual vs trailing rolling mean (20/60 obs); rolling z-score (20 obs); residual vs trailing OLS detrend (60 obs). Every transform is strictly causal (trailing windows; the expanding variant is the point-in-time running mean) and is a visual scale only — it never feeds strategy signals, markers remain tied to trades.
- Table spread cell shows % of far with the absolute value in the secondary line; tooltip shows relative + absolute + the normalized value when a non-raw mode is selected; CSV gains `spread_rel` / `spread_open_rel` / `spread_last_trade_rel` (absolute columns kept). Fill cards show the absolute fill with the relative value in parentheses. P&L, ledger, tiles and totals stay in RUB.
- `run_id` values change versus slice-3 payloads for identical selections (series content is hashed and the payload gained additive fields); pre-change `run_id`s are not reproducible after this change. `execution-proof.v1` remains a strict superset — additive optional fields only.

## Proof UI layout and interaction (2026-11-16)

- The proof screen uses the full viewport width. The pair/parameter and normalization columns can be resized by dragging their separators; widths are keyboard-adjustable and saved in the browser.
- Pair options are grouped by family. Each group's unavailable pairs stay disabled and appear after its available pairs; family labels are not repeated in each pair name.
- Calendar windows fill the available vertical height in the selection column (the asset list keeps a compact fixed height and unused strategy-parameter rows collapse). Selecting a pair/window or changing a strategy/asset starts a new analysis automatically. Numeric parameter inputs run on Enter or blur; the explicit “Показать разбор” buttons are removed. The calendar screen preselects the first asset with windows and its latest listed window, so the window list is populated immediately.
- Parameter form values mix catalog data and HTML defaults. Pair strategy availability comes from the selected pair; only `lookback` is loaded from the selected strategy's `catalog.pair_screen.strategies[..].parameters.lookback` (fallback 20) on pair/strategy sync. Pair `entry_z` / `exit_z` are fixed HTML defaults of 2.0 / 0.5 (also present in catalog metadata but not read by the UI), quantity starts at 1 and slippage at 1 tick; the disabled fill label is derived from strategy (`next_open` for mean reversion, `same_day_settlement` otherwise) and is not sent as an editable input. Calendar strategies/fills come from the catalog; `lookback` is set to 7 for monthly assets, otherwise 20. Calendar z-score inputs start at entry 1.5 / exit 0.5, the RUONIA convergence threshold at 1.0 pp, quantity at 1 and slippage at 1 tick; calendar fill defaults to `next_open`. User-edited values persist in the inputs except for lookback values re-applied by the selection logic.
- Pair and calendar analyses show a deterministic looping progress bar at the top while results are fetched and rendered; the textual “Строю разбор…” label is not shown in the left column. Switching between “Скринер пар” and “Календарные спреды” automatically starts a fresh analysis for the current selection.
- Charts are fitted to their full data range after the new layout paints and again when the charts tab is revealed, so pair switches use the available chart area. Visible panes now flex to use the available height (with readable minimum sizes); if all expanded panes exceed it, the chart area scrolls. Hovering any chart synchronizes a full dashed crosshair (vertical date line plus horizontal series-value line and axis labels) across all visible panes while keeping the hover tooltip anchored only to the hovered pane. RUB-denominated near/far leg axes show whole rubles only; non-RUB calendar quotes retain their native precision. Hover tooltips append ₽ to RUB-denominated prices and to fees, funding, P&L and drawdown.
- The header has no offline badge and includes a button to hide/show the evidence bar, quality flags, and summary tiles as one block; that summary block starts hidden. The chart-hover hint is removed; an unnormalized spread chart (% of far leg, with synchronized trade markers and tooltip) sits directly above the normalized spread chart and starts collapsed alongside the near-leg, far-leg, and volume charts, each expandable independently (expanded pane state persists while switching normalizations or instruments). The spread title no longer repeats the selected normalization; GARCH(1,1) z is the default normalization.
- Mouse-wheel scrolling/zooming is disabled for charts. In the ledger, only event rows that expand an execution card receive a hover highlight; ordinary rows have no hover reaction. A successful analysis no longer leaves a trade/reconciliation summary in the left-column status area; loading, error, and catalog status messages remain.
- These are presentation/interaction changes only: API payload, evidence, price-proxy labels and execution semantics are unchanged.

## Reconciliation contract (asserted in tests)

- `Σ ledger.costs == Σ trade entry+exit costs` (±0.02 ₽ rounding).
- `Σ ledger.mark_pnl == Σ trade gross` (telescoping; prices for the pair book are RUB-normalized `near*mv − far*mv`, constant multipliers — no FX drift on this universe).
- `last(ledger.cumulative_net) == Σ trade net` (±0.02 ₽); `ledger_reconciliation_rub == 0.0`.
- `cost_totals` equals the sum of per-side component dictionaries; broker component always 0.0 (VTB zero fee to 2026-12-31).
- Same inputs → identical `run_id`.
