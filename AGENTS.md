- Chat: Russian, outcome first, brief business language. Authored project files: English by default. User-requested exception: R01–R06/R12 research prompts and the user-facing sections of the research README are Russian; reports may follow their prompt language. Preserve user-supplied source documents in their original language; explicitly label redactions.
- `docs/inputs/brief.md` defines scope and stage gates. Each stage occupies at least one separate user/assistant turn and produces a committed artifact. Never combine later stages into the current one.
- Current stage: Stage 9 development. See `README.md` for status, `docs/decisions.md` for confirmed boundaries, and `docs/stages/08-planning.md` for S4 and later work.
- Workspace map and ownership (Phase 6): `packages/core` owns contracts/settings/hashing; `packages/data` owns ISS/lake/retention/benchmark; `packages/accounting` owns costs/risk/sizing/ledger/artifacts; `packages/strategies` owns isolated strategy plugins and pair/calendar datasets; `packages/proof` owns replay/search/audit; `packages/web` owns the loopback server/routes/static UI. Import dependencies flow `core -> data|accounting -> strategies -> proof -> web`; `data` and `accounting` remain siblings. Root `src/moex_spread_lab/cli.py` and `__init__.py` are public entry points; other root modules are documented backward-compatibility shims whose module docstrings name the canonical replacement.
- Default agent scope is one `packages/<name>/` subtree, including its tests/docs/fixtures/manifest. Use canonical `moex_spread_lab.<domain>` imports in all workspace package code and tests; root compatibility shims are reserved for external consumers. Cross-package contract changes start with an additive contract and conformance test, then fan out to consumers. Keep root governance files (`pyproject.toml`, `uv.lock`, workflows, `README.md`, `AGENTS.md`) minimal and coordinate cross-cutting edits.
- Adding a strategy is one new folder `packages/strategies/src/moex_spread_lab/strategies/<subpkg>/{__init__,engine,plugin}.py`; never edit `packages/strategies/pyproject.toml`, `test_architecture_dag.py` or a registry module for it (the folder is discovered, layer-classified and isolation-checked from disk), and never import a sibling strategy subfolder. Reach the strategy registry through `proof_runtime.strategy_catalog` accessors (`get_strategy_registry` / `get_proof_adapter_ids` / `get_strategy_axes`, `registry=` injection in tests) — no import-time globals, no patching module attributes.
- Package tests are collected only from `packages/{core,data,accounting,strategies,proof,web}/tests`; root `tests/` contains shared synthetic fixtures only. Run a focused suite with `uv run pytest packages/<name>/tests -q`, the dependency-light global check with `uv run python scripts/architecture_gate.py`, and the full suite with `uv run pytest -q -n auto --dist loadfile`. CI schedules dynamic xdist `loadfile` work per package; do not add a central test-duration JSON.
- **Verification cadence (plan S3, two-tier).** Within a single assistant turn, continue across internal sub-slices until the work package is complete, a genuine product/accounting/design decision is needed from the user, or the turn nears its call budget (target ~75%). Stopping after a handful of tool calls to ask for "продолжи" is a defect, not compliance. Inner-slice verification (between atomic local commits): `./scripts/verify.py --profile affected` (or `--profile quick` for very small edits). End of a coherent deliverable (before push): `./scripts/verify.py --profile full` on the exact integrated tree. A passing `affected`/`quick` result is advisory only; it is never reported as full verification. Every push goes through the full gate on the integrated tree. Browser smokes (`scripts/run_browser_smokes.py`) and C99 sanitizer runs are mandatory only when their contracts are touched, per the guardrails below.
- Code-health gate: before committing code changes, run `./scripts/check_health.sh --changed` (inner loop) or `./scripts/check_health.sh` (full gate before push); never raise ceilings in `config/code-health-baseline.json` or `.basedpyright/baseline.json`, never add `# noqa` / `# type: ignore` / broad `except Exception` without an inline justification, and always run `packages/proof/tests/test_perf_equivalence.py` (plus `scripts/run_sanitized_pytest.py` when clang/ASan is available) when touching `_fastcore.c` or its pure-Python mirrors.

## Multi-step task autonomy template (plan S3)

When starting a multi-slice work package, internalize this operating rule:

1. **Decompose before coding.** List the planned atomic sub-slices, their expected scope (which packages/files), and the verification profile each one will use. Identify any decisions that genuinely require user input (product choice, numerical default, trade-off between two valid designs) versus decisions you can make from existing code/docs.
2. **Execute sub-slices continuously.** For each sub-slice: read relevant files → make changes → run `./scripts/verify.py --profile affected` (or `--profile quick` for trivial/docs edits) → atomic local commit. Continue to the next sub-slice without asking for "продолжи". Stop only when: (a) the deliverable is complete and the full gate passes; (b) a genuine decision point is reached that existing docs do not resolve; (c) tool failures block progress; (d) you approach ~75% of the available tool-call budget.
3. **Full integrated gate before push.** After the last sub-slice commit, run `./scripts/verify.py --profile full` on the integrated tree. If it fails, fix and re-run until green. Only then push once to `origin/main` and (if required by the change) sync the workstation.
4. **Fail-to-full switch.** If the change-scope router errors out, or if non-`.py` inputs/fixtures/new files changed, run the full gate rather than relying on testmon deselection. Never report an affected/advisory run as full verification.
5. **Shadow mode for router changes.** When modifying `scripts/change_scope*.py` or the testmon integration, validate with `./scripts/shadow_runner.py --injections` and a `--commit` range replay before promoting the change. The acceptance target is zero missed failures across >=30 candidates plus all four injection categories.
6. **Turn-end report.** When stopping (whether from completion, decision needed, or budget), state: what was committed locally, what was pushed (if anything), which sub-slices remain, and the exact decision or next step needed.
